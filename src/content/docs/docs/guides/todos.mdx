A todo in AIDE is a checkbox line in a note, so there's no separate todo database: `- [ ] Call the bank` in any note is a todo, and the Todos screen gathers every open one from all your notes. Checking it off anywhere changes that line in its note.

## Writing todos

A todo is a list item with a one-character status in brackets: `- [ ]`, `* [ ]` or `+ [ ]`, indented as deep as you like. Lines inside fenced code blocks aren't todos.

| Status | Means | Open |
| --- | --- | --- |
| `[ ]` | to do | yes |
| `[/]` | in progress | yes |
| `[<]` | scheduled for later | yes |
| `[x]` `[X]` | done | no |
| `[-]` | cancelled | no |
| `[>]` | migrated: moved to another day | no |
| any other character | as written, counted as to do | yes |

Only done (`[x]`) counts as completed work in [Review](/docs/guides/search-graph-review/).

### Dates, priority and other fields

AIDE reads the fields of the Obsidian Tasks plugin (emoji) and of Dataview (`[key:: value]`, or `(key:: value)`). Both are always read; when a field appears twice, the first wins.

| Field | Tasks emoji | Dataview |
| --- | --- | --- |
| due | `📅 2026-10-24` | `[due:: 2026-10-24]` |
| scheduled | `⏳ 2026-10-23` | `[scheduled:: 2026-10-23]` |
| start | `🛫 2026-10-20` | `[start:: 2026-10-20]` |
| created | `➕ 2026-10-18` | `[created:: 2026-10-18]` |
| done | `✅ 2026-10-22` | `[completion:: 2026-10-22]` |
| cancelled | `❌ 2026-10-22` | `[cancelled:: 2026-10-22]` |
| priority | `🔺` highest, `⏫` high, `🔼` medium, `🔽` low, `⏬` lowest | `[priority:: high]` |
| recurrence | `🔁 every week` | `[repeat:: every week]` |
| estimate | — | `[estimate:: 25m]`, `1h`, `1h30m` or plain minutes |
| by | — | `[by:: aide]`: who added it (`aide` for the assistant, radar and the Claude app through AIDE) |
| project | — | `[project:: AIDE app]`: what it's part of. Up to 60 letters, digits, spaces, `-`, `_`, `.` and `/`; no brackets, `:`, `#` or `@` |
| source | — | `[source:: https://…]`: where it came from, such as a Slack message, a mail thread or an issue. Only `http://` and `https://` links |
| agent | — | `[agent:: claude]`: which coding agent works on an [agent card](#agent-cards). `claude`, `codex` and `grok` read as themselves, any other name (up to 20 of `a`–`z`, `0`–`9` and `-`) as `agent` |
| card | — | `[card:: k7f2q]`: an agent card's id, 5 to 12 of `a`–`z` and `0`–`9` |
| updated | — | `[updated:: 2026-11-10T14:03Z]`: when the card was last written, in UTC to the minute |

The editor highlights these fields as you type. Off the line you're editing, a todo's time block is tinted, its estimate shows as a timer chip and `[by:: aide]` as an **AI** chip, so what the assistant added stands out; put the cursor on the line to see them as written. Completing a todo with a recurrence rule creates its next occurrence: see [Recurring todos](#recurring-todos).

#### Fields as chips

Off the line you're editing, every field shows as a chip, the way the Todos screen shows it:

- **Due** says Today, Tomorrow, Yesterday, a weekday or the date: red once it's past, orange today, blue later. **Scheduled** and **start** read the same way, in blue.
- **Priority** shows its flag and name (Highest, High, Medium, Low, Lowest) in the Todos screen's colours. **Repeat** shows its rule; **done**, **cancelled** and **created** show their date.
- **Project** shows its name. **Source** shows where the link goes (Slack, Gmail, GitHub, or the site's address); click it to open the link, whether or not you're editing.
- Only a field's first occurrence becomes a chip. A value AIDE can't read, such as `[due:: someday]`, shows as written in the warning colour.

While you're editing a note, click a chip to change it:

- **Dates**: Today, Tomorrow, Next week (next Monday), Pick a date…, or Remove.
- **Priority**: one of the six; Normal takes it away.
- **Estimate**: 15m to 2h, or Remove. **Repeat**: every day, weekday, week or month, or Remove.

The field is rewritten where it is, in the format it was written in, and one undo takes the change back. Remove takes out every copy of that field on the line.

- **Status menu**: right-click a checkbox, or press and hold it on the iPhone, to set Open, In progress, Done or Cancelled. Done works like a click: it adds the completion date and the next occurrence of a recurring todo.
- **Add a field**: on the todo line you're editing, the **+** at its end adds a due date, scheduled date, priority, estimate or repeat, in your todo format.

Also read from a todo's text:

- **Time block**, as the Day Planner plugin writes it: `09:00 - 10:30` or `9:00` at the start of the text. A block whose end is before its start ends the next day.
- **Tags**: `#tag`, which must contain something other than digits (`#2026` isn't a tag).
- **Contexts and people**: `@name`.

#### Calm todo lines <Badge text="Next release" />

Off the line you're editing, a todo reads the same way it will on every screen:

- Its chips come **after the title**, at the end of the line as on the Todos screen and the board, always in the same order: the time block, due, scheduled, start, estimate, the agent working on it, its progress, its project, where it came from, a meeting it came from and its repeat rule.
- What doesn't help you decide is hidden: the **created**, **done** and **cancelled** dates (the checkbox already says it's done), who added it (`[by:: …]`), and an agent card's id and last update. Put the cursor on the line to see everything as written.
- **Priority** colours the checkbox's ring instead of taking a chip: pink for highest, red for high, orange for medium, grey for low. You change it on the line, or add it with **+**.
- A todo with subtasks shows its **progress**, such as **2/4**: the subtasks done out of the subtasks directly under it, cancelled ones left out. An [agent card](#agent-cards) shows its agent (**Claude**, **Codex**, **Grok** or **Agent**) too. A card's project isn't shown in that project's own board note.
- A long todo shows **two lines at most**: its title ends in **…** where its chips still fit, so you always see them. Click **…**, put the cursor on the todo, select across it, or find a word in it, and it shows in full; while reading, click it. Links in it stay links.
- A todo's [memo](#memos) folds to its first line, smaller and muted, with **+3 lines** (or however many) after it. Put the cursor on the todo or in the memo, or click **+3 lines**, to see it all.
- None of this happens in code (fenced or indented), the frontmatter or HTML: a todo-shaped line there shows exactly as written.

```markdown
- [ ] 09:00 - 10:00 Write the quarterly report ⏫ 📅 2026-10-24 #work
- [/] Review Mina's draft @mina [estimate:: 45m]
- [ ] Renew the passport [due:: 2026-11-30] [priority:: high]
- [x] Pay rent ✅ 2026-10-01
```

### Recurring todos

A todo with a recurrence rule (`🔁 every week` or `[repeat:: every week]`)
and a date comes back. When you complete it, by its checkbox in a note, on the Todos screen or through
the assistant, AIDE adds the next one, unchecked, on the line below it, after its memo if it has one:

```markdown
- [x] Water the plants 🔁 every week 📅 2026-10-24 ✅ 2026-10-24
- [ ] Water the plants 🔁 every week 📅 2026-10-31
```

- **The rule.** `every day`, `every 3 days`, `every week`, `every 2 weeks`, `every month`,
  `every year`, `every weekday` (Monday to Friday), or days by their full names, such as
  `every Monday, Thursday`. The number goes from 1 to 1000, and upper or lower case doesn't matter.
  A rule AIDE doesn't know adds nothing.
- **The dates.** The next date counts from the due date, or the scheduled date when there's no due
  date, or the start date. The due, scheduled and start dates all move by the same number of days, so
  the gaps between them stay. A month or a year that has no such day ends on its last day: January 31
  plus a month is February 28 (29 in a leap year).
- **`when done`** at the end of the rule (`every 2 weeks when done`) counts from the day you complete
  the todo instead.
- **No date, no next one.** A todo with a rule but no due, scheduled or start date gets no next
  occurrence.
- **What the new one keeps.** Its text, indent, rule and tags. A created date becomes today; the done
  and cancelled dates are left off. The memo stays with the completed todo.
- **One at a time.** Without `when done`, completing a todo that's long overdue adds one next
  occurrence, which may be overdue too.

Undoing the completion never deletes the next occurrence: it stays, edited or not. Completing the
same todo again adds nothing when the line below is already that exact occurrence. Typing `[x]`
yourself in the text doesn't add one; tick the checkbox instead.

An [agent card](#agent-cards) never comes back as a second card: its next occurrence is a plain todo,
without the card, agent and updated fields.

### Agent cards

An agent card is a todo that a coding agent keeps its work on: a todo with a `[card:: …]` field in a
note under the `board` folder, such as `board/aide.md`. Its steps are the todos right under it, and
the first line of its memo says what the agent is doing now:

```markdown
- [/] Agent board plan [project:: aide] [agent:: claude] [card:: k7f2q] ➕ 2026-11-10
    > Codex review, round 2
    - [x] Survey Todos, editor, agents
    - [/] Codex plan review
    - [ ] Send to the owner
```

- Only a todo at the top of its list counts. A subtask with a card field isn't a card, and neither is
  a todo with one in a note outside `board/` (`boards/` and `board.md` are outside too).
- When two cards share an id, the one in the note whose path comes first, then the one higher in
  that note, is the card; the others are duplicates and are left alone.
- A card always gets its completion date when it's done, whatever **Completion date** says.
- The title leaves the card, agent and updated fields out, like the other fields.

### Memos

A todo's memo is a quote indented under it, with no blank line between:

```markdown
- [ ] Call the bank [estimate:: 15m]
    > Ask about the transfer fee.
    >
    > Account ends in 1234.
```

The memo shows under the todo's title on the Todos screen, and it moves with the todo when the todo moves to another day. <Badge text="Next release" /> In the editor, a memo folds to its first line until you put the cursor on its todo (see **Calm todo lines** above).

### Completion dates

When you check a todo off, AIDE appends today's date, ` ✅ 2026-10-22` (or `[completion:: 2026-10-22]` if you write Dataview fields). Unchecking it removes the date again. **Completion date** in **Settings › Todos** decides when this happens; Review counts completed todos by that date. An [agent card](#agent-cards) always gets the date.

## The Todos screen

The **Todos** screen shows the number of open todos and switches between **Today** and **All**. Your choice is remembered on the device.

**Today** is the day in order:

- **All day**: today's all-day calendar events.
- **Schedule**: today's timed calendar events (read-only) together with today's time-blocked todos, by start time.
- **Overdue**: todos whose due or scheduled date has passed.
- **No time yet**: today's todos without a time block.

**All** groups every open todo the way your [view preset](#view-presets) says.

<Badge text="Next release" /> With the [agent board](/docs/guides/agent-board/) on, the switch is **Today**, **Board** and **All**. Your coding agents' work (their cards, the steps under them, and any todo with an `agent` field and what's under it) stays off **Today** and **All**, and out of what the assistant plans with; **All** ends with a line such as **3 agent cards on the Board**, which opens the board showing only the agents' cards.

A todo counts as today's when it's in today's daily note or its due (or scheduled) date is today.

### Adding todos

**+** (**Add todo**) asks **Add to today** and adds the line under the **Todo** heading of today's daily note, creating the note or the heading if needed. In the Scribble and GTD presets it asks **Add to inbox** and adds it to your inbox note instead. In Time blocking you can type the block first: `09:00 - 10:00 Focus`. The heading and the inbox note are set in **Settings › Todos**.

You can also just type a todo into any note.

### Working with a todo

Click a todo to open its note at that line. Its menu (right-click on the Mac and Linux, touch and hold on the iPhone; on the iPhone, swipe left for **Done** and right for **Start**) has:

- **Done**, **In progress**, **To do**, **Cancel**, and **Migrated** in the Bullet Journal preset.
- **Move to today** and **Move to tomorrow**: the todo, its memo and its subtasks move to that day's daily note, and the line where it was becomes `[>]`. An earlier day's group has a **Move to today** button for all of its todos. A todo that moves out of a daily note takes that day along as its created date (` ➕ 2026-10-20`) unless it has one, so its [age](#old-todos) carries over.
- **Move to a day…**: the same, to a day you pick from today on.
- **Someday**: adds your someday tag (`#someday`) so the todo waits under **Someday / maybe** at the end of **All**, out of the way. It isn't asked about as an old todo.
- **Add memo…** or **Edit memo…**: the memo under the todo.
- **Set time…**: how long it should take, as `25m`, `1h` or `1h30m`. AIDE writes it as `[estimate:: …]` and shows it as a timer chip.
- **Schedule…** (today's todos): a start and an end, such as `09:00` and `10:30`; the end can be left out. AIDE writes it as the todo's time block. **Remove** takes it away.
- **Focus for 25m**: starts a focus timer for the todo.
- <Badge text="Next release" /> **Give to an agent** (a todo that isn't under another open todo, with the [agent board](/docs/guides/agent-board/) on): the todo becomes a card for your coding agents. It moves, with its memo and subtasks, to its project's board note (such as `board/aide.md`, or `board/inbox.md` with no project), and the line where it was becomes `[>]`. It leaves **Today** and **All** and shows on the Board in the column its status gives it (**To do** for a todo you haven't started) until an agent picks it up. A repeating todo can't be given.

### The Board

<Badge text="Next release" /> **Board** shows your todos and your coding agents' cards in four columns, so you can see at a glance what is being worked on and where you're needed:

- **To do**: open todos and cards. Your own todos tagged with your someday tag stay in **All** instead.
- **Doing**: in progress (`[/]`).
- **Waiting**: open and tagged with your waiting tag (`#waiting`), such as a card whose agent asked you something.
- **Done**: done this week (the week starts on the day **Settings › Journal** says), and a done or cancelled card that still has open steps under it, whatever its day, with **2 steps still open**.

A todo's open subtasks ride on it instead of being cards of their own, and a card's steps always ride on the card. The line under the title counts what matters now, such as **2 working · 1 needs you · 4 done this week**; click a figure to show only those cards, and again to show all. Under it, **All**, **Agents** and **Mine** pick whose work shows, and a chip for each project shows only that project's lane. Your choices are remembered on the device.

Each project is a lane across the columns: projects with an agent card in progress come first, then the others, then **No project**, which starts folded when it holds more than 10. Click a lane's name to fold it. In a column, cards that need you come first, then overdue ones, then by priority, due date and age.

A card shows its title on two lines, then its agent (**Claude**, **Codex**, **Grok** or **Agent**) and its progress, such as **2/4**, and one line of what's happening. While the agent's terminal pane is open in AIDE, the card shows what the pane is doing, the same way everywhere:

- a filled dot and **Working**, with what it's running (**Bash: Run the tests**);
- a warning sign and **Needs you: Approve** or **Needs you: Answer**, with what it's asking;
- an hourglass and how long it has been idle (**Idle 12m**).

The board never moves a card because of this: the column is what the note says. Without an open pane, a card in **Doing** says when the agent last wrote it and its status line, such as **Updated 2h ago · Running the Linux e2e**.

Click a card to see its details beside the board (in the right panel's **Card** view on the Mac and Linux, in a sheet on the iPhone): its column, agent and project, what its pane is doing with **Open pane**, its **Plan** with a checkbox for each step you can tick, its status, where it came from, and its note with **Open note**. Double-click a card to open its note at the card. On the Mac and Linux, with a card selected, the arrow keys move between cards, <kbd>Return</kbd> shows its details, <kbd>O</kbd> opens its pane and <kbd>⌘</kbd><kbd>Return</kbd> (<kbd>Ctrl</kbd><kbd>Return</kbd> on Linux) opens its note.

On the iPhone the board shows one column at a time, **Doing** first; the bar under the summary switches columns and shows how many cards each holds. The iPhone shows what a pane is doing only for the computers whose AIDE terminal it's connected to.

<Badge text="Next release" /> To move a card, drag it onto another column on the Mac and Linux. Dropping it in another project's lane also sets its project (**No project** takes it out). Every platform also has **Move to** in the card's menu (right-click on the Mac and Linux, touch and hold on the iPhone) and in its details, with the other columns; it's the iPhone's way to move a card. Moving to **Waiting** adds your waiting tag, moving to **To do**, **Doing** or **Done** takes it off, and **Done** completes the todo as checking it does. When a todo still has open subtasks, **Done** asks first: **Complete all** completes them and the todo, **Cancel** leaves it as it was. If the note changed meanwhile, nothing is written and the board reads it again.

The card's menu and details also have **Give to an agent** for a todo of yours that isn't a card yet, as in **Today** and **All**.

### Focus timer

**Focus for** runs a timer for the todo's estimate, else its time block's length, else 25 minutes. A bar on top of the list shows the todo's title and the time left, with **Done**, which checks the todo off, and **Stop**. When the time is up you get a notification, even with AIDE closed. One focus runs at a time per vault, and it survives relaunching the app. Nothing is written to the note until you press **Done**.

#### Pomodoro

Turn on **Pomodoro** under **Settings › Todos › Focus** to follow each focus with a break, as copad's
pomodoro did:

- A focus runs for the todo's estimate, else for **Focus** (25 minutes). When it's over, a **Break**
  (5 minutes) starts by itself. Every few finished focuses (**Long break every N focuses**, 4) the break is a
  **Long break** (15 minutes).
- When a break is over, AIDE waits for you to start the next focus. It never loops on its own.
- The bar shows the phase, the time left and how many focuses you finished today, with **Pause**
  (**Resume**) and **Skip**. A skipped or stopped focus doesn't count. The count starts again at
  midnight.
- You get a notification when a focus or a break is over. On the Mac and iPhone it comes even with AIDE
  closed. On Linux it comes while AIDE runs, and a break that ended while it was closed is told once
  when it starts again.
- On the Mac and Linux, the focus also shows as a ring at the bottom of the sidebar
  ([status items](/docs/guides/appearance/#status-items-mac-and-linux)), whose right-click menu
  pauses, skips and stops it.
- Changes in Settings apply from the next focus, on this device.
- On the Mac and Linux, the command palette has **Pause or resume the focus**, **Skip to the next
  phase** and **Stop the focus** (`focus/toggle`, `focus/skip`, `focus/stop`), which you can give a
  shortcut.

For a separate timer that logs a daily count, see the [Pomodoro plugin](/docs/plugins/pomodoro/).

### The assistant's proposals

The [assistant](/docs/guides/assistant/) can propose changes to your todos: times, estimates, moves, new todos. They wait on the Todos screen under the todo they change, and new todos under **Proposed**, until you take (**✓**) or drop (**✕**) them, or **Take all** (or **Drop all**).

## Old todos

Todos you keep not doing pile up. AIDE asks about old ones, so each gets a decision: do it today, give it a day, keep it for someday, or drop it.

### How old a todo is

A todo's age counts from its created date (`➕ 2026-10-01` or `[created:: 2026-10-01]`), else from the date of the daily note it's in. A todo in a note without a date and with no created date has no age, and is never asked about.

A todo is **old** when it's open, not indented, and as old as **Settings › Todos › Old todos** says (14 days unless you change it), unless it's:

- today's (in today's daily note, or due or scheduled today);
- overdue (Overdue asks about it already);
- waiting for a day ahead: due, scheduled or starting after today, or in a daily note after today;
- kept for someday (tagged with your someday tag);
- scheduled for later (`[<]`).

Taking an old todo into today is the decision for that day: if it isn't done, it's asked about again the next day.

### To decide

**All** shows old todos under **To decide**, after today's groups, the oldest first, each with a chip saying how many days old it is. They don't show in the preset's other groups. **Today** says how many wait (**N old todos to decide**). When a vault opens with more than 30 old todos, **All** says so once, with **Tidy up…**; **Not now** hides that for good on this device.

### Tidy up

**Tidy up…** (in the Todos header, and on **To decide**) decides on several todos at a time:

- **Old** lists the old todos, oldest first. **No age** lists the open todos in notes without a date that have no created date, by note: nothing tells how old they are, so they're never asked about otherwise. **All open** lists every open todo.
- Pick todos, then **Today**, **A day…**, **Someday** or **Drop**. Drop marks them cancelled (`[-]`) where they are. A todo that changed meanwhile is left as it is, and AIDE says how many.
- **Look alike** groups open todos whose titles read the same (case and spaces aside). Open a group to see each one as it's written, with its memo and note, and **Keep** the one to keep: the others are dropped. Recurring todos are never grouped.
- **Ask the assistant** hands the old todos to the [assistant](/docs/guides/assistant/), which proposes a decision for each: today, a day, someday or drop. Nothing changes until you take a proposal.

### The weekly tidy

With [**Speak first**](/docs/guides/assistant/#speaking-first) on, the assistant asks about old todos once a week, on **Weekly tidy**'s day at the evening recap's time (21:00 when the recap is off), when there are some. Its proposals wait on the Todos screen like any other.

## View presets

The preset menu in the Todos header, or **View** in **Settings › Todos**, picks how **All** is grouped. It changes only the grouping and where **+** adds a todo; your notes stay the same.

| Preset | Groups | New todos go to |
| --- | --- | --- |
| **Simple** | Overdue, Today, Upcoming, then each earlier daily note and each other note | today's daily |
| **Scribble** | one group per note, nothing else | the inbox note |
| **Time blocking** | Today's blocks in time order, Today, no time yet, then Everything else | today's daily |
| **GTD** | Inbox (todos in the inbox note), In progress (`[/]`), Next actions, Waiting for (`#waiting`), Someday / maybe (`#someday`) | the inbox note |
| **Eisenhower** | Do now — urgent & important, Schedule — important, Delegate — urgent, Later — neither | today's daily |
| **Bullet Journal** | each day's log, newest first, then other notes as collections; adds **Migrated** to a todo's menu | today's daily |

In Eisenhower, a todo is important when its priority is high or highest, and urgent when it's due or scheduled within two days. The [Eisenhower plugin](/docs/plugins/eisenhower/) draws the same four quadrants as a matrix tab.

**Except on that day's daily** leaves out the date when you complete a todo in the daily note of that same day, where the note's date already says when.

### Carrying open todos

With **Carry open todos** on, a new daily note gets the previous daily note's open top-level todos (`- [ ] ` lines that aren't indented). The previous note's lines are then marked: **Move, mark source \[>\]** turns them into `- [>]`, migrated, and **Move, strike through (이월)** turns them into `- [x] ~~…~~ (이월)`.

Carrying needs `{{slot todo-carry.open}}` in your daily template, which is where the todos go:

```markdown
## Todo
{{slot todo-carry.open}}
```

With **Old todos when carrying** on **Leave them where they are**, a todo that's old (by its age, whatever day it's carried into) or kept for someday isn't carried: it stays open where it is, so a new day doesn't fill up with old ones. Todos keeps listing it from there, in whichever group fits it now. A carried todo takes the day it came from as its created date when it has none.

In a local vault, AIDE carries the todos itself. With a server or a desktop host, the [Todo carry](/docs/plugins/todo-carry/) plugin does it and needs to be turned on.
