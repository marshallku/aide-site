AIDE on the Mac and Linux has the same shortcuts, with <kbd>⌘</kbd> on the Mac where Linux uses
<kbd>Ctrl</kbd>. On the Mac each one is also in the menu bar, and every command is in the command
palette with its shortcut.

You can change any of them, turn them off and add your own in **Settings › Keyboard**: see
[Change your shortcuts](#change-your-shortcuts).

<kbd>⌘</kbd><kbd>2</kbd> Wiki, <kbd>⌘</kbd><kbd>3</kbd> Todos, <kbd>⌘</kbd><kbd>4</kbd> Graph, then

The mouse's back and forward buttons also go back and forward. A note opened with <kbd>⌘</kbd>-click
(<kbd>Ctrl</kbd>-click on Linux) or the middle button opens in a new tab.

<kbd>⌥</kbd><kbd>Space</kbd> by default. Change or turn it off in **Settings › Quick capture**
(**Quick capture shortcut**, **Shortcut**). In the window:

| Action | Keys |
|---|---|
| Save to Scratch | <kbd>Return</kbd> |
| New line | <kbd>⇧</kbd><kbd>Return</kbd> |
| Close | <kbd>Esc</kbd> |
| Move through the command list (after <kbd>/</kbd>) | <kbd>↑</kbd> <kbd>↓</kbd> |
| Pick a command | <kbd>Tab</kbd> or <kbd>Return</kbd> |

The menu bar icon (**Show AIDE in the menu bar**) has **Quick capture…** too.

On Linux, bind a shortcut in your desktop or compositor to `aidectl capture`, which adds its text
(its arguments, or standard input with `-`) as a scratch note. See [aidectl](/docs/developers/aidectl/).

### The prefix key

The terminal has a prefix key, as comux and tmux do: press it, let go, then press one more key. The prefix is
<kbd>Ctrl</kbd><kbd>B</kbd> (on the Mac <kbd>⌃</kbd><kbd>B</kbd>) until you set another one: **Settings › Keyboard ›
Terminal prefix** shows **⌃B (default)** on the Mac and **Ctrl+B (default)** on Linux. Click it and press the key you
want; **Clear** turns the prefix off, and it stays off. The prefix is <kbd>Ctrl</kbd> (on the Mac <kbd>⌃</kbd>) with a
letter, <kbd>Space</kbd>, <kbd>[</kbd>, <kbd>\\</kbd> or <kbd>]</kbd>; anything else isn't taken.

While a terminal has the keyboard, the prefix doesn't reach the program: the status bar shows `^B`
(for <kbd>Ctrl</kbd><kbd>B</kbd>) until the next key, which does one of these:

| Key after the prefix | Does |
|---|---|
| <kbd>%</kbd> / <kbd>"</kbd> | Split right / Split down |
| <kbd>o</kbd> | Next pane |
| <kbd>h</kbd> <kbd>j</kbd> <kbd>k</kbd> <kbd>l</kbd>, or the arrows | Focus the pane to the left / below / above / to the right |
| <kbd>`</kbd> | Last pane |
| <kbd>q</kbd> | Show pane numbers |
| <kbd>H</kbd> <kbd>J</kbd> <kbd>K</kbd> <kbd>L</kbd> | Move the divider left / down / up / right |
| <kbd>z</kbd> | Zoom pane |
| <kbd>x</kbd> | Close pane |
| <kbd>c</kbd> | New terminal tab |
| <kbd>C</kbd> | New space… |
| <kbd>$</kbd> / <kbd>X</kbd> | Rename space… / End space… |
| <kbd>)</kbd> / <kbd>(</kbd> | Next space / Previous space |
| <kbd>;</kbd> or <kbd>Tab</kbd> | Last place |
| <kbd>&lt;</kbd> / <kbd>&gt;</kbd> | Back to the previous place / Forward to the next place |
| <kbd>m</kbd> / <kbd>'</kbd> | Mark this pane… / Go to a mark… |
| <kbd>f</kbd> or <kbd>w</kbd> | List tabs… |
| <kbd>g</kbd> | [Lock the switcher key](/docs/guides/terminal/#the-switcher-key), or unlock it; the status bar shows `LOCK` while it's locked |
| <kbd>Shift</kbd><kbd>←</kbd> / <kbd>Shift</kbd><kbd>→</kbd> | Move tab left / Move tab right |
| <kbd>!</kbd> | Jump to the agent that needs you |
| <kbd>u</kbd> | Jump to the newest finished agent |
| <kbd>R</kbd> | Resume a conversation… |
| <kbd>[</kbd> | Copy mode |
| <kbd>Ctrl</kbd><kbd>E</kbd> | Open history in editor <Badge text="Next release" /> |
| <kbd>Space</kbd> | Next layout |
| <kbd>Alt</kbd><kbd>1</kbd> … <kbd>Alt</kbd><kbd>5</kbd> (<kbd>⌥</kbd> on the Mac) | Even horizontal, Even vertical, Main horizontal, Main vertical, Tiled layout |
| <kbd>E</kbd> | Spread panes evenly |
| <kbd>{"{"}</kbd> / <kbd>{"}"}</kbd> | Swap with the previous pane / Swap with the next pane |
| <kbd>Ctrl</kbd><kbd>O</kbd> / <kbd>Alt</kbd><kbd>O</kbd> (<kbd>⌃</kbd> / <kbd>⌥</kbd> on the Mac) | Rotate panes / Rotate panes back |
| <kbd>B</kbd> | Break pane into a tab |
| <kbd>T</kbd> | [Rename pane…](/docs/guides/terminal/#name-a-pane) |
| <kbd>S</kbd> | Sync panes |
| <kbd>n</kbd> / <kbd>p</kbd> | Next terminal tab / Previous terminal tab |
| <kbd>1</kbd> … <kbd>9</kbd> | Tab 1 … Tab 9 |
| <kbd>,</kbd> | Rename terminal tab…: the tab's name field in the status bar |
| <kbd>&amp;</kbd> | Close terminal tab, with all its panes |
| <kbd>s</kbd> | Show or hide the panel |
| <kbd>a</kbd> | Notifications |
| <kbd>W</kbd> | New worktree… |
| <kbd>?</kbd> | **Terminal keys**: **Settings › Keyboard** with the terminal's actions, each with its prefix key |

- The prefix pressed twice sends it to the program, for a tmux or readline inside.
- <kbd>Esc</kbd>, or a key that isn't in the table, does nothing and the prefix lets go.
- After <kbd>H</kbd> <kbd>J</kbd> <kbd>K</kbd> or <kbd>L</kbd>, those four keep working without the prefix for half
  a second after each press, so prefix <kbd>H</kbd> <kbd>H</kbd> <kbd>H</kbd> moves the divider three times.
- While an input method is composing, the prefix doesn't arm. On Linux AIDE can't see a
  composition the terminal is holding; a key that types Hangul or kana there cancels the prefix and
  goes to the program.
- Clicking outside the terminal, or leaving the window, lets go of it too.

The keys are matched where they are on a US keyboard, so they work with any layout or input
source. On Linux you can change the table in `config.toml`:

```toml
[keybindings.prefix]
prefix = "ctrl+b"                    # Settings › Keyboard › Terminal prefix writes this
"|" = "action:terminal/split-right"  # another key for an action
z = "none"                           # a key taken out of the table
```

A key is one character as you type it (`%`, `H`, `|`), or a named key with `ctrl`, `alt` or
`shift` (`shift+left`, `tab`); comux's `C-o`, `M-1` and `S-Left` work too. An entry that isn't a key
with `action:<id>` or `none` is listed in **Settings › Keyboard** and left out. On the Mac the table
is kept in the app's settings with the prefix. <Badge text="Next release" /> A value reads as the
shortcuts' values do: `action:<id>` followed by other words is `<id>`, and `none` works in any case.

## Change your shortcuts

On the Mac and Linux, everything the command palette runs is a named
action, and **Settings › Keyboard** lists each one with the shortcut that runs it now. There you
give an action a new shortcut, turn one off, and put shell commands on shortcuts of their own.

### Record a shortcut

<Steps>

1. Open **Settings › Keyboard**. **Search shortcuts** narrows the list by name or by shortcut.
2. Click the shortcut next to an action (**None** when it has none). It reads **Type a shortcut…**.
3. Press the new shortcut. <kbd>Esc</kbd> keeps the old one; on Linux <kbd>Backspace</kbd> leaves
   the action with none. Nothing runs while AIDE is listening.

</Steps>

The new shortcut replaces the action's built-in one. If another action had it, that action loses
it, and AIDE says so: "… had this shortcut; it's off now." That action stays off, so its built-in
shortcut doesn't come back later when you move yours elsewhere.

<Badge text="Next release" /> Giving an action its own built-in shortcut back takes it from no
other action's built-in one: on the Mac, <kbd>⌘</kbd><kbd>T</kbd> back for **Open today's note**
leaves **New terminal tab** on <kbd>⌘</kbd><kbd>T</kbd> in a terminal. An action with two built-in
shortcuts that loses one keeps the other, and AIDE says nothing: Linux's **Back** keeps
<kbd>Alt</kbd><kbd>Left</kbd> when another action takes <kbd>Ctrl</kbd><kbd>[</kbd>.

- **Clear** turns an action's shortcut off, built-in one included.
- **Reset** gives one action its built-in shortcut back. It appears only on an action you changed.
- **Reset all** gives every action its built-in shortcut back. Your commands stay.

On the Mac, the menu bar shows each action's shortcut as you set it.

### Which shortcuts you can use

A shortcut is one key with modifiers, and it needs <kbd>⌘</kbd> or <kbd>⌃</kbd> on the Mac, or
<kbd>Ctrl</kbd> or <kbd>Super</kbd> on Linux. A key alone, or with only <kbd>Shift</kbd> or
<kbd>⌥</kbd> / <kbd>Alt</kbd>, is typing: on many keyboard layouts <kbd>⌥</kbd> and <kbd>Alt</kbd>
type letters and accents, so AIDE doesn't take them. Pressing one while recording says
**Hold Command or Control with a key.** (**Hold Ctrl or Super with a key.** on Linux).

A shortcut is the key's place on the keyboard, named by what that key types on a US keyboard. So
it's the same shortcut whatever input source or layout you type with, and <kbd>⇧</kbd><kbd>⌘</kbd><kbd>1</kbd>
stays <kbd>⇧</kbd><kbd>⌘</kbd><kbd>1</kbd>, not <kbd>⌘</kbd><kbd>!</kbd>. Function keys
(F1–F24), the arrows, Home, End, Page Up, Page Down, Insert, Delete, Backspace, Tab, Return, Esc
and Space work too.

While an input method is composing (Korean, Japanese, Chinese), no shortcut runs, and holding a
shortcut's keys down runs it once.

### In a terminal

The keys you press in a terminal belong to the program running there, so your shortcuts step aside:

- **Mac**: while a terminal has the keyboard, only shortcuts with <kbd>⌘</kbd> reach AIDE. A
  <kbd>⌃</kbd><kbd>⌥</kbd><kbd>J</kbd> of yours goes to the program there, and works everywhere else.
- **Linux**: while a terminal has the keyboard, only shortcuts with <kbd>Ctrl</kbd><kbd>Shift</kbd>
  or <kbd>Ctrl</kbd><kbd>Alt</kbd> (and <kbd>Ctrl</kbd><kbd>,</kbd>) reach AIDE. Plain
  <kbd>Ctrl</kbd> letters, <kbd>Super</kbd> shortcuts and function keys go to the program.

The switcher key is the one more key that reaches AIDE in a pane:
**Open the switcher from a pane**, <kbd>⌃</kbd><kbd>F</kbd> on the Mac and <kbd>Ctrl</kbd><kbd>F</kbd>
on Linux (see [The switcher key](/docs/guides/terminal/#the-switcher-key)). The note under the list
in **Settings › Keyboard** says so too.

- Give it another shortcut, and that one opens the switcher in a pane while <kbd>Ctrl</kbd><kbd>F</kbd>
  goes to the program again. **Clear** sends <kbd>Ctrl</kbd><kbd>F</kbd> to the program, and the
  switcher keeps <kbd>⇧</kbd><kbd>⌘</kbd><kbd>O</kbd> (<kbd>Ctrl</kbd><kbd>Shift</kbd><kbd>O</kbd>).
- The prefix key, then <kbd>g</kbd>, locks it so the program gets <kbd>Ctrl</kbd><kbd>F</kbd>; the
  same again unlocks it. A plain <kbd>Ctrl</kbd><kbd>G</kbd> never does.
- On Linux it shares <kbd>Ctrl</kbd><kbd>F</kbd> with **Find in note**: one acts in a pane, the other
  in a note. Giving either one its own shortcut back takes nothing from the other. Recording
  <kbd>Ctrl</kbd><kbd>F</kbd> for any other action takes it from both.
- <Badge text="Next release" /> The switcher key and the other actions no longer take each other's
  built-in shortcuts. Recording <kbd>Ctrl</kbd><kbd>F</kbd> (on the Mac <kbd>⌃</kbd><kbd>F</kbd>)
  for another action takes it from **Find in note** on Linux, but a pane keeps it as the switcher
  key; and recording an action's built-in shortcut for the switcher key leaves that action its
  shortcut outside a pane. A shortcut you recorded is still one action's: recording it for the
  switcher key, or the switcher key's for another action, takes it, and the one that had it is off.
  The exception is the switcher key's own <kbd>Ctrl</kbd><kbd>F</kbd>: giving it back to the
  switcher key takes nothing, so an action you recorded <kbd>Ctrl</kbd><kbd>F</kbd> for keeps it
  outside a pane.

The terminal's own actions (**New terminal tab**, **Split right**, **Split down**, **Next pane**,
**Previous pane**, **Close pane**, the focus, divider, zoom and pane-number ones, the space
actions, and the switcher, history, mark and move-tab ones) run only
while a terminal has the keyboard, whatever shortcut you give them.

### Commands

**Commands** puts a shell command on a shortcut, for the Mac (not the Mac App Store build) and
Linux.

<Steps>

1. In **Settings › Keyboard › Commands**, type the command in **Shell command**.
2. Record its shortcut: on the Mac, click the button next to **Add a command** and press the
   shortcut; on Linux, click the shortcut button in the row, press the shortcut, then click
   **Add a command**.

</Steps>

The command runs with `/bin/sh -c` in your home folder, with AIDE's environment, and its output is
dropped; AIDE doesn't wait for it. If it can't start, AIDE says **The command didn't start: …**.
**Remove** takes a command off its shortcut. A command takes its shortcut from an action that had
it, as recording does.

### On Linux: config.toml

On Linux, your shortcuts live in `~/.config/aide/config.toml` (the file `AIDE_CONFIG` names, when
set), next to the app's other settings. **Settings › Keyboard** writes them there, keeping your
comments and everything else in the file, and you can edit them by hand. AIDE reads the file again
when it changes.

```toml
[keybindings]                          # a shortcut, then what it does
"ctrl+alt+j" = "action:today"          # a named action
"ctrl+shift+g" = "action:git-sync"
"super+r" = "action:random"
"ctrl+alt+k" = "spawn:touch /tmp/x"    # a shell command (a value without a prefix is one too)

[keybindings_off]                      # built-in shortcuts turned off, by action id
actions = ["new-scratch"]
```

- A shortcut is its modifiers `ctrl`, `alt`, `shift`, `super`, then the key, joined with `+`: a
  letter or digit, a symbol a US keyboard types without <kbd>Shift</kbd> (`]`, `,`, `/`), `space`,
  `f1`–`f24`, `left`, `right`, `up`, `down`, `home`, `end`, `pageup`, `pagedown`, `insert`,
  `delete`, `backspace`, `tab`, `return` or `escape`. Any case works, and so do GTK's names
  (`<Control><Shift>g`, `Page_Down`). Use `ctrl+shift+1`, not `ctrl+!`.
- <Badge text="Next release" /> The file reads every spelling the Mac reads, so a line written either
  way works: the key before its modifiers (`j+ctrl`), the Mac's symbols (`⌃⌥J`), and
  `action:<id>` followed by other words, which are ignored.
- An action you give a shortcut here loses its built-in one; an action can have several.
- One of yours wins over a built-in shortcut with the same keys.

If something in these two tables can't be used (a shortcut without <kbd>Ctrl</kbd> or
<kbd>Super</kbd>, `action:` with no id, a command that's empty, the same shortcut twice, `actions`
that isn't a list), AIDE keeps the shortcuts it had before and **Settings › Keyboard** shows
**The keyboard settings have a problem: …** with what's wrong. A shortcut to an action id the
window doesn't have now does nothing. A shortcut to an action that no
longer exists says **No action is called …** when you press it, and **Settings › Keyboard** lists it
among the problems.

On the Mac, the same shortcuts are kept in the app's settings; change them in **Settings ›
Keyboard**.

### Run an action from a script

`aidectl action run <id>` runs an action in the AIDE window of your vault, as if you'd picked it in
the command palette, and returns once it has finished. It needs the app running with that vault
open; see [aidectl](/docs/developers/aidectl/#action) and the
[local API](/docs/developers/local-api/#actions).
