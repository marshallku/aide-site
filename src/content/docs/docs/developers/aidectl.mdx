`aidectl` reads and writes your AIDE notes from a terminal, a script, an editor or a status bar. It goes through AIDE's own note rules, so a write never overwrites an edit it didn't see. It knows nothing about any particular workflow: you compose `get`, `put`, `append` and `toggle` yourself.

## Install

`aidectl` ships with the desktop app on macOS and Linux. You don't install it separately:

- The install script links `~/.local/bin/aidectl` to the copy inside `AIDE.app` on macOS, and puts it in `~/.local/bin` on Linux (or `<prefix>/bin` with `--prefix`).
- The Homebrew cask (`brew install --cask marshallku/tap/aide`) links it onto your `PATH` too.
- It updates with the app.

Run `aidectl help` for the command list, with any extension commands you've added at the end.

## Pick what it talks to

`aidectl` works on one of two targets:

- **A vault**: a notes folder on this computer. When the AIDE app has that folder open, `aidectl` talks to the app over its [local socket](/docs/developers/local-api/). When a [desktop host](/docs/self-hosting/desktop-host/) serves it, `aidectl` talks to the host, with the whole server behind it. When nothing has it open, `aidectl` opens the folder itself for the length of one command, with the same note rules, and lets it go before it exits.
- **A server**: an AIDE server URL and a token.

It takes the first of these that names a target:

| Source | Vault | Server |
| --- | --- | --- |
| Flags before the command | `--vault DIR` | `--server URL` |
| Environment | `AIDE_VAULT` | `AIDE_URL` |
| Config file | `vault=` | `url=` |

Each source names a vault or a server, not both; one that names both stops with a usage error. A server's token comes from `AIDE_TOKEN`, else from `token=` in the config file.

```sh
aidectl --vault ~/Notes daily
AIDE_URL=https://aide.example.ts.net AIDE_TOKEN=aide_p_… aidectl todos
```

<Aside type="caution" title="An open vault that doesn't answer">
If the app has the vault open but its socket doesn't answer, `aidectl` stops instead of waiting: `… is open in AIDE, but … doesn't answer for it: update or restart the app (or close the vault there)`. A folder that a server keeps its notes in is refused too: talk to that server instead.
</Aside>

### The config file

`~/.config/aidectl/config`, or the file `AIDECTL_CONFIG` names. One `key=value` per line; lines starting with `#` are skipped. A missing default file is fine; a missing file named by `AIDECTL_CONFIG` is an error.

```ini
# a notes folder on this computer (absolute, or starting with ~/)
vault=~/Notes

# or a server
# url=https://aide.example.ts.net
# token=aide_p_…

# a token only the extension aidectl-<name> gets
# token.sync=aide_p_…
```

`vault=` in the file must be an absolute path (or start with `~/`); `--vault` and `AIDE_VAULT` may be relative to the current folder.

### A token for a server

On your own server, use a plugin token scoped to what the caller may touch, minted with the server's `aide plugin-token` command; [Build a server plugin](/docs/developers/server-plugins/) explains tokens and scopes.

## Notes and paths

`<path>` is a note path (`topics/k8s`) or the file it mirrors (`topics/k8s.md`); the note path wins when both exist. Commands that take an id (`toggle`) use the note id that `--json` output and `todos` print.

## Commands

### get

```sh
aidectl get <path> [--json]
```

Prints the note's Markdown body. `--json` prints the whole note instead: `id`, `path`, `kind`, `title`, `body`, `version`, `todos`, `updatedAt`, and `period` / `periodStart` for a journal note.

### put

```sh
aidectl put <path> --create-only [--file f]
aidectl put <path> --base-version N [--file f]
```

Writes a whole body, from `--file` or standard input (`--file -` also reads standard input). You must pass exactly one of:

- `--create-only`: create the note; exit code 3 if the path is already taken. A path ending in `.md` keeps that file name as written.
- `--base-version N`: replace the body only if the note is still at version `N`. If it moved on, nothing is written, your body is saved to a temporary file whose path is printed, and the exit code is 4.

On success it prints the note as JSON.

```sh
v=$(aidectl get topics/k8s --json | jq .version)
aidectl get topics/k8s | sed 's/old/new/' | aidectl put topics/k8s --base-version "$v"
```

### append

```sh
aidectl append <path> [--heading H] [--create-heading] [--if-absent] [--text T] [--json]
```

Adds text (from `--text`, else standard input) at the end of a heading's section, or at the end of the note without `--heading`. It needs no version: if someone edits the note at the same moment, AIDE reads it again and retries.

| Flag | Effect |
| --- | --- |
| `--heading H` | Append under the heading whose text is `H`. Without `--create-heading`, a missing heading is "not found" (exit 5). |
| `--create-heading` | Add `## H` at the end of the note when the heading is missing. |
| `--if-absent` | Skip the append when the same lines already stand together in that section; prints `already there`. |
| `--json` | Print `id`, `path`, `version` and `appended` (true or false). |

```sh
aidectl append daily/2026-10-22 --heading Log --create-heading --text "- 14:10 deployed v2"
```

### edit

```sh
aidectl edit <path>
```

Opens the note in `$VISUAL`, else `$EDITOR`, else `vi`, and saves it back under the version it was read at. While your editor is open, `aidectl` lets go of the vault, so the app can open it. If the note changed meanwhile, nothing is written, your text stays in the temporary file it names, and the exit code is 4. Closing without changes writes nothing.

### daily and periodic

```sh
aidectl daily [YYYY-MM-DD] [--json | --edit]
aidectl periodic <period> <date> [--json | --edit]
```

`daily` prints today's daily note (or that day's), creating it from your daily template if it doesn't exist. `periodic` does the same for the note of `daily`, `weekly`, `monthly`, `quarterly` or `yearly` that contains `<date>`. The date is `YYYY-MM-DD`, or `today`; `weekly` also takes an ISO week (`2026-W43`) and `monthly` a month (`2026-10`). A new note goes where your journal settings put that period. `--edit` opens it in your editor instead of printing it.

### todos

```sh
aidectl todos [--json]
```

Every open todo across your notes, one per line, tab-separated: note id, line (0-based), note version, note path, text. `--json` adds `noteTitle`, `indent`, `due`, `scheduled` and `noteDate` (the day of the daily note it's in).

### toggle

```sh
aidectl toggle <noteId> --line L --version V --text T
```

Checks off (or unchecks) the todo on line `L`, as read at version `V`, if that line still reads `T`. All three flags are required. If the note changed since, it tries again only when the same line still holds that same open todo; a todo with the same text on another line is a different task, so it never searches for it. Otherwise the exit code is 4: list the todos again.

```sh
aidectl todos | grep "call Mina" | head -1 | while IFS=$'\t' read -r id line version path text; do
    aidectl toggle "$id" --line "$line" --version "$version" --text "$text"
done
```

### search

```sh
aidectl search <query…> [--limit N] [--json]
```

Full-text search. Prints path and title, tab-separated, for each match. `--limit` defaults to 20; the most the server returns is 50.

### capture

```sh
aidectl capture [text… | -]
```

Adds a scratch note, as the apps' quick capture does. The text comes from the arguments, or from standard input with `-` or no arguments; it's trimmed, and empty text is a usage error. Prints the new note's path (`--json`: the note).

Text starting with `/todo` (or `/할일`) adds each line after it to today's todos instead, under the daily note's todo heading, and prints the daily note's path once per todo (`--json`: the daily note); `/todo` with nothing after it is a usage error. It works with a server and with a notes folder alike.

```sh
pbpaste | aidectl capture
```

### status

```sh
aidectl status [--json | --waybar] [--format T]
```

One look at your day: open todos, overdue ones, ones due today, scratch notes, today's daily note, and the next calendar event. It never creates the daily note.

- Overdue means due (else scheduled) before today; due today includes undated todos in today's daily note, as the Todos tab counts them. "Today" is in the time zone of your settings.
- The next event is the first timed event from the Google Calendar plugin in a calendar you show. It appears only when `aidectl` talks to a server as its owner; through a vault or with a plugin token it's left out.

Without flags it prints a short summary:

```text
12 open todos · 2 overdue · 3 due today
4 scratch notes
Today: daily/2026-10-22
Next: 15:00 Design review
```

`--format` sets your own line with these placeholders; an unknown one is a usage error:

| Placeholder | Value |
| --- | --- |
| `{open}` | Open todos |
| `{overdue}` | Overdue todos |
| `{today}` | Todos due today |
| `{scratch}` | Scratch notes |
| `{date}` | Today, `YYYY-MM-DD` |
| `{daily}` | Today's daily note's title, empty if it doesn't exist |
| `{next}` | `15:04 Title` today, `Mon 15:04 Title` on a later day, empty without one |

`--json` prints `date`, `open`, `overdue`, `today`, `scratch`, `daily` (`id`, `path`, `title`, or `null`) and `next` (`title`, `start`, `end`, when there is one). `--json` doesn't combine with `--waybar` or `--format`.

`--waybar` prints one line of JSON for a [Waybar](https://github.com/Alexays/Waybar) custom module: `text` (your `--format`, default `{open}`), `tooltip` (the summary above), and `class` / `alt` set to `overdue` when anything is overdue, else `ok`. On any failure it still prints a line, with `text` `!`, the error in `tooltip` and class `error`, and exits 0, because Waybar hides a module whose command fails.

### watch

```sh
aidectl watch (--waybar | --json | --format T) [--interval 30s]
```

Prints the status again whenever it changes, one line per change, checking every `--interval` (default `30s`, at least `1s`). It needs one of the three output flags. Each check opens the vault or server and lets it go, so a vault is never held between checks. A failed check prints the error line with `--waybar`, or tells standard error once, and watching goes on.

A Waybar module that updates by itself:

```json
"custom/aide": {
    "exec": "aidectl watch --waybar --format '{today} today · {overdue} late'",
    "return-type": "json",
    "on-click": "aidectl open todos"
}
```

### open

```sh
aidectl open [today | scratch | wiki | todos | <period> | YYYY-MM-DD | <path> | aide://…] [--print]
```

Opens the AIDE app at that place, through `open` on macOS or `xdg-open` on Linux. Without an argument it opens today's daily note. A period (`weekly`, …) opens the current note of that period; a date opens that day's daily note; a note path opens that note (only this form needs the vault or server, to look up the note's id). An `aide://` link is checked against the links the apps accept: `aide://note/<id>`, `aide://today`, `aide://periodic/<period>[/YYYY-MM-DD]`, `aide://scratch`, `aide://wiki`, `aide://todos`.

`--print` prints the link instead of opening it.

### action

<Badge text="Next release" />

```sh
aidectl action list [--json]
aidectl action run <id>
```

Lists and runs the AIDE app's named actions: what its command palette runs, by id (`today`, `git-sync`, `terminal/split-right`, `plugin/<plugin>/<command>`). [Keyboard shortcuts](/docs/guides/shortcuts/#action-ids) lists the ids.

- `list` prints each action the window has now: id, title, and `unavailable: …` with the reason for one that can't run now (a note command with no note open, say). `--json` prints them as a list of `id`, `title`, `available` and `why`.
- `run` runs the action and returns once it has finished, as if you'd picked it in the command palette. It prints nothing when it worked. It waits at most two minutes.

Actions run in a window, so this command talks only to the AIDE app on this computer, never to a desktop host or a server, and never opens the folder itself. The target must be a vault (`--vault`, `AIDE_VAULT` or `vault=`), open in the app: a server is a usage error. The action runs in the window of that vault you used last, even when another vault's window is in front.

| What happened | Exit code |
| --- | --- |
| The action ran (or the list printed) | 0 |
| The app isn't running with the vault open, or is the Mac App Store build (it has no local API) | 1 |
| The action can't run now (`… can't run now: …`), or failed | 1 |
| No AIDE window shows the vault | 1 |
| A server as target, or wrong arguments | 2 |
| No action has that id | 5 |

```sh
aidectl action run today
aidectl action list | grep plugin/
```

### trigger

<Badge text="Next release" />

```sh
aidectl trigger list [--json]
aidectl trigger run <name>
```

Lists the [Triggers](/docs/guides/triggers/) of the AIDE app and runs one now. `list` prints each
trigger with what it listens for or its schedule, whether it's on or paused, and its last run.
`run` runs it once, skipping `when` and `condition`; it's refused while the trigger is off,
paused, already running, or a command without `allow_privileged`. Both need the Triggers core
plugin on.

### event

<Badge text="Next release" />

```sh
aidectl event emit <name> [--data JSON]
aidectl event tail [--json] [--all]
```

`emit` sends `custom.<name>` with the JSON object as its payload. Only triggers with
`accept_external = true` fire on it. Inside a trigger's command it passes the run's cause along,
so a chain of triggers stays bounded. `tail` prints events as they happen (from now; `--all` from
the oldest the app keeps) and says so when some were missed.

### status-item

<Badge text="Next release" />

```sh
aidectl status-item set <id> <text> [--icon I] [--ring START END] [--tooltip T] [--action ID] [--order N] [--ttl 5m]
aidectl status-item clear <id>
aidectl status-item list [--json]
```

Shows a small item at the bottom of the AIDE app's sidebar ([Status items](/docs/guides/appearance/#status-items-mac-and-linux-)),
in the windows of the vault it talks to. `--ring` draws a ring that empties from `START` to `END`
(Unix seconds), `--action` is an action id a click runs, and `--order` (0–1000) places it. An item
goes away after its `--ttl` (10 minutes unless you say, at most 24 hours; setting it again renews
it) or when AIDE quits, so a script that stops doesn't leave one behind. A vault has up to 16 of
these. `list` shows every item the vault has, the app's and plugins' included. `aidectl status`
is unchanged.

### terminal

<Badge text="Next release" />

```sh
aidectl terminal <command> [--socket S] [--pane P] [--json]
```

Reads and types into AIDE's terminal, and opens, splits, names and closes its tabs and panes. It talks to the [terminal socket](/docs/developers/local-api/#terminal-socket), not to a vault, so it needs no vault or server. <Badge text="Next release" /> The socket is the terminal server's, which keeps your shells running, so reading and typing work even with no AIDE window open.

| Command | What it does |
| --- | --- |
| `read [--start-row R --start-col C --end-row R --end-col C]` | Prints the screen, or the part of it between those rows and columns (both ends included) |
| `state` | Prints the pane, its tab, size, cursor, folder, title and whether its shell has exited |
| `exec <line…>` | Types the line and <kbd>Enter</kbd>. It doesn't wait for the command to run |
| `feed <text>` | Types the text as it is, without <kbd>Enter</kbd> |
| `history [--lines N]` | Prints the last `N` rows above the screen, then the screen (`N` is 100 unless you say) |
| `context [--history-lines N]` | The rows above the screen (50 unless you say), then the screen |
| `tabs` | Lists every tab and its panes: tab id, pane id, title, and whether the pane is on screen, focused or exited |
| `new-tab` | Opens a new tab and prints its pane id |
| `close-tab [<tab>]` | Closes that tab with every pane in it; without a tab id, closes the focused pane |
| `rename <tab> <title>` | Names a tab; an empty title clears the name |
| `switch-tab <index>` <Badge text="Next release" /> | Selects a tab by its index in `tabs`, counting from 0 |
| `split right\|down` | Splits the pane and prints the new pane's id |
| `focus <pane>` | Brings that pane forward: its tab, the Terminal section and the window |

`read`, `state`, `exec`, `feed`, `history`, `context` and `split` act on the pane `--pane` names, else on the focused pane. A pane's id is in `tabs`, and a pane's own shell has it in `$COPAD_PANEL_ID`. `--json` prints the app's answer as JSON instead of text.

Reading never moves the pane: `read` and `history` read the live screen even when you've scrolled back. A pane whose shell has ended can still be read, but not typed into.

#### Which app it talks to

- `--socket S` names the socket.
- Else, inside one of AIDE's panes, `$COPAD_SOCKET` names it. If nothing answers there, `aidectl` stops with `COPAD_SOCKET (…) answers nothing` instead of trying another: name one with `--socket`.
- <Badge text="Next release" /> Else it uses the terminal server's socket, from any shell: `~/Library/Application Support/AIDE/mux/terminal.sock` on the Mac, `$XDG_RUNTIME_DIR/aide-mux/terminal.sock` on Linux (`/tmp/aide-mux-<uid>/terminal.sock` without `XDG_RUNTIME_DIR`). It's used only when its folder is yours alone and the server answers.
- Else it uses the only AIDE app with a terminal running as your user. With none, it stops. With more than one, it doesn't guess: it lists their sockets and asks you to choose one with `--socket`.

`focus`, `switch-tab` and `new-tab` need an AIDE window showing the terminal; with none, they stop with exit code 1.

The Mac App Store build and the iPhone have no terminal socket.

| What happened | Exit code |
| --- | --- |
| Done | 0 |
| No app to talk to, a `$COPAD_SOCKET` or `--socket` that doesn't answer, or the app refused (a shell that has exited, a pane too small to split) | 1 |
| Several apps running and no `--socket`, or wrong arguments (a `read` range the app refuses, say) | 2 |
| No pane or tab with that id | 5 |

```sh
aidectl terminal tabs
pane=$(aidectl terminal split right)
aidectl terminal exec --pane "$pane" 'make test'
aidectl terminal history --lines 500 > scrollback.txt
```

### agent

<Badge text="Next release" />

```sh
aidectl agent list [--json]
aidectl agent install-hooks [--claude] [--codex] [--yes] [--print] [--remove] [--pre-compact]
```

The [coding agents](/docs/guides/terminal/#coding-agents-) in AIDE's terminal.

`list` asks the terminal server which agents run in its panes, with no AIDE window needed: one row
per agent with its pane, its vault's session, the agent, its state (`done` for a turn nobody has
looked at, `(not updating)` when the last read couldn't be confirmed), how full its context is, and
the step it's on. With none it prints `No agents.` `--json` prints the server's answer as it is.

```text
PANE           SESSION  AGENT   STATE    CONTEXT  DETAIL
1794000000001  work     claude  blocked  41%      Bash: Run the tests
```

`install-hooks` sets up the hooks that let Claude Code and Codex tell AIDE the moment they finish or
need you, as **Set up agent hooks…** in Settings does. It shows each file's diff first, then asks
`Apply? [y/N]`.

| Flag | What it does |
| --- | --- |
| `--claude`, `--codex` | Only that tool's file. Without either, both, skipping a tool that isn't set up here |
| `--print` | Only shows the diff |
| `--yes` | Applies without asking. Without a terminal and without `--yes`, it only shows the diff and exits 1 |
| `--remove` | Takes AIDE's entries out again, only where they're exactly as written; one you edited since is left alone with a note |
| `--pre-compact` | Also adds the [gate that holds Claude Code's auto-compaction](/docs/guides/terminal/#hold-claude-codes-auto-compaction-until-you-commit) while tracked changes are uncommitted. A plain `install-hooks` never adds it; `--remove` takes it out too |

It runs the terminal server's own `hooks` command through the link AIDE keeps,
`~/Library/Application Support/AIDE/bin/aide-mux` on the Mac and `~/.local/share/aide/bin/aide-mux`
on Linux, so open AIDE once first (or set `AIDE_MUX_BIN`). It exits 0 when it wrote, there was
nothing to change, or it only showed; 1 when nothing was written (you said no, no terminal, a file
changed since the diff, a write that failed); 2 for wrong flags.

### browser

<Badge text="Next release" />

```sh
aidectl browser <command> [--tab T] [--json]
```

Drives the AIDE app's [Browser](/docs/guides/browser/): its tabs and pages. Turn the Browser on first (**Settings › Core plugins › Browser**); while it's off every command fails with `plugin_off`.

| Command | What it does |
| --- | --- |
| `open <url>` | Opens the page in a new tab and shows it. It never takes the keyboard |
| `navigate <url>`, `back`, `forward`, `reload` | Moves the tab |
| `state` | Prints the tab's address, title and whether it can go back or forward |
| `exec-js <code>` | Runs JavaScript in the page and prints its value |
| `get-content [--format text\|html]` | Prints the page's visible text, or its HTML |
| `screenshot [--path F]` | The visible page as PNG, written to `F` (base64 without it) |
| `query <selector>`, `query-all <selector> [--limit N]`, `get-styles <selector> <prop,prop…>` | Reads elements and their computed styles |
| `click <selector>`, `fill <selector> <value>`, `scroll [--selector S] [--x X --y Y]` | Acts on the page. Not for passwords: use [`aidectl secret fill`](#secret) |
| `page-info` | Prints the page's address, title, size, scroll position, and how many forms, links, images, inputs and buttons it has |
| `net [--since T] [--filter S] [--limit N]` | The page's requests: what its scripts fetch and the pages it loads (`coverage` on stderr says so) |
| `console [--since T] [--level L] [--filter S] [--limit N]` | The page's console messages |
| `clear-log` | Drops the captured requests and console messages |
| `grab` | Waits up to two minutes for you to click an element in the browser, then prints its description (also copied to your clipboard) |
| `protect [--off]` | Turns protected mode on or off for the tab |
| `tabs` | Lists the tabs: id, mode, address and title, `*` marking the one shown |
| `tab new [<url>] [--foreground]`, `tab select <tab>`, `tab close <tab>`, `tab move <tab> <i>` | Manages tabs. A new tab opens in the background unless you add `--foreground` |
| `profile clear [--kinds cookies,storage,cache]` | Clears the browser's website data (all of it without `--kinds`) |

Without `--tab`, a command acts on the tab the browser shows; with it, an agent works in a background tab without changing what you see. `--json` prints the app's answer as JSON.

While a tab is protected, reading commands (`state`, `exec-js`, `get-content`, `screenshot`, `query`, `get-styles`, `page-info`, `net`, `console`, `scroll`, `grab`) fail with `tab_protected`, and `click`, `fill` and `navigate` only say they ran. Every other tab loads nothing until protection ends.

Like [`action`](#action), this talks only to the AIDE app that has the vault open, never to a desktop host or a server. Any vault the app has open reaches the same browser. The Mac App Store build has no browser. It exits 1 with `code: message` when the app refuses, 5 for a tab or credential that doesn't exist, and 2 for wrong arguments.

```sh
tab=$(aidectl browser tab new http://localhost:3000)
aidectl browser click --tab "$tab" 'button[type=submit]'
aidectl browser console --tab "$tab" --level error
aidectl browser screenshot --path page.png
```

### secret

<Badge text="Next release" />

```sh
aidectl secret <command> [--tab T] [--json]
```

Website passwords for the [Browser](/docs/guides/browser/#passwords-and-protected-mode), kept in the Keychain (Mac) or the Secret Service (Linux) and tied to their site. A password never passes through `aidectl`.

| Command | What it does |
| --- | --- |
| `list [--origin O]` | Lists saved passwords: id, site, username. Never a password |
| `fill <credential>` | Fills it into the protected tab's password field |
| `save <username>` | Saves the password you typed into the protected tab |
| `delete <credential>` | Forgets it |

`fill` and `save` need a protected tab (`requires_protected`), on the credential's own site for `fill` (`origin_mismatch`).

```sh
aidectl browser open https://example.com/login
aidectl browser protect
aidectl secret fill "$(aidectl secret list --origin https://example.com --json | jq -r '.credentials[0].id')"
aidectl browser click 'button[type=submit]'
aidectl browser protect --off
```

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Done |
| 1 | Error |
| 2 | Usage: a wrong flag or argument, or no vault or server configured |
| 3 | Path taken (`put --create-only`) |
| 4 | Conflict: the note moved on; nothing was written |
| 5 | Not found: the note, the heading for `append`, or the action for `action run` |

An extension command exits with its own code (128 plus the signal number when a signal ended it).

## Extensions

Like `git` and `kubectl`, any other command `foo` runs an executable named `aidectl-foo`. Built-in commands always win, and `help` and `plugins` are reserved.

- **Where**: `~/.config/aidectl/plugins/` (or `AIDECTL_PLUGINS_DIR`) first, then each folder on `PATH`. The first file found with that name is the one used. Names are lowercase letters, digits, `-` and `_`, up to 64 characters.
- **Trust**: an extension runs only if the file and every folder on its way (links resolved) belong to you or root and can't be written by others (sticky folders such as `/tmp` excepted). An unsafe file found first is refused, never skipped for a later one. Nothing ever runs from the vault.
- **Environment**: the extension gets your environment without `AIDE_URL`, `AIDE_TOKEN`, `AIDE_VAULT` and `AIDECTL_*`, plus:

| Variable | Value |
| --- | --- |
| `AIDECTL_BIN` | The `aidectl` that ran it, to call back |
| `AIDECTL_PLUGIN_NAME` | Its name (`foo`) |
| `AIDECTL_VERSION` | `aidectl`'s version |
| `AIDECTL_CONFIG` | Only when you named a config file |
| `AIDE_VAULT` | The resolved vault, when the target is one |
| `AIDE_URL`, `AIDE_TOKEN` | The resolved server; the token only when it came from `AIDE_TOKEN` or from `token.foo=` in the config file, never from the general `token=` |

With nothing configured the extension still runs, without a target. A wrong configuration (a vault and a server in one source, a bad path, a missing named config file) stops it, so it never runs against a target you didn't ask for. Ctrl-C at a terminal reaches the extension alone.

- **Metadata**: `aidectl help` and `plugins list` run `aidectl-foo --aidectl-metadata` and expect, within 2 seconds and 64 KiB, `{"schemaVersion": 1, "name": "…", "description": "…", "version": "…"}`.

A minimal extension that prints today's open todo count:

```sh
#!/bin/sh
# ~/.config/aidectl/plugins/aidectl-count  (chmod 755)
if [ "$1" = "--aidectl-metadata" ]; then
    echo '{"schemaVersion": 1, "name": "count", "description": "Count open todos", "version": "1.0.0"}'
    exit 0
fi
exec "$AIDECTL_BIN" status --format '{open} open, {today} today'
```

```sh
aidectl count
```

## Example

Append a line to today's daily note from a git hook:

```sh
aidectl append "$(aidectl daily --json | jq -r .path)" --heading Log --create-heading \
    --text "- $(date +%H:%M) committed $(git log -1 --format=%s)"
```
