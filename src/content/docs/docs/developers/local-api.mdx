While the AIDE app on the Mac or Linux has a vault open, it serves that vault's notes on a Unix socket. Any program you run on the same computer can read and write notes there with plain HTTP, with no server and no token, and gets the same answers a server would give. [`aidectl`](/docs/developers/aidectl/) is built on it; this page is for when you want to call it yourself.

## Who can connect

- Only programs running as **your user** on the same computer. The app checks the user of every connection and closes any other.
- The socket's folder is created with mode `0700` and must be a real folder (not a link) that belongs to you with no access for anyone else; the app refuses to serve, and `aidectl` refuses to connect, otherwise.
- There's no authentication beyond that: whoever reaches the socket acts as the vault's owner.

The iPhone has no local API.

## Where the socket is

The folder is `$XDG_RUNTIME_DIR/aide/` when `XDG_RUNTIME_DIR` is set (most Linux desktops), else `/tmp/aide-<uid>/aide/` (macOS has no runtime folder). There is one socket per open vault, named `<32 hex digits>.sock`, derived from the vault folder's real path and its device and inode numbers. A copy of a vault in another folder gets its own socket.

The easy way to find the right one is to ask each socket which folder it serves:

```sh
dir="${XDG_RUNTIME_DIR:-/tmp/aide-$(id -u)}/aide"
for s in "$dir"/*.sock; do
    printf '%s  ' "$s"
    curl -s --unix-socket "$s" http://aide/me
    echo
done
```

```json
{"mode": "local", "vaultId": "8c4e…", "root": "/Users/you/Notes", "dev": 16777232, "ino": 2918843}
```

The host name in the URL doesn't matter; this page uses `http://aide/`. Use the socket whose `root` is your vault folder (links resolved).

The socket exists only while the app holds the vault open. It disappears when you close the vault or quit the app.

## A desktop host's socket

When a [desktop host](/docs/self-hosting/desktop-host/) serves the vault, its socket sits in the same folder, named `host-<same name>.sock`. It serves the whole server API instead of the routes below, also as you without a token, and its `GET /me` names the folder it serves under `"host"`. `aidectl` tries the host's socket first, then the app's, then opens the folder itself.

## Routes

The same inputs, JSON shapes, status codes and errors as the note routes of an AIDE server.

| Route | What it does |
| --- | --- |
| `GET /me` | Which vault this socket serves: `mode` (`local`), `vaultId`, `root`, `dev`, `ino` |
| `GET /notes?kind=&prefix=` | `{"notes": [Note]}`, newest change first; `kind=scratch` lists scratch notes |
| `GET /notes/lookup?path=` | A note by its path or by the file it mirrors (`topics/x.md`); the note path wins |
| `GET /notes/{id}` | One live note |
| `POST /notes` | `{path?, body?, title?, sourcePath?, template?, vars?}` → `201` Note; `409 path_taken` |
| `PUT /notes/{id}` | `{version, body}` → Note; `409 version_conflict` when the note moved on. Changing `path`, `title` or `sourcePath` isn't supported here (`422 unsupported`) |
| `DELETE /notes/{id}` | `{version}` → `204`; the note is archived, not deleted |
| `POST /notes/{id}/append` | `{text, heading?, createHeading?, ifAbsent?}` → Note plus `appended`; `404 heading_not_found` |
| `POST /notes/{id}/todos/{line}/toggle` | `{version}` → Note; `422` when the line isn't a todo |
| `GET /todos` | `{"todos": [OpenTodo]}`: every open todo |
| `GET /daily/{date}` | The daily note for `YYYY-MM-DD`, created from your template if missing |
| `GET /periodic/{period}/{key}` | The note of `daily`, `weekly`, `monthly`, `quarterly` or `yearly` containing `key` (`YYYY-MM-DD`, `today`, `2026-W43`, `2026-10`), created if missing; `?create=false` answers `404` instead |
| `GET /periodic/{period}/{key}/prev` | The latest existing note of that period before `key`'s |
| `GET /search?q=&limit=` | `{"notes": [{id, path, kind, title, summary?, snippet?}]}`, `limit` up to 50 |
| `GET /notes/{id}/sections/{name}` | A named section a plugin owns; `404` none, `409 section_ambiguous` |
| `PUT /notes/{id}/sections/{name}` | `{content, version?}` → Note |
| `GET /settings` | Your effective settings, plus `serverTimezone` |

A Note is `{id, path, kind, title, body, version, todos, updatedAt}`, with `sourcePath` for a note that mirrors a file under another name and `period` / `periodStart` for a journal note. Line numbers are 0-based.

Everything else a server offers (events, plugins, organize, attachments, changing settings) isn't part of the local API: an unknown route answers `404`, a known path with another method `405`.

### Errors

Errors are `{"error": {"code": "…", "message": "…"}}`. A `version_conflict` also carries `"current"`: the note as it is now.

### Writes never overwrite blindly

- A request that carries a `version` (update, archive, toggle, a section replace with `version`) gets `409 version_conflict` with the current note when the note changed since that version. The app never retries it for you: read again and decide.
- Append and a section replace without `version` re-read and retry when an outside edit lands between their read and their write, up to 3 times.

## Actions

The app's socket also runs its named actions: what the command palette runs, by id. [Keyboard shortcuts](/docs/guides/shortcuts/#action-ids) lists the ids. A desktop host's socket doesn't have these routes (`404`).

| Route | What it does |
| --- | --- |
| `GET /actions` | `{"actions": [{"id", "title", "available", "why"}]}`: the window's actions now; `why` (only on one that isn't available) says what it needs |
| `POST /actions/{id}` | Runs the action and answers once it has finished: `200` `{"id", "ran": true}` |

`POST /actions/{id}` can also answer:

| Status | `code` | When |
| --- | --- | --- |
| `404` | `unknown_action` | No action has that id (a plugin removed meanwhile, say) |
| `409` | `unavailable` | It can't run now; `message` says why |
| `409` | `no_window` | No window shows this vault (`GET /actions` answers this too) |
| `409` | `superseded` | Linux: something else was opened before it finished, so it didn't open what it fetched |
| `500` | `action_failed` | The action failed (its error is the `message`) |
| `500` | `window_closed` | The window closed while it ran |

Both act in the window of this socket's vault that was used last, whether it's in front or not. Escape the `/` in an id (`/actions/plugin%2Fbookmark%2Fsave`); the unescaped form (`/actions/plugin/bookmark/save`) works too. [`aidectl action`](/docs/developers/aidectl/#action) is built on these routes.

With `$s` the socket, as in [Examples](#examples):

```sh
curl -s --unix-socket "$s" http://aide/actions | jq -r '.actions[] | select(.available) | .id'
curl -s --unix-socket "$s" -X POST http://aide/actions/today
```

## Browser

On the Mac and Linux, the app's socket also drives its [Browser](/docs/guides/browser/), once it's turned on in **Settings › Core plugins**. There is one browser per app, so every vault socket of the app reaches the same tabs. A desktop host's socket and the Mac App Store build don't have these routes (`404`). [`aidectl browser`](/docs/developers/aidectl/#browser) and [`aidectl secret`](/docs/developers/aidectl/#secret) are built on them.

| Route | What it does |
| --- | --- |
| `GET /browser/tabs` | `{"tabs": [{"id", "url", "title", "loading", "mode"}], "active"}`: `mode` is `automation` or `protected`, `active` the shown tab's index (`-1` with none). Addresses and titles are empty while a tab is protected |
| `POST /browser/{op}` | Runs the op with the JSON body as its parameters (an empty body is `{}`) and answers `200` with its result |

`tab_id` in the body names a tab; without it, an op acts on the tab the browser shows. The ops:

- Tabs: `tab/new` (`url`, opens in the background unless `background: false`), `tab/select`, `tab/close`, `tab/move` (`index`), `tab/protect` (`on`, `true` unless `false`).
- Moving: `navigate` (`url`), `back`, `forward`, `reload`, `state`.
- The page: `execute_js` (`code`), `get_content` (`format`: `text` or `html`), `query`, `query_all` (`selector`, `limit`), `get_styles` (`selector`, `properties`), `click`, `fill` (`selector`, `value`), `scroll` (`selector`, or `x` and `y`), `page_info`, `screenshot` (`{"image_b64", "width", "height"}`).
- Capture: `net` and `console` (`since`, `filter`, `limit`, and `level` for the console) answer `{"records", "coverage"}`; `clear_log`.
- `profile/list`, `profile/clear` (`kinds`: `cookies`, `storage`, `cache`).
- `grab`: waits up to two minutes for you to click an element and answers `{"prompt"}`, its description.
- Passwords: `secret/list` (`origin`), `secret/fill` (`credential_id`), `secret/save` (`username`), `secret/delete` (`credential_id`). A password is never in a request or an answer.

While a tab is protected, reading ops answer `409` `tab_protected`, writes answer only `{"status", "protected": true}`, and an error carries a fixed message for its code, never the page's text.

| Status | `code` | When |
| --- | --- | --- |
| `400` | `invalid_params` | A parameter is missing or wrong |
| `404` | `unknown_method`, `tab_closed`, `not_found` | No such op, tab, or credential |
| `409` | `plugin_off` | The Browser is turned off |
| `409` | `no_tab` | No tab is open |
| `409` | `tab_protected`, `requires_protected`, `origin_mismatch` | Refused while a tab is protected; a password op on a tab that isn't, or on another site |
| `409` | `purge_incomplete` | The site's service workers or caches couldn't be removed, so protection or the fill was refused |
| `409` | `superseded`, `timeout`, `cancelled` | A Grab that another replaced, that ran out of time, or that ended |
| `500` | `js_error`, `snapshot_failed`, `fill_failed`, `secret_backend_unavailable` | The page's script failed, no screenshot (on Linux, a tab not on screen), the page refused the value, no Keychain or keyring |

```sh
curl -s --unix-socket "$s" http://aide/browser/tabs
curl -s --unix-socket "$s" -X POST http://aide/browser/navigate -d '{"url": "http://localhost:3000"}'
```

## Triggers

On the Mac and Linux, a vault's socket also reaches its [Triggers](/docs/guides/triggers/) while the core plugin is on; otherwise every route answers `409` `plugin_off`. A desktop host's socket and the Mac App Store build don't have them. [`aidectl trigger`](/docs/developers/aidectl/#trigger) and [`aidectl event`](/docs/developers/aidectl/#event) are built on them.

| Route | What it does |
| --- | --- |
| `GET /triggers` | `{"file", "file_error", "paused_all", "triggers", "errors"}`: each trigger with its source, `enabled`, `paused`, `busy`, `next_fire` and its last 10 runs |
| `POST /triggers/{name}/run` | Runs it once now (`202`). `409` `paused` or `busy`, `403` `not_privileged`, `404` `unknown_trigger` |
| `POST /events` | `{"kind": "custom.<name>", "payload"}`: `202` `{"id"}`. Only `custom.*`; a payload over 8 KiB is `413` |
| `GET /events?epoch=&after=&limit=` | `{"epoch", "events", "next", "dropped"}` from the last 500 events. `dropped` is true when `after` is gone, the app restarted, or `after` is ahead |

## Status items

On the Mac and Linux, a vault's socket sets the [status items](/docs/guides/appearance/#status-items-mac-and-linux) at the bottom of that vault's sidebar. A socket sets and clears only its own items (`ext.<id>`); `GET` lists them all, the app's and plugins' included. Nothing is saved: an item goes when its ttl runs out or the app quits. [`aidectl status-item`](/docs/developers/aidectl/#status-item) uses these routes.

| Route | What it does |
| --- | --- |
| `GET /status-items` | `{"items": [...], "shown": 8}`, sorted by `order` then `id`; the first `shown` are on the rail, the rest under … |
| `PUT /status-items/{id}` | `{"text", "icon", "progress": {"start", "end"}, "tooltip", "action", "order", "ttl"}` (all optional, but an item needs text, an icon or a ring): `200` `{"item"}`; `409` `too_many` past 16 |
| `DELETE /status-items/{id}` | `200` `{"id", "cleared"}` |

## Limits

- HTTP/1.1, one request per connection is enough (`Connection: close`).
- Request line and headers up to 16 KiB, body up to 2 MiB, 10 seconds to send a request, 8 connections at once.
- A body needs `Content-Length`; chunked `Transfer-Encoding` is refused. `curl --data` sets it for you.

## Examples

```sh
s="${XDG_RUNTIME_DIR:-/tmp/aide-$(id -u)}/aide/3f9a….sock"   # from the loop above
```

Today's daily note (created if missing):

```sh
curl -s --unix-socket "$s" http://aide/periodic/daily/today | jq -r .body
```

Look up a note and append under a heading:

```sh
id=$(curl -s --unix-socket "$s" "http://aide/notes/lookup?path=topics/k8s" | jq -r .id)
curl -s --unix-socket "$s" -X POST "http://aide/notes/$id/append" \
    -H 'Content-Type: application/json' \
    -d '{"text": "- read the 1.31 changelog", "heading": "Reading", "createHeading": true}' | jq .appended
```

Replace a body only if nobody changed it since you read it:

```sh
note=$(curl -s --unix-socket "$s" "http://aide/notes/$id")
version=$(echo "$note" | jq .version)
body=$(echo "$note" | jq -r .body | sed 's/TODO/DONE/')
jq -n --argjson v "$version" --arg b "$body" '{version: $v, body: $b}' |
    curl -s --unix-socket "$s" -X PUT "http://aide/notes/$id" -H 'Content-Type: application/json' -d @-
```

Check off the first open todo in a note:

```sh
curl -s --unix-socket "$s" http://aide/todos |
    jq -r --arg id "$id" '[.todos[] | select(.noteId == $id)][0] | "\(.line) \(.version)"' |
    while read -r line version; do
        curl -s --unix-socket "$s" -X POST "http://aide/notes/$id/todos/$line/toggle" \
            -H 'Content-Type: application/json' -d "{\"version\": $version}"
    done
```

Search:

```sh
curl -s --unix-socket "$s" "http://aide/search?q=postgres&limit=5" | jq -r '.notes[] | "\(.path)\t\(.title)"'
```

<Aside title="No app open?">
When no app has the vault open, there is no socket. `aidectl` then opens the folder itself for one command, with the same rules and answers, so scripts that use `aidectl` work either way. If the app has the vault open but no socket answers, update or restart the app.
</Aside>

## Terminal socket

AIDE's terminal is served on one more socket, so programs can read and type into its panes and open, split and close its tabs. It speaks the same protocol as copad's terminal socket, not HTTP, so copad's `coctl` and comux's notification click work against AIDE. [`aidectl terminal`](/docs/developers/aidectl/#terminal) is built on it. The Mac App Store build and the iPhone don't have it.

### Where it is

The terminal server, which runs your shells and outlives the app (see [Shells that outlive AIDE](/docs/guides/terminal/#shells-that-outlive-aide)), serves it as `terminal.sock` in its own folder:

- On the Mac: `~/Library/Application Support/AIDE/mux/terminal.sock`.
- On Linux: `$XDG_RUNTIME_DIR/aide-mux/terminal.sock`, or `/tmp/aide-mux-<uid>/terminal.sock` without `XDG_RUNTIME_DIR`.
- The folder is yours alone (mode `0700`), the socket has mode `0600`, and only your user can connect.

Every pane's shell gets `COPAD_SOCKET` and `AIDE_TERMINAL_SOCKET`, the path of this socket, and `COPAD_PANEL_ID` and `AIDE_MUX_PANE`, the pane's id.

Reading and typing work with no AIDE window open. What only a window can do (`panel.focus`, `tab.switch`, `tab.new`) goes to the AIDE window that was in front last among those showing the pane's vault; with no such window it answers `no_window`. <Badge text="Next release" /> A pane in a [space](/docs/guides/terminal/#spaces) no window shows goes to the window in front, which switches to that space; `no_window` only when no window can. A request without a pane means the focused pane of the window in front; with no window, of the first vault with a tab.

### Requests and answers

One JSON request per line, answered on the same connection, one JSON answer per line. A connection can send several requests.

```json
{"id": "1", "method": "terminal.read", "params": {"id": "…"}}
{"id": "1", "ok": true, "result": {"text": "…"}}
{"id": "1", "ok": false, "error": {"code": "not_found", "message": "…"}}
```

### Methods

In `params`, `id` (or `panel_id`) is a **pane** id and defaults to the focused pane, in the window that was in front last. Only the `tab.*` methods take tab ids.

| Method | Params | What it does |
| --- | --- | --- |
| `system.ping` | | Answers, to check the socket: `{status, app: "aide", server: "aide-mux", pid}`. <Badge text="Next release" /> Also `features`, what the socket does beyond these methods (`space-panes`, `space-notes`, `tab-in-space`): ask before you rely on a param an older server would ignore |
| `panel.focus` | `panel_id` | Selects the pane and its tab, shows the Terminal section and brings the window forward; answers `{focused, raised}`. A pane the server doesn't have answers `focused: false`, not an error. Linux always answers `raised: false` |
| `terminal.read` | `id`, `start_row`, `start_col`, `end_row`, `end_col` | The live screen as text, or part of it: both ends included, an end past the screen clamped |
| `terminal.state` | `id` | Size, cursor, folder, title, and whether its shell has exited |
| `terminal.exec` | `id`, `command` | Types `command` and a newline. It doesn't wait for the command |
| `terminal.feed` | `id`, `text` | Types `text` as it is |
| `terminal.history` | `id`, `lines` | The last `lines` rows above the screen (at most 10 000), then the screen |
| `terminal.context` | `id`, `history_lines` | State, screen and the rows above it |
| `tab.new` | <Badge text="Next release" /> `space`, `cwd`, `pane`, `show` | Opens a tab; answers its pane's id. <Badge text="Next release" /> With `space` or `cwd` the server opens it itself, with no window needed: in `space` (else `pane`'s space), in `cwd` (an existing folder's absolute path, else the space's folder), answering `{session, tab, pane, panel_id}`. A window showing that space stays on its tab unless `show: true` |
| `tab.close` | `id` | With a tab id, closes that tab and every pane in it; without one, closes the focused pane |
| `tab.list`, `tab.info` | | `{count, current, tabs: [{id, index, title, selected, panes: [{id, title, focused, exited, cols, rows}]}]}`: the tabs of the windows in front-to-back order; with no window, every vault's tabs, and `current` is null |
| `tab.rename` | `id`, `title` | Names a tab |
| `tab.switch` | `index` | Selects the tab at that index of `tab.list` (from 0); answers `{tab}`. No tab there is `not_found`, an index that isn't a whole number is `invalid_params` |
| `split.horizontal` | `id` | Splits the pane to the right; answers `{panel_id}` of the new pane |
| `split.vertical` | `id` | Splits the pane downward; answers `{panel_id}` |
| `pane.focus_next`, `pane.focus_prev` | | Focuses the next or previous pane |
| `agent.list` | | The [coding agents](/docs/guides/terminal/#coding-agents) in the server's panes: `{agents: [{pane, tab, session, agent}]}`, each `agent` with its `kind`, `state`, `unseen`, `wait`, `detail` and `context`. <Badge text="Next release" /> A pane linked to a board card also has `link {vault, card, gen, finished, at}`. <Badge text="Next release" /> Each entry also has `checkout`, the git checkout the pane works in (agents with the same one edit the same files), and each `agent` has `changed`, when its state last changed in Unix milliseconds |
| `agent.card` <Badge text="Next release" /> | `pane`, `vault`, `card` | From inside the pane only: links the pane to a [board card](/docs/guides/terminal/#cards-linked-to-panes), or unlinks it with `card: null`. What `aidectl board add` and `link` call |
| `agent.notify` | `pane`, `kind`, `body` | From inside the pane only: its agent finished (`kind: "done"`) or needs you (`"blocked"`), with `body` (at most 1 KiB) as the notification's text. What the hooks call |
| `agent.report` | `pane`, `session_id`, `window`, `used`, `cost_usd`, `duration_ms` | From inside the pane only: Claude Code's context and cost, from its status line. Taken only while the pane's agent is Claude Code in that conversation |
| `conversation.list` <Badge text="Next release" /> | `dir`, `all`, `query`, `after`, `limit`, `rescan` | Past Claude Code, Codex and Grok conversations, newest first: `{items: [{tool, id, title, cwd, mtime, age, interactive, open, starting, card, relink}], more, truncated}`. `dir` keeps those in that folder or under it, `query` those whose prompt, folder or id hold its characters in order; `after` is the last item of the page before (`{mtime, tool, id}`), `limit` 1–1000 (200). `open` is the pane that has it (`{session, tab, pane}`), `truncated` says there were too many to read them all |
| `conversation.resume` <Badge text="Next release" /> | `conversation`, `tool`, `pane`, `focus` | Opens the conversation in a new tab, in the space working in its folder, else in `pane`'s session (the focused pane's without one): `{session, tab, pane, moved, shown}`, or `{open: {session, tab, pane}}` when a pane has it. `focus: true` shows the new tab, or the pane that has it, in its window |
| `conversation.fork` <Badge text="Next release" /> | `pane` or `conversation`, `tool`, `focus` | A new conversation from the agent in `pane` (the focused one without either), or from a past `conversation`, in a new tab; `unlinked` names the board card the fork isn't linked to |
| `space.list` <Badge text="Next release" /> | | Every space: `{spaces: [{id, name, kind, dir, branch, vault, project, created, dormant, windows, tabs, programs, agents, panes}]}`, those running first. `windows` is how many windows show it, `programs` what runs in front of its shells, `agents` a count for each state, `panes` its panes (`{id, tab, title, cwd, focused, exited}`, none for a space that isn't running) |
| `space.new` <Badge text="Next release" /> | `dir`, `name`, `project`, `pane`, `notes`, `vault`, `show` | Makes a space working in `dir` (an existing folder's absolute path): `{session, tab, pane}`, its first tab and pane. It belongs to `pane`'s vault, to none without `pane`, and when the caller runs inside `pane` it uses that pane's notes, so `aidectl` works in it before any window shows it. `notes` (a folder vault's absolute path) with `vault` (that vault's id) names its notes instead. With `show: true` a window shows it, and `shown` (with `show_error` when it couldn't) says whether one did; the space is made either way |
| `space.show` <Badge text="Next release" /> | `session`, `pane` | Shows the space, and the pane when given, in a window: the one showing it, else the window in front switches to it, and brings that window forward: `{shown, raised}`. `raised: false` means the window switched but stayed behind, as a Mac window behind another app does until you switch to AIDE; Linux always answers `raised: false`. A pane that isn't in that space is `not_found` |
| `space.rename` <Badge text="Next release" /> | `session`, `name` | Names a space |
| `space.end` <Badge text="Next release" /> | `session`, `force` | Ends a space and its shells. While a program runs in one, it answers `busy` naming the programs, unless `force: true` |
| `agent.fill` | `pane`, `session_id` | From inside the pane only: `{used, window}` for that Claude Code conversation, both null when AIDE isn't sure. What the auto-compaction gate asks |
| `usage.get` <Badge text="Next release" /> | `refresh` | Your Claude and Codex plan limits, as the [status bar](/docs/guides/terminal/#the-status-bar-) shows them: `{usage, refreshing}`, where `usage` is `{claude?: {five_hour?, seven_day?, stale?}, codex?: {five_hour?, weekly?, stale?}, at, problems: [{provider, text}]}`, each limit `{used, resets_at?}` with `used` a percentage and `resets_at` in Unix seconds, and `at` in Unix milliseconds. A provider is missing while it's turned off or nothing of it was read in the last 3 hours; `stale: true` is the last good value, kept because the last read failed, with the reason in `problems`. The server reads every 60 s while an app is connected; `refresh: true` asks for a new reading now, and `refreshing: true` says this request started one; ask again for the new value. `usage` is null before the first reading. What `aidectl agent usage` calls |

Reading doesn't move the pane's scroll position.

### Errors

| `code` | When |
| --- | --- |
| `parse_error` | The line isn't JSON |
| `invalid_request` | Not a JSON object, or no string `id`, no `method`, or `params` isn't an object |
| `invalid_params` | A param is missing or wrong (a read range that makes no sense, say) |
| `unknown_method` | No method by that name |
| `not_found` | No pane or tab with that id (one closed meanwhile, say) |
| `no_terminal` | No terminal is open (no window, or no tab) |
| `exited` | `terminal.exec` or `terminal.feed` on a pane whose shell has ended; it can still be read |
| `too_small` | The pane is too small to split |
| `busy` | 16 clients are already connected, or `terminal.exec` or `terminal.feed` on a pane whose program isn't reading what it's sent, or (<Badge text="Next release" />) `space.end` while a program runs there |
| `no_window` | `panel.focus`, `tab.switch` or `tab.new` with no AIDE window showing that pane's vault (<Badge text="Next release" /> or, for a space no window shows, no window that could switch to it) |
| `not_in_pane` | An `agent.notify`, `agent.report` or `agent.fill` from a program that isn't running in that pane |
| `no_agent` | No agent in that pane |
| `unknown_conversation` <Badge text="Next release" /> | No conversation with that id, or the pane's agent's conversation isn't known yet |
| `lookup_incomplete` <Badge text="Next release" /> | There were too many conversations to look through for that id; try again |
| `frame_too_large` | The request line is longer than 64 KiB |

### Terminal socket limits

- A request line up to 64 KiB, 16 clients at once.
- 10 seconds to send a line and 10 seconds to take its answer; a client that stalls is dropped.

With `$t` the socket (from `$COPAD_SOCKET` in a pane, or the folder above):

```sh
printf '%s\n' '{"id": "1", "method": "tab.list"}' | nc -U "$t"
```
