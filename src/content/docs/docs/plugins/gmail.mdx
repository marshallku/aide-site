The Gmail plugin reads your mail so you don't have to check it all day. At 18:00 it writes what needs
a reply and what you're waiting on into your day note, and it pushes the mail your AI finds urgent.
It can only read: it never sends, labels, archives or deletes anything.

<PluginFacts id="gmail" />

## What it does

**Every 5 minutes** it asks Gmail which threads changed. It reads only headers and keeps only thread
ids.

**At 18:00** it writes a **📬 Mail** section into the day note (`briefings/<date>` unless you
choose another note):

- **Needs a reply**: inbox mail from the last 7 days that asks something of you. The plugin takes the
  latest message of at most 30 threads, leaves out newsletters and Gmail's Promotions, Social,
  Updates and Forums categories, cuts each to 2 KB of text and gives them to your AI to sort. Each
  line links to the thread in Gmail. Without an AI (or when it fails), every candidate is listed
  under **Mail to check** (selected without AI) instead.
- **Waiting for a reply**: threads where you wrote last, more than 3 days ago (and at most 30), and
  someone besides you was on it. Notes to yourself are left out.
- A count: how many messages came today, and how many were newsletters and notifications.

The section is the plugin's own: it rewrites it each day and leaves the rest of the note alone.
Link the day note from your daily template to see it from your daily note, or set **Write into** to
`daily` to put the section in the daily note itself ([Daily notes and
templates](/docs/guides/periodic-notes/)).

**Urgent mail.** When the AI marks a message urgent, the plugin pushes it once to your devices, titled
`📬 <subject>`, with who sent it and why it's urgent, linking to the thread. Turn off **Push urgent
mail** to stop that.

**A broken token** is said once a day: a pushed **Reconnect Gmail** item.

If the computer was asleep at 18:00, the day's section is written when it wakes, if that's within 6
hours.

## Before you start

- **A server or desktop host running the server plugins**, on a computer where you can open a
  browser. On a desktop host that's the computer AIDE hosts the vault on
  ([Host on your desktop](/docs/self-hosting/desktop-host/)).
- **Your own Google OAuth client.** AIDE doesn't ship one: you create one in Google Cloud, which is
  free, and the plugin talks to Gmail with it. The steps are below.
- **An AI** for sorting the mail ([AI and models](/docs/guides/ai/)). Without one, the plugin still
  lists the mail, unsorted.

## Set it up

### 1. Create the Google OAuth client

<Steps>

1. Open the [Google Cloud console](https://console.cloud.google.com/) and create a project (any name,
   for example `AIDE`).
2. In **APIs & Services › Library**, find **Gmail API** and choose **Enable**.
3. Set up the consent screen (**APIs & Services › OAuth consent screen**, called **Google Auth
   Platform** in newer consoles): an app name, your email as the support and contact address, and
   **External** as the user type.
4. Under **Audience** (or on the consent screen's summary), choose **Publish app** so its status is
   **In production**. Left in **Testing**, Google expires your sign-in every 7 days.
5. Create the client: **APIs & Services › Credentials › Create credentials › OAuth client ID** (or
   **Clients › Create client**). Choose **Desktop app** as the application type, then **Create**.
6. Choose **Download JSON**. Save the file as `~/.config/life-assistant/credentials.json`, the path the
   plugin reads by default:

   ```sh
   mkdir -p ~/.config/life-assistant
   mv ~/Downloads/client_secret_*.json ~/.config/life-assistant/credentials.json
   ```

</Steps>

### 2. Sign in with Google

Run `aide-plugins google-auth gmail` on the computer that runs the plugins. It opens Google's consent
page in your browser and waits up to 10 minutes. Sign in, allow read access to your mail, and the
token is saved to `~/.config/aide-plugins/gmail-token.json`.

`aide-plugins` comes with AIDE's desktop host:

<Tabs syncKey="os">
<TabItem label="macOS">

It's inside the app. With AIDE in `~/Applications` (where the install script puts it):

```sh
~/Applications/AIDE.app/Contents/MacOS/aide-plugins google-auth gmail
```

If you moved AIDE to `/Applications`, use `/Applications/AIDE.app/Contents/MacOS/aide-plugins`.

</TabItem>
<TabItem label="Linux">

It's in the host runtime folder, one per AIDE version:

```sh
ls ~/.local/lib/aide/
~/.local/lib/aide/host-0.4.16/aide-plugins google-auth gmail
```

Use the `host-<version>` folder of the AIDE you have installed.

</TabItem>
</Tabs>

Because your client isn't verified by Google, the consent page warns that Google hasn't verified the
app. It's your own client: choose **Advanced** and continue. The command prints `Saved the token to …
Turn the plugin on in AIDE.` when it's done.

`-credentials <file>` and `-token <file>` choose other paths for the command. The plugin itself reads
the default paths, so keep the files there unless you also set them in the host's local plugin
settings ([Host on your desktop](/docs/self-hosting/desktop-host/)).

### 3. Turn it on

<Steps>

1. In AIDE, open **Settings** and choose **Gmail** under **On the server** (on Linux, **Settings ›
   Plugins › Gmail**).
2. Turn on **Enabled**. The plugin starts within a minute.

</Steps>

The first section arrives at 18:00. Until then the plugin follows your threads every 5 minutes.

## Settings

<PluginSettings
    id="gmail"
    defaults={{ at: "18:00", note: "briefings/{date}", followUpDays: "3", urgent: "On" }}
/>

- **Write into** takes a note path with `{date}` (`briefings/{date}`, `mail/{date}`…) or `daily` for
  the daily note.
- **Waiting for an answer after (days)**: a thread you wrote last is listed once it has waited this
  long, until it is 30 days old.

## Troubleshooting

### Nothing arrived at 18:00

- Check the plugin is **Enabled**, and that the host was running at 18:00 or woke within 6 hours.
- Check both files exist: `~/.config/life-assistant/credentials.json` and
  `~/.config/aide-plugins/gmail-token.json`. Without them the plugin can't start.

### Reconnect Gmail

The token stopped working: you removed AIDE's access, changed your Google password, or the consent
screen was in **Testing** and the 7 days ran out. Publish the consent screen (**In production**) and
run `aide-plugins google-auth gmail` again.

### google: no refresh token came back

Google gave out a token before and won't give a lasting one again. Remove the app's access at
[myaccount.google.com/permissions](https://myaccount.google.com/permissions), then run the command
again.

### google: no answer from the browser

The consent page wasn't finished within 10 minutes. Run the command again. It must run on the
computer whose browser you sign in with: Google sends you back to an address on that computer.

### Everything is under Mail to check

The AI wasn't available or its answer couldn't be used, so the plugin listed every candidate. Check
[AI and models](/docs/guides/ai/).

## Privacy

- The plugin asks Google only for `gmail.readonly`. It can't send or change mail.
- Your OAuth client and token stay in files on the computer that runs the plugins. A refreshed token
  is kept in the plugin's own state there.
- It stores thread ids, not mail. The mail itself is read from Gmail each time.
- For sorting, up to 30 messages a day (sender, subject and at most 2 KB of text each) go to the AI you
  set up. The mail is given to it as data, not as instructions.
- The **📬 Mail** section (subjects, senders, why each needs a reply) is a note, synced to your
  devices. Urgent mail's subject and reason go out as a push notification.
