Git은 git 저장소인 보관소를 커밋된 상태로, 원격과 맞춰 둬서 노트가 커밋하지 않은 변경으로 쌓이지 않게 해요. Mac과 Linux의 AIDE에 들어 있고, 그 컴퓨터에서 로컬 모드로 연 보관소에서 동작해요.

## 하는 일

AIDE에서 보관소를 열어 둔 동안, 보관소를 열 때 한 번, 그 뒤로 몇 분마다(기본 10분) 실행돼요. 한 번 실행하면:

1. 보관소의 모든 변경(새 파일, 바뀐 파일, 옮긴 파일, 지운 파일)을 커밋 메시지로 커밋해요. 바꾸지 않았다면 `vault backup: {{date}}`예요. 이 기기용 AIDE 파일은 빼요(아래 참고).
2. **pull과 push**가 켜져 있고 업스트림 브랜치가 있으면 원격을 가져와요. 원격에 새 커밋이 있으면 병합해요. 내 커밋이 없으면 fast-forward로, 있으면 병합 커밋 `Merge origin/main into main`으로요. 그런 다음 내 커밋을 업스트림 브랜치에 push해요.

리베이스, reset, stash, 강제 push, 커밋 고쳐 쓰기는 하지 않아요. 직접 봐야 할 일이 생기면 아무것도 건드리기 전에 멈추고, Git 페이지에 이유를 보여 줘요.

- 내 변경과 원격의 변경이 같은 줄을 바꿨을 때(파일을 알려 줘요. 터미널에서 해결해 주세요)
- 다른 git 명령이 실행 중일 때(다음 실행에서 다시 시도해요)
- 병합이나 리베이스가 진행 중이거나 충돌한 파일이 있을 때
- 저장소가 브랜치 위에 있지 않을 때
- 원격이 추가한 파일이 이 컴퓨터에 추적되지 않거나 무시된 파일로 이미 있을 때

Git 페이지의 **지금 커밋하고 동기화**는 자동 커밋이 꺼져 있어도 바로 실행해요. 명령 팔레트에도 **git으로 커밋하고 동기화**가 있어요. 자동 실행이 직접 봐야 할 일을 만나면 패널 아래쪽의 보관소 이름 옆에 경고가 떠요. 그 메뉴 맨 위에 이유가 있고, 누르면 Git 페이지가 열려요.

git이 가져온 변경은 AIDE 밖에서 고친 변경처럼 노트에 반영돼요. git은 커밋 뒤에 바뀐 파일 위로 fast-forward하지 않으니, 실행 중에 고친 내용은 다음 실행을 기다려요.

## 시작하기 전에

- 보관소 폴더가 git 저장소 자체 폴더(`.git`이 있는 곳)여야 해요. 더 큰 저장소 안에 있는 보관소는 커밋하지 않으니, 보관소 밖의 파일은 절대 커밋하거나 push하지 않아요.
- git이 설치돼 있어야 해요. Mac에서는 Homebrew의 git이나 Xcode 명령줄 도구요.
- pull과 push를 하려면 브랜치에 업스트림이 있어야 해요. 터미널에서 한 번 `git push -u origin main`(원격과 브랜치에 맞게)을 실행해 주세요.
- AIDE는 터미널처럼 로그인 셸의 환경으로 git을 실행해서, 자격 증명 도우미, SSH 키, git 설정이 그대로 적용돼요. 비밀번호는 묻지 않아요. 비밀번호가 필요한 원격은 실패하고, Git 페이지에 git의 메시지가 보여요.

## 설정하기

<Steps>

1. **설정 › 코어 플러그인**을 열고 **Git**을 골라요. Linux에서는 **코어 플러그인** 페이지 맨 위에 있어요.
2. 페이지 위쪽을 확인해요. 브랜치와 업스트림, 커밋하지 않은 변경 수, 마지막 커밋이 보여요.
3. **변경 사항 자동 커밋**을 켜고, **커밋 간격**에서 5, 10, 30, 60분 중에 골라요.
4. 원격과 동기화하려면 **pull과 push**를 켜 둬요. 커밋만 하려면 꺼요.

</Steps>

이 설정은 이 컴퓨터에 이 보관소용으로 저장돼요. 같은 저장소를 clone해서 여는 다른 컴퓨터는 따로 설정해요.

## 설정

| 설정             | 기본값                   | 하는 일                                                                                          |
| ---------------- | ------------------------ | ------------------------------------------------------------------------------------------------ |
| 변경 사항 자동 커밋 | 꺼짐                     | 보관소를 열 때, 그리고 AIDE가 열려 있는 동안 몇 분마다 커밋해요                                  |
| 커밋 간격        | 10분                     | 5, 10, 30, 60분. 마지막 실행이 시작된 때부터 세요                                                 |
| pull과 push      | 켜짐                     | 커밋한 뒤 브랜치의 업스트림을 가져와 병합하고 push해요                                           |
| 커밋 메시지      | `vault backup: {{date}}` | `{{date}}`는 시각(`2026-11-03 14:05`), `{{files}}`는 커밋에 담긴 파일 수예요. 첫 줄만, 200자까지 써요. 비우면 기본값이에요 |

## AIDE의 기기용 파일

AIDE는 보관소의 `.aide/` 아래에 자기 파일을 둬요. 노트 색인, 버전, 지운 노트 보관함, 끝나지 않은 작업, 두 번째 AIDE가 열지 못하게 하는 잠금 파일이에요. 이 파일들은 이 컴퓨터의 것이고, 편집할 때마다 바뀌고, 컴퓨터끼리 충돌해서 Git은 커밋하지 않아요. `.aide/settings.json`(노트에서 뺀 항목 같은 보관소 자체 설정)만 보관소와 함께 커밋해요.

저장소가 이미 그 파일 일부를 추적하고 있으면 Git 페이지가 알려 줘요. **추적 멈추기**는 그 파일들을 저장소에서 빼고(파일은 디스크에 그대로 있어요), `.gitignore`에 `.aide/*`와 `!.aide/settings.json`을 추가한 뒤 커밋해요. 스테이징된 변경이 있으면 아무것도 하지 않아요. 다른 컴퓨터가 먼저 추적을 멈췄다면, 여기서 실행할 때 병합하기 전에 같은 일을 해서 어느 쪽도 파일을 잃지 않아요.

<Aside>
지운 노트는 이 컴퓨터의 `.aide/archive/`에 남는데, Git은 그곳을 커밋하지 않아요. 저장소에는 지우기 전 마지막 커밋 때의 노트가 남아 있어요.
</Aside>

## 문제 해결

### 보관소가 git 저장소가 아니라고 해요

보관소 폴더에 `.git`이 없어요. 터미널에서 그 폴더에 `git init`을 실행하고(원격도 추가하고), Git 페이지를 다시 열어 주세요.

### 보관소가 다른 저장소 안에 있다고 해요

저장소 폴더가 보관소 폴더보다 위에 있어요. 저장소 폴더를 보관소로 열거나, 보관소를 따로 저장소로 만들어 주세요.

### 병합하지 못했다고 해요

내 커밋과 원격의 커밋이 알려 준 파일의 같은 줄을 바꿨어요. 아무것도 병합하거나 push하지 않았고, 내 커밋은 그대로 있으며 다음 실행도 계속 커밋해요. 보관소 폴더에서 `git pull`을 실행해 충돌을 해결하고 커밋하면 다음 실행이 push해요.

### 원격이 AIDE의 기기용 파일을 바꾼다고 해요

다른 컴퓨터가 자기 `.aide/` 파일을 커밋하고 있어요. 그 컴퓨터의 Git 페이지에서 **추적 멈추기**를 골라 주세요.

### 다른 git 명령이 오래 실행 중이라고 해요

git은 작업하는 동안 `.git/index.lock`을 남겨요. 10분이 지나면 멈춘 git이 남긴 파일일 수 있다고 알려 줘요. 실행 중인 git이 없다면 그 파일을 지워 주세요. AIDE는 지우지 않아요.

## 쓸 수 있는 곳

Mac(aide.marshallku.dev에서 받은 빌드)과 Linux예요. iPhone에서는 안 돼요. iPhone 앱은 git을 실행하거나 백그라운드에서 계속 돌 수 없어요. Mac App Store 빌드에서도 안 돼요. 샌드박스 때문에 SSH 키, git 설정, 자격 증명 도우미에 닿을 수 없어요.

## 개인정보

Git은 저장소에 적힌 원격하고만, 터미널의 git처럼 내 자격 증명으로 통신해요. AIDE는 설정과 마지막 실행 결과를 이 컴퓨터에만 저장해요.
