문서 동기화는 노트를 git 저장소로 복사하고, 저장소에서 고친 내용을 다시 가져와요. 그래서 GitHub나 다른 git 서버에 일반 Markdown 사본을 두고, 어떤 편집기나 스크립트로든 고칠 수 있어요.

<PluginFacts id="docs-sync" />

## 하는 일

플러그인은 플러그인을 실행하는 컴퓨터에 저장소의 자체 클론을 둬요. 매분, 그리고 노트를 바꾸고 5초 뒤에 다음을 해요.

1. 브랜치를 가져와서 클론을 그 상태로 되돌려요. 그래서 항상 원격 저장소의 내용에서 시작해요.
2. 각 파일을 해당 노트와 비교해요. 둘이 마지막으로 같았던 커밋을 기준으로 삼아요.
3. 결과를 양쪽에 써요. 바뀐 노트는 파일로, 바뀐 파일은 노트로 써요.
4. 바꾼 파일을 `journal: aide sync (N files)`로 커밋하고 푸시해요.

다음 최상위 폴더 아래의 노트를 저장소의 같은 경로에 `.md` 파일로 동기화해요: `daily`, `weekly`, `monthly`, `topics`, `brainstorm`, `missions`, `templates`. 다른 노트는 저장소에 들어가지 않아요.

<Badge text="다음 릴리스" /> 한 번도 실행된 적 없는 새 동기화는 대신 `daily`, `weekly`, `monthly`, `quarterly`, `yearly`, `topics`, `templates`를 동기화하고, 원격 저장소의 기본 브랜치를 따라요. 이전에 실행된 동기화는 위의 폴더와 `master` 브랜치를 그대로 써서, 이미 동기화하던 것이 빠지지 않아요. 아래의 `prefixes`와 `branch`로 직접 정할 수도 있어요.

**양쪽이 모두 바뀌었을 때.** 노트의 서로 다른 부분을 고쳤다면 `git merge`처럼 합쳐요. 같은 줄을 양쪽에서 고쳤다면 AIDE 쪽이 이기고, 파일 쪽 버전은 `conflicts/` 아래에 별도 노트로 보관되며, 피드 이벤트가 그 노트를 알려 줘요. 같은 날의 데일리 노트가 양쪽에서 따로 만들어졌다면(하나는 AIDE에서, 하나는 저장소에서) 하나로 합쳐요. 섹션마다 AIDE의 글을 먼저 두고, 그 뒤에 파일에만 있는 내용을 붙여요. 양쪽에 같은 할 일이 있으면 하나만 남기고, 어느 한쪽에서라도 완료했다면 완료로 표시해요.

**새 노트와 지운 노트.** AIDE에서 만든 노트는 파일이 되고, 저장소에 추가한 파일은 노트가 돼요. 저장소에서 파일을 지우면 해당 노트가 보관되고, **최근 삭제된 항목**에서 되살릴 수 있어요. AIDE에서 지운 노트는 저장소에서도 지워져요. 마지막 동기화 뒤에 반대쪽에서 고친 내용이 있으면, 삭제보다 수정이 이겨요.

**안전장치.**

- 한 번의 동기화에서 20개 넘게 지우거나 보관하려 하면 동기화를 멈추고 피드에 이벤트를 올려요. 보통 잘못된 브랜치나 대량 변경 때문이에요. 이벤트는 "한 번에 20개 넘게 …하려 해서 동기화를 멈췄어요. 확인이 필요해요."라고 알려 줘요. 원인이 사라질 때까지 아무것도 바꾸지 않아요.
- 심볼릭 링크는 따라가지 않고, 1 MiB가 넘는 파일은 제외해요. 각각 피드에 알리고 그대로 두며, 삭제된 것으로 취급하지 않아요.

### 내보내기 전용

**동기화 방향**을 `export`(**내보내기 전용**)로 정하면 AIDE만 파일을 써요. 저장소에서는 아무것도 가져오지 않아요. 누군가 저장소에서 고친 파일은 `conflicts/` 아래에 노트로 보관한 뒤 AIDE 쪽 버전으로 덮어써요. `export`로 바꾸면 그 전에 양방향 동기화를 한 번 더 실행해서, 바꾸기 전에 고친 내용을 잃지 않아요. 내보내기 전용 모드에서도 한 번에 20개 넘는 파일을 교체하려 하면 동기화를 멈춰요.

<Badge text="다음 릴리스" /> 그 `conflicts/` 노트 맨 위에 저장소에서 고친 파일을 바꿨다고 알리는 줄은 플러그인이 쓰는 언어로 쓰여요.

## 시작하기 전에

- [데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)나 직접 운영하는 서버가 필요해요.
- 플러그인을 실행하는 컴퓨터에 `git`이 설치돼 있어야 해요.
- git 저장소와, 미리 만들어 둔 브랜치가 필요해요(플러그인은 그 브랜치를 클론할 뿐 만들지 않아요). <Badge text="다음 릴리스" /> `branch` 없이 새로 시작하는 동기화는 원격 저장소의 `HEAD`가 가리키는 브랜치를 써요(빈 저장소라면 `main`). 처음 시작할 때 원격 저장소에 닿지 못하면(네트워크가 없거나 SSH 키가 아직 로드되지 않았을 때) 브랜치를 짐작하지 않아요. 상태에 "아직 저장소에 연결할 수 없어요. 1분 뒤에 다시 시도해요."라고 나오고 1분마다 다시 시도해요. 처음 고른 폴더와 브랜치는 그 뒤로 계속 써요.
- 입력 창 없이 접근할 수 있어야 해요. 플러그인은 내 계정과 git 자격 증명(에이전트에 등록한 SSH 키, 또는 HTTPS용 자격 증명 도우미)으로 `git`을 실행하고, 비밀번호를 묻지 않아요. 비밀번호가 필요한 원격 저장소는 실패해요.

## 설정하기

<Steps>

1. 호스트 데이터 폴더의 `plugins.json`에 저장소를 추가해요([폴더 위치](/ko/docs/plugins/overview/#로컬-설정)).

    ```json
    {
        "plugins": {
            "docs-sync": {
                "remote": "git@github.com:you/notes.git",
                "branch": "main"
            }
        }
    }
    ```

2. 호스트가 파일을 읽도록 다시 시작해요. AIDE를 종료했다가 다시 열어요(**로그인한 동안 계속 실행**이 켜져 있다면 껐다가 다시 켜요). <Badge text="다음 릴리스" /> 다시 시작하지 않아도 돼요. 호스트가 1분쯤 안에 바뀐 내용을 읽어요.
3. 플러그인을 켜요. **설정 › 코어 플러그인**에서 **문서 동기화**를 고르고 **활성화됨**을 켜요(Linux에서는 설정의 **코어 플러그인** 페이지에서 해당 행의 스위치). [플러그인 켜기](/ko/docs/plugins/overview/#플러그인-켜기)를 참고하세요.
4. 1분 안에 플러그인이 저장소를 클론하고 첫 동기화를 해요. 양쪽에 같은 경로로 있는 노트는 짝지어 합치고, 나머지는 반대쪽에 만들어요.

</Steps>

<Aside type="tip">
첫 동기화는 빈 저장소나 같은 노트의 사본이 있는 저장소로 하세요. 첫 동기화는 경로로 파일과 노트를 짝짓고, 한쪽에만 있는 것은 모두 반대쪽에 추가해요.
</Aside>

## 설정

<PluginSettings id="docs-sync" defaults={{ paused: "끔", interval: "1분", mode: "양방향" }} />

**일시 정지**는 모든 작업을 멈춰요. 읽지도, 쓰지도, 푸시하지도 않아요. 데일리 노트 형식을 바꾸는 것처럼 많은 노트를 새 경로로 옮기기 전에 켜 두세요. 그래야 옮기는 도중에 옛 파일이 지워진 것처럼 보이지 않아요. 다 옮긴 뒤에 다시 꺼요.

**동기화 방향**은 **양방향**(위에서 설명한 방식)과 `export`(**내보내기 전용**) 중에서 골라요.

### 로컬 키

`plugins.json`의 `"docs-sync"` 아래에 적어요.

| 키         | 하는 일                                                                                          | 기본값 |
| ---------- | ------------------------------------------------------------------------------------------------ | ------- |
| `remote`   | 클론하고 푸시할 저장소. 필수예요. 없으면 플러그인이 시작되지 않아요.                             | 없음 |
| `branch`   | 동기화할 브랜치.                                                                                 | `master`. <Badge text="다음 릴리스" /> 새 동기화는 원격 저장소의 기본 브랜치 |
| `prefixes` | 동기화할 최상위 폴더 목록. 기본 목록을 대신해요.                                                 | `["daily", "weekly", "monthly", "topics", "brainstorm", "missions", "templates"]`. <Badge text="다음 릴리스" /> 새 동기화는 `["daily", "weekly", "monthly", "quarterly", "yearly", "topics", "templates"]` |
| `clone`    | 플러그인이 클론을 두는 곳.                                                                       | 호스트 데이터 폴더의 `plugins/docs-sync/clone` |
| `author`   | 커밋 작성자 이름.                                                                                | `aide docs-sync` |
| `email`    | 커밋 작성자 이메일.                                                                              | `aide@localhost` |

클론은 플러그인 전용이에요. 동기화할 때마다 원격 저장소 상태로 되돌리기 때문에, 거기서 파일을 고치지 마세요. 따로 클론해서 고친 뒤 푸시하세요.

## 문제 해결

### 아무것도 동기화되지 않아요

호스트 로그(경로는 설정 › 호스트의 **로그**에 있어요)를 확인하세요. `remote`가 없으면 플러그인은 `docs-sync: remote is required`와 함께 바로 멈춰요. <Badge text="다음 릴리스" /> 대신 앱의 플러그인 설정 아래에 "플러그인 설정 파일에 동기화할 저장소(remote)를 적어 주세요"라고 보여 주고 기다려요. `git clone`, `fetch`, `push`가 실패하면 git의 메시지가 그대로 나와요. 보통 없는 브랜치이거나, 입력 창이 필요한 자격 증명 때문이에요.

### 피드에 "동기화를 멈췄어요"라는 이벤트가 있어요

한 번에 20개 넘는 노트나 파일을 지우거나, 보관하거나, 교체하려 했어요. `remote`와 `branch`가 의도한 곳을 가리키는지, 누군가 저장소에서 폴더를 지웠는지 확인하세요. 남은 작업이 21개보다 적어지면 다음 동기화가 진행돼요.

### conflicts/ 아래에 노트가 생겼어요

두 번의 동기화 사이에 AIDE와 저장소에서 같은 줄을 고쳤어요. AIDE 쪽 버전은 원래 노트에 있고, 파일 쪽 버전은 이벤트가 알려 준 `conflicts/` 노트에 있어요. 필요한 부분을 복사한 뒤 그 노트를 지우세요. `conflicts/` 아래의 노트는 동기화하지 않아요.

### 파일이 건너뛰어졌어요

심볼릭 링크이거나 1 MiB보다 큰 파일이에요. 동기화하려면 1 MiB 미만의 일반 파일로 바꾸세요.

## 개인정보

동기화하는 폴더 아래의 노트는 내 자격 증명으로, git 자체 전송 방식을 통해 설정한 git 원격 저장소로 전달돼요. 그 밖에는 컴퓨터 밖으로 나가는 것이 없어요. 이 플러그인은 AI를 쓰지 않아요.
