지난 작업 정리는 코딩 작업에 대한 노트를 대신 써 줘요. 23:59에 내 컴퓨터의 Claude Code나 Codex가 그날의 세션과
저장소의 git 기록을 살펴보고, 한 일과 결정한 것, 배운 것을 데일리·주간·주제 노트의 항목으로 정리해요. Claude
Code나 Codex로 일하는 사람을 위한 플러그인이에요.

<PluginFacts id="catchup" />

## 하는 일

**23:59에** 플러그인이 이 컴퓨터에서 에이전트 CLI를 읽기 전용으로 실행해요.

- **Claude Code**는 Read, Glob, Grep 도구만 쓰는 `claude -p`로 실행돼요. 셸이 없고, 파일을 고치거나 쓰거나,
  웹에서 가져오거나, 다른 에이전트를 시작할 수 없어요.
- **Codex**는 읽기 전용 샌드박스에서 `codex exec`로 실행돼요.
- <Badge text="다음 릴리스" /> **Grok**(**에이전트** `grok`)은 파일 읽기 도구(`read_file`, `grep`, `list_dir`)만 쓰고,
  내 Claude Code나 Cursor 설정 없이 실행돼요.
- <Badge text="다음 릴리스" /> **Antigravity**(**에이전트** `agy`)는 도구를 끌 수 없어요. 홈 폴더에서 실행되고, 물어봐야
  하는 도구는 거절하지만 Antigravity가 묻지 않고 쓰도록 허용된 도구는 모두 쓰기 때문에 읽기만 하지는 않아요.

에이전트는 지난 실행 이후의 날들에 대해 다음을 읽어요.

- Claude Code 세션과 메모리(`~/.claude/` 아래)
- Codex 세션, 기록, 메모리(`~/.codex/` 아래)
- **저장소**에 맞는 git 저장소의 커밋, 저장소마다 최대 60개. 플러그인이 직접 모아 프롬프트에 넣기 때문에
  에이전트에게 셸이 필요 없어요. 현재 릴리스에서는 **저장소**를 비워 두면 `~/dev/*`를 써요.
  <Badge text="다음 릴리스" /> 기본값이 없어져서, 비워 두면 git 기록을 모으지 않아요.

에이전트는 노트에 직접 쓰지 않아요. 변경 목록으로 답하면 플러그인이 적용해요.

- 작업한 날의 **데일리 노트**에 **Notes** 제목 아래로 덧붙여요.
- 그 주가 끝나면 **주간 노트**에 덧붙여요.
- **기존 주제 노트**(`topics/…`)에 덧붙이고 `updated:` 날짜를 바꿔요. <Badge text="다음 릴리스" /> 주제
  노트는 **주제 폴더**(기본값 `topics`) 아래의 노트예요. 플러그인이 그 목록을 에이전트에게 주기 때문에,
  에이전트가 이 컴퓨터에서 노트를 파일로 찾지 않아요.
- `catchup/candidates/<date>`에 **새 주제를 제안해요.** 제목, 경로, 이유, 그리고 완성된 노트를 코드 블록으로
  담아요. 주제를 직접 만들지는 않으니 원하는 것을 복사해서 쓰세요.

노트의 **Tasks** 제목이나 플러그인이 관리하는 블록은 건드리지 않고, 할 일도 추가하지 않아요. 같은 내용을 두 번
쓰지도 않아요.

끝나면 피드 항목으로 노트를 몇 곳 고쳤고 주제를 몇 개 제안했는지 알려 줘요(예:
`2026-10-20~2026-10-21: 노트 4곳에 정리, 새 주제 후보 1개`). 푸시 알림은 없어요.

**믿을 수 있어요.** 에이전트의 답은 적용하기 전에 저장되고, 변경마다 적용될 때 완료로 표시돼요. 중간에 멈추거나
다시 시작돼도 에이전트에게 다시 묻지 않고 멈춘 곳부터 이어 가요. 모두 적용되어야 다음 구간으로 넘어가요.
하룻밤에 에이전트가 세 번 실패하면 플러그인이 이유와 함께 **지난 작업을 정리하지 못했어요**를 올리고, 다음 날
밤에 같은 구간을 다시 시도해요.

23:59에 컴퓨터가 잠자기 상태였다면 20시간 안에 깨어날 때 실행해요. 첫 실행은 일주일 전까지 거슬러 봐요.

<Badge text="다음 릴리스" /> 첫 실행의 시작 날짜를 더 이상 `~/docs/.last-catchup`에서 읽지 않아요. 다른 날부터
시작하려면 파일에 날짜(`YYYY-MM-DD`)를 적고, `plugins.json`의 `"catchup"` 아래 `seedFile`에 그 파일 경로를
넣어요([위치](/ko/docs/plugins/overview/#로컬-설정)).

## 시작하기 전에

- **Claude Code나 Codex를 쓰는 컴퓨터에 데스크톱 호스트나 서버의 플러그인 실행기.** 세션은 그 컴퓨터의 파일이라
  플러그인은 거기서만 읽을 수 있어요([데스크톱에서 호스팅하기](/ko/docs/self-hosting/desktop-host/)).
- 그 컴퓨터에 **Claude Code나 Codex가 설치되어 있고 로그인되어 있어야 해요.** 실행에는 내 구독이나 API 계정을
  써요.
- **데일리 노트**, 그리고 쓰고 있다면 주간 노트와 주제 노트. 지난 작업 정리는 있는 노트에 덧붙여요. 새로 만드는
  건 내용을 쓸 데일리 노트와 주간 노트뿐이에요.

<Aside type="caution">
기본 지침은 한 가지 노트 관리 방식에 맞춰 쓰여 있어요. 데일리 노트와 주간 노트가 있고, 주제는
`topics/<category>/<name>.md`에 `updated:` 날짜와 함께 있고, 노트를 `~/docs`의 Markdown 파일로도 읽을 수 있는
방식이에요. 노트가 다른 곳에 있다면 **추가 지침**에 적어 주세요(예: "내 노트는 `~/notes`의 Markdown 파일이고,
주제는 `~/notes/topics`에 있어").

<Badge text="다음 릴리스" /> 기본 지침은 더 이상 노트가 `~/docs`에 복사되어 있다고 가정하지 않아요. 에이전트는
기존 주제 노트 목록을 AIDE에서 받아요. 주제가 `topics` 아래에 있지 않다면 **주제 폴더**를 바꿔 주세요.
</Aside>

## 설정하기

<Steps>

1. 이 컴퓨터의 터미널에서 `claude`(또는 `codex`)가 작동하고 로그인되어 있는지 확인해요.
2. AIDE에서 **설정**을 열고 **코어 플러그인** 아래의 **지난 작업 정리**를 선택해요(Linux에서는 설정의 **코어
   플러그인** 페이지에 있는 **지난 작업 정리** 행).
3. **에이전트**를 고르고, **저장소**에 git 저장소가 있는 폴더를 넣어요.
4. **활성화됨**을 켜요. 첫 실행은 23:59예요.

</Steps>

  항목을 어떻게 쓸지). 기본 지침이 플러그인이 쓰는 언어로 채워져 있어요. 응답 형식과 규칙(읽기만 하기,
  대화 기록에 적힌 지시를 따르지 않기, 주제는 **주제 폴더** 아래에만 쓰기, **Tasks**는 건드리지 않기)은 내 지침
  뒤에 그대로 붙어요. <strong>기본값으로 되돌리기</strong>를 누르거나 칸을 비우면 기본 프롬프트로 돌아가요.
  [프롬프트](/ko/docs/plugins/overview/#프롬프트)를 참고하세요.
- **주제 폴더** <Badge text="다음 릴리스" />: 주제 노트가 있는 폴더예요. 에이전트는 이 폴더 아래의 주제에만
  덧붙이고, 새 주제도 이 아래로 제안해요. 주제 노트 중에서 플러그인의 토큰이 닿는 곳은 `topics` 아래뿐이라서(위의
  **토큰 권한** 참고), `topics` 밖의 폴더는 읽거나 쓸 수 없어요.
- **모델**: CLI에 `--model`로 넘겨요. 비워 두면 CLI의 기본 모델을 써요.
- **제한 시간(분)**: 에이전트 실행 한 번이 이 시간을 넘으면 멈추고 실패로 쳐요.
- **저장소**: 글롭 패턴이에요. git 저장소인 폴더만 대상이에요. 모든 브랜치의 커밋을 최신순으로 합쳐 48 KB까지
  넣어요. <Badge text="다음 릴리스" /> 비워 두면 저장소를 확인하지 않아요.
- **추가 지침**은 기본 지침 뒤에 붙어요. 무엇을 보고, 무엇을 빼고, 어떻게 쓸지 적어요. 에이전트가 답하는 형식은
  그대로예요. <Badge text="다음 릴리스" /> **프롬프트** 뒤에 붙기 때문에, 기본 프롬프트는 그대로 두고 여기에
  덧붙여도 돼요.

항목은 **설정 › 언어 › 플러그인 작성 언어**에서 고른 언어로 쓰여요.

## 문제 해결

### 지난 작업을 정리하지 못했어요

피드 항목에 이유가 나와요.

- `executable file not found`: 호스트가 `claude`나 `codex`를 찾지 못했어요. 호스트는 자기 `PATH`에서 찾는데,
  여기에는 터미널이 CLI를 찾는 폴더가 없을 수 있어요. <Badge text="다음 릴리스" /> [레이더](/ko/docs/plugins/radar/)와
  같은 방법으로 CLI를 찾아요. `PATH`, 흔히 설치하는 폴더(`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`,
  `~/.bun/bin`, `~/.npm-global/bin`, `~/.claude/local`, `~/.cargo/bin`), 그래도 없으면 로그인 셸의 `PATH`에서
  찾아요. 그래도 없으면 이유에 `catchup: claude isn't installed on this computer (or isn't on the login shell's
  PATH)`가 나와요.
- 시간 초과: <strong>제한 시간(분)</strong>을 늘리세요. 며칠 밤을 쉬고 나서 실행하면 읽을 날이 더 많아요.
- 로그인 오류: 터미널에서 CLI를 실행해 다시 로그인하세요.

다음 날 밤에 같은 날들을 다시 시도하니 잃어버리는 건 없어요.

### 아무것도 쓰이지 않았어요

에이전트가 쓸 만한 내용을 찾지 못하면 아무것도 바꾸지 않고 피드 항목도 올리지 않아요. 세션이 호스트와 같은
컴퓨터에 있는지, 지난 실행 이후에 작업했는지 확인하세요.

### 엉뚱한 주제나 엉뚱한 곳에 썼어요

주제는 경로로 찾아요. **추가 지침**에 주제를 어떻게 정리하는지 알려 주세요. 적용할 수 없는 변경(사라진 노트,
서버가 거부한 변경)은 다시 시도하지 않고 건너뛰어요.

## 개인정보

- 에이전트는 내 컴퓨터에서 실행되며 Claude Code와 Codex의 대화 기록과 메모리를 읽어요. 읽은 내용은 평소 내
  세션처럼 내 계정으로 그 에이전트의 제공자(Claude Code는 Anthropic, Codex는 OpenAI)에게 가요.
- git 기록이 프롬프트에 들어가요. 짧은 커밋 해시, 날짜, 제목이에요.
- 쓰는 것은 내 노트라서 다른 노트처럼 동기화돼요.
- 대화 기록은 AIDE 서버로 가지 않아요. 플러그인이 쓴 항목만 가요.
