GitHub 플러그인은 진행 중인 GitHub 작업을 한곳에 모아요. 나에게 할당된 이슈와 풀 리퀘스트, 나에게 온 리뷰
요청은 `work/now` 노트에 정리되고, 새로 생긴 것과 멘션, 댓글은 피드로 와요.

<PluginFacts id="github" />

## 하는 일

**진행 중인 작업.** 10분마다 GitHub에서 나에게 할당된 열린 이슈와 풀 리퀘스트, 내 리뷰를 요청한 열린 풀
리퀘스트를 찾아요. 보관된 저장소는 빼요. 찾은 것은 `work/now` 노트("Work — now")의 플러그인 전용 섹션에 마지막
업데이트 순으로 최대 50개까지 써요.

```markdown
GitHub — 진행 중 3개
- [acme/web\#42](https://github.com/acme/web/pull/42) Fix the login redirect · review
- [acme/web\#40](https://github.com/acme/web/issues/40) Flaky upload test · assigned
- [acme/api\#7](https://github.com/acme/api/pull/7) Rate limit headers · assigned, review
```

더 이상 열려 있지 않거나 내 작업이 아닌 것은 목록에서 빠져요. 이 섹션은 플러그인 전용이라, 노트의 나머지와
옆에 있는 [Linear](/ko/docs/plugins/linear/), [Jira](/ko/docs/plugins/jira/) 섹션은 건드리지 않아요.

**멘션과 댓글.** 2분마다(GitHub가 더 긴 간격을 요청하면 그 간격으로) 내가 참여한 스레드의 알림을 읽은 것,
안 읽은 것 모두 읽고, 그중 멘션, 팀 멘션, 댓글을 가져와요.

**피드에.** 바뀐 것마다 피드에 `github` 주제로 항목을 하나씩 올리고, GitHub의 해당 페이지로 연결해요.

| 피드 제목                  | 언제                                          | 알림                  |
| -------------------------- | --------------------------------------------- | --------------------- |
| "나에게 할당: &lt;제목&gt;"      | 이슈나 풀 리퀘스트가 새로 나에게 할당됐을 때  | 항상                  |
| "리뷰 요청: &lt;제목&gt;"        | 풀 리퀘스트가 새로 내 리뷰를 요청했을 때      | 항상                  |
| "나를 언급했어요: &lt;제목&gt;"  | 누군가 나나 내 팀을 언급했을 때               | 피드의 분류가 정해요  |
| "새 댓글: &lt;제목&gt;"          | 내가 참여한 스레드에 새 댓글이 달렸을 때      | 피드의 분류가 정해요  |

항목은 한 번씩만 올려요. 할당이나 리뷰 요청이 끝났다가 나중에 다시 생기면 다시 올려요. 토큰을 넣은 뒤나 다른
GitHub 계정으로 바꾼 뒤의 첫 확인에서는 아무것도 올리지 않아요. 이미 열려 있던 작업은 `work/now`에만 정리돼요.

플러그인은 읽기만 해요. GitHub에 댓글을 달거나, 닫거나, 무엇이든 바꾸지 않아요.

## 시작하기 전에

- [데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)나 직접 운영하는 서버가 필요해요. 플러그인은 거기서
  실행되고, 그 컴퓨터에서 GitHub를 읽어요.
- `repo`와 `notifications` 권한이 있는 GitHub **클래식** 개인 액세스 토큰이 필요해요. GitHub는 세분화된
  토큰(fine-grained)에는 알림을 주지 않아요. 그런 토큰이면 플러그인은 할당과 리뷰 요청은 계속 정리하지만 멘션과
  댓글은 읽지 못하고, 상태에 " · 멘션은 클래식 토큰이 필요해요"가 붙어요.

## 설정하기

<Steps>

1. **설정**을 열고 **코어 플러그인** 아래의 **GitHub**를 선택해요(Linux에서는 설정의 **코어 플러그인** 페이지에
   있는 **GitHub** 행).
2. **API 토큰** 옆의 **토큰 만들기**를 선택해요. GitHub의 **New personal access token (classic)** 페이지가
   `repo`와 `notifications`가 체크되고 메모가 `AIDE`인 채로 열려요. 만료 기간을 고르고 **Generate token**을
   누른 뒤 토큰을 복사해요.
3. **API 토큰**에 붙여 넣고 **저장**을 선택해요.
4. **활성화됨**을 켜요. 몇 분 안에 설정 아래 상태가 "&lt;내 로그인&gt;로 연결됐어요 · 진행 중 N개 · HH:MM 확인"으로
   바뀌고, `work/now`에 진행 중인 작업이 정리돼요.

</Steps>

## 설정

<PluginSettings id="github" defaults={{ apiToken: "", repos: "", mentions: "켬" }} />

- **저장소**로 일부 저장소만 볼 수 있어요. 하나는 `owner/repo`, 한 소유자의 전부는 `owner/*`로 적어요. 비우면
  토큰이 볼 수 있는 모든 저장소예요. 진행 중인 작업과 알림 모두에 적용돼요.
- **멘션**을 끄면 알림을 읽지 않아요. 피드에 멘션과 댓글이 오지 않고, 할당과 리뷰 요청은 계속 와요.

### 로컬 키

데스크톱 호스트의 `plugins.json`([폴더 위치](/ko/docs/plugins/overview/#로컬-설정))에서 `"github"` 아래에 적어요.

| 키        | 하는 일                                                                                    |
| --------- | ------------------------------------------------------------------------------------------ |
| `apiBase` | 플러그인이 통신할 API 주소. 기본값 `https://api.github.com`. 보통은 정하지 않아요.         |

## 상태

플러그인 설정 아래의 상태에 지금 어떤지가 나와요.

- 확인에 성공할 때마다 "&lt;로그인&gt;로 연결됐어요 · 진행 중 N개 · HH:MM 확인". 읽을 수 있는 것보다 작업이 많으면
  " · 처음 N개를 표시해요"가 붙어요.
- 토큰이 없으면 "API 토큰을 넣어 주세요". 토큰을 지우면 `work/now`의 플러그인 섹션도 "GitHub — 연결이
  해제됐어요"로 바뀌어요.
- 확인에 실패하면 "토큰이 거부됐어요, HH:MM에 다시 시도해요", "요청 한도에 도달했어요, HH:MM에 다시
  시도해요", "GitHub에 연결하지 못해 다시 시도해요, HH:MM에 다시 시도해요" 같은 문구가 나와요. `work/now`의
  목록은 그대로 두고, 첫 줄에 "&lt;시각&gt; 이후 갱신 안 됨: &lt;이유&gt;"를 표시해요.

## 문제 해결

### 토큰이 거부됐어요

GitHub가 토큰을 받지 않았어요. 예를 들어 토큰이 만료됐거나 지워졌을 때예요. 플러그인은 마지막 목록을 두고
30분마다 다시 시도해요. **토큰 만들기**로 새 클래식 토큰을 만들어 **API 토큰**에 저장하세요.

### 요청 한도에 도달했어요

GitHub가 요청을 줄여 달라고 했어요. 플러그인은 GitHub가 정한 만큼(최대 1시간) 기다렸다가 다시 확인해요.
네트워크가 없는 것 같은 다른 실패는 2분 뒤에 다시 시도하고, 점점 간격을 늘려 최대 30분마다 시도해요.

### 목록에 "처음 50개를 표시해요"가 나와요

섹션에는 최대 50개까지 나오고, 검색마다 최대 250개까지 읽어요. 그보다 많으면 지금 보이지 않는 작업을 지우지
않고 남겨 둬요. **저장소**로 읽는 범위를 좁힐 수 있어요.

### 피드에 멘션이 오지 않아요

**멘션**이 켜져 있는지, 토큰이 `notifications` 권한이 있는 클래식 토큰인지 확인하세요. 세분화된 토큰이면 상태에
" · 멘션은 클래식 토큰이 필요해요"가 나와요. **토큰 만들기**로 클래식 토큰을 만드세요. 내가 참여한 스레드의 알림만 세고,
**저장소**를 정했다면 그 저장소의 알림만 세요.

### work/now의 첫 줄과 상태가 하는 말

`work/now`의 플러그인 섹션 첫 줄은 "GitHub — 진행 중 3개"처럼 보여요. 목록보다 작업이 많으면
" · 처음 50개를 표시해요"가, 확인에 실패한 뒤에는 " · &lt;날짜 시각&gt; 이후 갱신 안 됨: &lt;이유&gt;"가(아래 목록은 마지막으로
성공한 목록이에요), 첫 확인이 아직 성공하지 못했으면 " · 아직 동기화하지 못했어요: &lt;이유&gt;"가 붙어요. 섹션에는
시각이 없고, 마지막으로 확인한 시각은 플러그인 설정 아래의 상태에 나와요.

### 피드 항목이 늦게 와요

AIDE 서버가 플러그인의 피드 항목을 받지 못하면(서버가 다시 시작 중일 때 등) 항목은 기다렸다가 나중에 순서대로,
빠짐없이 한 번씩 보내져요. 그동안 상태에 " · 이벤트 N개가 AIDE 서버를 기다려요"가 붙어요.

## 개인정보

플러그인은 플러그인을 실행하는 컴퓨터에서 내 토큰으로 GitHub API와 통신하고, 읽기만 해요. 진행 중인 항목마다
저장소, 번호, 제목(200자까지), 링크, 상태, 마지막 업데이트만 보관하고, 이슈 본문이나 댓글은 보관하지 않아요.
토큰은 호스트나 서버에 봉인돼 저장되고, 이 플러그인만 읽을 수 있어요. `work/now` 노트와 피드 항목은 다른
노트처럼 기기에 동기화돼요. [어시스턴트](/ko/docs/guides/assistant/)와 [아침 브리핑](/ko/docs/plugins/briefing/)은
`work/now`를 지시가 아닌, 내 도구에서 온 데이터로 읽어요.

<Aside>
제목은 다른 사람이 GitHub에 쓴 그대로 와요. AIDE는 노트에 쓰기 전에 제목을 이스케이프해서, 제목이 링크나
서식으로 바뀌지 않게 해요.
</Aside>
