스크래치는 어디에 둘지 정하지 않고 쓰는 곳이에요. 스크래치 노트는 `scratch/` 아래에 있는 평범한 노트예요. 나중에 **정리**가 노트마다 위키 안의 자리를 제안하고, 승인하기 전에는 아무것도 옮기지 않아요.

## 적어 두기

- **빈 탭**(Mac, Linux): 새 탭은 이미 편집기이고 "입력하면 스크래치 노트가 돼요."라는 안내가 보여요. 처음 입력한 텍스트로 스크래치 노트가 만들어지고 바로 스크래치에 나타나며, 같은 자리에서 계속 입력하면 돼요.
- **새 스크래치 노트**: Mac에서는 <kbd>⌘</kbd><kbd>N</kbd>, Linux에서는 <kbd>Ctrl</kbd><kbd>N</kbd>, 또는 스크래치 패널의 **+**. iPhone에서는 스크래치 탭의 **+**.
- **빠른 메모**(Mac): 어느 앱에서든 <kbd>⌥</kbd><kbd>Space</kbd>를 누르세요. "간단히 적어 보세요…"가 적힌 작은 창이 열려요. <kbd>Return</kbd>은 스크래치에 저장하고("스크래치에 저장됨") 창을 닫고, <kbd>⇧</kbd><kbd>Return</kbd>은 줄을 바꾸고, <kbd>Esc</kbd>는 창을 닫아요.
- **메뉴 막대 아이콘**(Mac): **빠른 메모…**, **새 노트**, **오늘 노트 열기**, **AIDE 열기**, **AIDE 종료**. 아이콘이나 단축키가 켜져 있으면 마지막 창을 닫아도 AIDE가 계속 실행돼요.
- **터미널이나 런처에서**: `aidectl capture "call the bank"`는 앱과 같은 방식으로 스크래치 노트를 추가해요. `-`를 주거나 텍스트가 없으면 표준 입력을 읽어요. Linux에서는 데스크톱의 키보드 설정에서 키에 연결하면 메모 단축키가 돼요. [aidectl](/ko/docs/developers/aidectl/)을 보세요.

Mac의 **설정 › 빠른 메모**에서 **메뉴 막대에 AIDE 표시**와 **빠른 메모 단축키**를 켜거나 끄고(둘 다 기본으로 켜져 있어요), 다른 단축키를 기록해요. 입력란을 클릭하고 키를 누르면 되고, <kbd>Esc</kbd>는 이전 단축키를 유지하며, **초기화**는 <kbd>⌥</kbd><kbd>Space</kbd>로 되돌려요.

### 노트 대신 할 일로

<Badge text="다음 릴리스" /> 적는 내용을 `/todo`(또는 `/할일`)로 시작하면 스크래치가 아니라 오늘 할 일에 들어가요. 그 뒤의 줄마다 할 일 하나가 되고, 할 일 화면의 빠른 추가처럼 데일리 노트의 할 일 머리글 아래에 추가돼요.

```
/todo call the bank
pay rent
```

빠른 메모(**오늘 할 일에 추가했어요**라고 알려 줘요), 스크래치의 입력칸, [어시스턴트](/ko/docs/guides/assistant/)(모델에 묻지 않고 바로 추가해요), `aidectl capture`에서 돼요. 빠른 메모와 스크래치에서는 추가하지 못한 할 일만 입력칸에 남고(이미 추가된 건 그대로 둬요), 다시 시도해도 두 번 들어가지 않아요. 어시스턴트는 추가하지 못한 할 일을 알려 줘요.

적어 둘 때 AIDE가 노트에 닿을 수 없다면(예를 들어 서버가 오프라인일 때), 텍스트는 스크래치의 **미전송** 아래에 남았다가 가능해지면 추가돼요.

## 정리

<Steps>

1. 스크래치 패널 머리글에서 **정리**를 고르세요(iPhone에서는 스크래치의 **더 보기 › 정리**, 데스크톱에서는 명령 팔레트의 <strong>스크래치 노트 정리…</strong>도 돼요). 시트에 위키 안의 자리를 제안받을 스크래치 노트 수가 보여요.
2. **제안받기**를 고르세요. 스크래치 노트마다 짧은 이유와 함께 제안이 하나씩 나와요. 경로에 **새 페이지**를 만들거나, 기존 페이지에 덧붙이는(**추가할 위치**) 제안이에요.
3. 모든 제안은 선택된 채로 시작해요. 빼고 싶은 제안을 클릭하세요.
4. **적용**을 고르면 선택한 제안이 반영돼요. 뺀 제안은 손대지 않은 스크래치 노트로 남아요.

</Steps>

새 페이지 제안은 스크래치 노트의 텍스트로 페이지를 만들어요. 덧붙이는 제안은 그 페이지 끝에 텍스트를 넣어요. 아직 없는 일일 노트라면 먼저 템플릿으로 만들어서, 텍스트가 템플릿 모양대로 그날의 노트에 들어가요. 반영된 스크래치 노트는 삭제되지 않고 스크래치에서 보관되며, **설정 › 노트 › 최근 삭제된 항목**에서 되살릴 수 있어요.

제안받기와 적용 사이에 노트가 바뀌면, 적용은 멈추고 최신 텍스트로 작업하도록 다시 제안받으라고 해요. 반영하는 도중 AIDE가 중단됐다면 시트에 관련 페이지와 함께 "이전 정리 작업을 확인해야 해요"가 보여요. 페이지를 확인하세요. 확인할 때까지 스크래치 노트는 남아 있어요.

### AI로, 또는 규칙으로

정리는 AI가 설정돼 있으면 AI를, 아니면 규칙을 써요. AI를 쓸 수 있으면 시트에 **AI 사용** 스위치가 있어요.

- **AI로** 할 때는 모델이 스크래치 노트마다 내용과 위키 페이지 이름을 읽고, 새 페이지나 덧붙일 기존 페이지를 제안해요. 서식을 깔끔한 Markdown으로 다듬을 수는 있지만 표현은 그대로 둬요. `scratch/` 아래로는 절대 정리하지 않고, AIDE가 보여 주기 전에 제안을 모두 확인해요. 로컬 보관소에서는 **설정 › AI**에 Anthropic API 키를 추가하세요. 서버나 데스크톱 호스트에서는 정리가 서버의 AI를 써요. [AI와 모델](/ko/docs/guides/ai/)을 보세요.
- **규칙으로** 할 때는 모델을 쓰지 않아요.
    1. `#tag`가 있는 노트는 `topics/` 뒤에 첫 태그가 붙은 곳으로 가요(`#investing` → `topics/investing`).
    2. 아니면, 할 일이 있는 노트는 오늘의 일일 노트로 가요.
    3. 아니면, `inbox`로 가요.

<Badge text="다음 릴리스" /> 이유는 AI로 하든 규칙으로 하든 플러그인 작성 언어(**설정 › 언어 › 플러그인 작성 언어**)로 써요. 한국어라면 "#investing 태그가 있어요", 영어라면 "tagged #investing"이에요.

<Aside title="정리가 보내는 것">
AI로 정리할 때는 정리하는 스크래치 노트와 위키 페이지 이름을 모델로 보내요. 내 키를 쓰면 Anthropic으로 바로 가요. 다른 노트의 텍스트는 보내지 않아요. 규칙으로 정리할 때는 아무것도 기기나 서버를 떠나지 않아요.
</Aside>
