AIDE에서 회의는 노트예요. 캘린더 일정에서 만들거나 그 자리에서 바로 만들고, 회의를 그 노트에 녹음해요. AIDE는
나눈 말을 기기에서 받아쓰고, 어시스턴트의 모델로 요약하고, 실행 항목을 제안해요. 실행 항목은 승인하면 할 일이
돼요. 회의는 그날 데일리 노트에도 한 줄로 들어가요.

## 회의 노트 만들기

- **일정에서:** [캘린더](/ko/docs/guides/calendar/)에서 일정을 열고 **회의 노트**를 선택하세요. 노트에 일정의
  제목, 시간, 참석자, 관련 노트 링크, 받아쓰기용 단어 목록이 들어가요. 다시 선택하면 같은 노트가 열려요.
- **그 자리에서:** Mac에서는 **파일 › 새 회의**(<kbd>⇧</kbd><kbd>⌘</kbd><kbd>R</kbd>), iPhone에서는 위키의
  **더 보기** 메뉴에 있는 **새 회의**, Linux에서는 명령 팔레트의 **새 회의**를 쓰세요. 지금 시작하는 회의를
  만들고, 열고, 녹음을 시작해요.

회의 노트는 `meetings/` 아래에 날짜와 제목을 딴 이름으로 저장돼요. 예: `meetings/2026-10-17-design-review`. 노트
이름을 바꾸거나 옮겨도 돼요. AIDE는 경로가 아니라 frontmatter의 ID로 회의를 찾아요.

회의 노트에는 이런 섹션이 있어요.

| 섹션 | 들어가는 것 |
|---|---|
| **Context** | 회의와 관련된 노트 링크. Google 일정이면 캘린더가 아는 내용도 들어가요. |
| **Notes** | 내 메모. 여기에(또는 생성된 부분 밖이라면 어디에든) 자유롭게 쓰세요. |
| **Summary** | 요약을 마치면 들어가는 요약과 결정 사항. |
| **Actions** | 승인한 실행 항목, 할 일 형태로. |
| **Transcript** | 받아쓴 대화와 그 교정 내용. |

생성된 부분은 각자의 블록에 들어 있고, AIDE는 그 블록만 다시 써요. 그래서 내가 쓴 내용은 절대 건드리지 않아요.
다른 곳에서 온 텍스트(대화록, 일정 설명)는 코드 블록 안에 들어가서, 그 안의 어떤 것도 할 일로 바뀌지 않아요.

## 녹음

회의 노트에서 **녹음**을 선택하세요. 노트 위에 막대가 나타나 경과 시간, 소스, 음량 표시와 함께
**일시 정지**/**계속**, **중지** 버튼을 보여 줘요. 회의를 녹음하는 동안에는 모든 창에 회의 제목과 시간이 적힌
작은 알약 모양 표시가 보이고, 누르면 노트가 열려요.

- **소스:** 마이크, 그리고 Mac과 Linux에서는 컴퓨터에서 재생되는 소리도 녹음해요. 그래서 통화 상대방의 목소리도
  녹음돼요. **설정 › 회의 › 이 Mac의 재생 소리 녹음**(Linux에서는 **이 컴퓨터의 재생 소리 녹음**)이고, 기본값은
  켜짐이에요. Mac에서는 처음 한 번 권한을 물어요. 녹음은 동작하는 소스로 시작하고, 어떤 소스인지 알려 줘요.
- 중지한 뒤 **Record again**을 누르면 같은 녹음에 이어서 붙어요. 타임라인도 계속 이어져요.
- 한 번에 한 회의만 녹음할 수 있어요. 녹음하는 동안에는 어시스턴트의 마이크가 꺼져요.
- 마이크가 끊기면 녹음이 일시 정지돼요. 디스크가 가득 차거나 쓰기가 밀리면 녹음을 멈추고 그때까지의 내용을
  보관해요. 앱이 비정상 종료되면 다음 실행 때 녹음을 복구해요.

## 녹음 가져오기

다른 곳에서 녹음한 오디오(음성 메모, 녹음기, 통화 녹음 등 기기에서 재생할 수 있는 것, 최대 6시간)를 가져오려면:

- 회의 노트에서 <strong>녹음 가져오기…</strong>를 누르면 그 회의에 파일을 추가해요.
- Mac의 **파일 › 녹음 가져오기…**, iPhone 위키의 **더 보기** 메뉴에 있는 **녹음 가져오기**, Linux의 명령
  팔레트는 먼저 어떤 회의인지 물어요. AIDE가 파일이 녹음된 때를 추정해(**녹음 시각**, 바꿀 수 있어요) 그 무렵의
  일정을 나열하거나, 파일 이름을 딴 **새 회의**를 보여 줘요.

가져온 파일도 실시간 녹음처럼 받아쓰고 요약해요.

## 기기에서 받아쓰기

나눈 말은 녹음이 있는 기기에서 받아써요. 녹음이 진행되는 동안 30초 단위로, 어시스턴트의 음성과 같은 엔진으로
받아써요. Mac과 iPhone에서는 Apple의 기기 내 음성 인식, Linux에서는 whisper.cpp예요. 받아쓰기를 위해 어디로도
전송하지 않아요. 언어는 **설정 › 어시스턴트 › 음성 › 언어**에 설정한 언어를 따라요.

회의마다 단어 목록(frontmatter의 `meeting-glossary`)이 있어요. 참석자, 링크된 노트의 제목, 일정 제목과 설명에
나오는 이름이 들어가요. 인식기는 이 단어들이 나올 거라고 미리 알고 받아써요. 이름이나 전문 용어를 잘 알아듣게
하려면 목록에 직접 단어를 추가하세요.

회의를 받아쓸 수 없으면(그 언어를 지원하는 엔진이 없거나, 권한을 거부했거나, Linux에서 음성 모델을 내려받지
않았을 때) 노트에 **아직 받아쓰지 않았어요**와 이유, **다시 시도**가 보여요. Linux에서는 **설정 › 어시스턴트 ›
음성**에서 음성 모델을 내려받으세요.

## 요약

녹음을 멈추고 받아쓰기가 모두 끝나면, AIDE가 어시스턴트의 모델(**설정 › 어시스턴트 › 모델 제공처**.
[AI와 모델](/ko/docs/guides/ai/) 참고)로 알아서 요약해요. 모델에는 제목, 시작 시각, 참석자, 단어 목록, 링크된
노트마다 앞부분, 캘린더의 맥락, 대화록이 전달돼요. 긴 회의는 여러 부분으로 나눠 요약해요.

그러면 노트에 이런 것이 들어가요.

- **Summary**: 몇 개의 글머리 항목, 어디서 요약했는지("Summed up with Claude Code (sonnet)"), 그리고
  **Decisions**. 결정 사항마다 그 이야기가 나온 시각이 붙어요.
- **Corrections**: 참석자와 내 노트를 바탕으로 모델이 잘못 들었다고 판단한 단어예요. 대화록에서 고친 단어와 원래
  들린 말이 함께 보여요.
- **Proposed action items**: 제안된 실행 항목이 나를 기다려요.

나중에 대화록이나 맥락이 바뀌면 노트에 <strong>요약한 뒤로 바뀌었어요.</strong>와 **다시 처리**가 보여요. 실패하면
**요약하지 못했어요**와 이유, **다시 처리**가 보여요.

## 실행 항목 승인하기

요약된 회의 아래에는 제안된 실행 항목마다 내용, 담당자, 언급된 시각이 **승인**, **닫기** 버튼과 함께 보여요.
여러 개라면 **모두 승인**도 있어요.

- **승인**은 **Actions** 섹션에 `- [ ] Send the report [meeting:: a1]` 같은 할 일을 추가해요. 그래서 다른 할
  일처럼 [할 일](/ko/docs/guides/todos/)에 보여요.
- **닫기**는 항목을 버려요.
- AIDE는 제안했던 항목을 모두 기억해요. 그래서 닫았거나 수정한 항목은 다시 제안하지 않아요.
- 어시스턴트가 <strong>즉시 적용(yolo)</strong>으로 설정되어 있으면, 새 항목은 작성되자마자 승인돼요.

**대화록**을 누르면 교정이 적용된 전체 대화록이 열려요. 교정 옆의 **실행 취소**를 누르면 그 교정을 되돌려요.

## 녹음 보관

**설정 › 회의 › 녹음 보관**에서 오디오를 기기에 얼마나 둘지 정해요.

- **처리 후 7일**(기본값)
- **처리 직후**
- **삭제할 때까지**

오디오는 회의 요약이 끝나고 정한 시간이 지난 뒤에만 삭제돼요. 노트의 대화록은 어느 쪽이든 남아요.

## 개인정보

<Aside type="note">
회의 오디오는 녹음한 기기를 떠나지 않아요. 그 기기의 AIDE 데이터 폴더(Mac과 iPhone은 Application Support,
Linux는 `$XDG_DATA_HOME/aide`)에 보관되고, 노트에는 텍스트만 들어가요.
</Aside>

요약할 때는 회의 내용이 모델로 전송돼요. 대화록, 참석자, 단어 목록, 링크된 노트의 앞부분이
**설정 › 어시스턴트 › 모델 제공처**에서 고른 백엔드로 가요. 어시스턴트의 **읽지 않을 폴더**에 있는 노트는 절대
보내지 않아요. 모델이 없어도 녹음과 대화록은 동작해요. 회의 요약만 되지 않아요.
