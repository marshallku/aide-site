AIDE는 전체를 직접 소유하도록 만들어졌어요. 노트는 내 컴퓨터나 서버의 파일이고, AI는 내가 고른 제공자에서
돌거나 아예 돌지 않아요. 이 페이지에는 무엇이 기기 밖으로 누구에게 나가는지, 그리고 나가지 않게 하려면 어떻게
하는지 정리했어요.

## 기기에 남는 것

- **음성.** 어시스턴트와 말로 대화하면 기기에서 받아써요. Mac과 iPhone에서는 Apple의 온디바이스 인식을,
  Linux에서는 whisper.cpp를 써요. 서버의 인식은 절대 쓰지 않아요. 오디오는 그 녹음 하나 동안만 메모리에 있고,
  디스크에 쓰이거나 전송되지 않아요. 직접 입력한 메시지처럼 텍스트만 넘어가요.
- **회의 오디오.** 회의는 녹음하는 기기에서 녹음하고 받아써요. 오디오는 그 기기를 절대 떠나지 않아요. 나눈
  이야기는 텍스트로 회의 노트에 들어가요. [회의](/ko/docs/guides/meetings/)를 보세요.
- **기기의 캘린더.** Mac과 iPhone에서 캘린더는 기기의 캘린더를 읽고, 서버에 올리지 않아요.
- **레이더의 Slack 피드.** Slack의 **내 채널 팔로우**를 켜면 참여한 채널의 메시지가 플러그인을 돌리는 컴퓨터에
  14일 동안 보관되고, 서버로는 절대 보내지 않아요. [레이더](/ko/docs/plugins/radar/)를 보세요.
- **기기 플러그인의 저장 공간.** 기기 플러그인 자체의 저장 공간은 그 기기에 남아요.

## AI 제공자에게 가는 것과 그 시점

AI는 직접 설정한 곳에서만 돌아요. Anthropic API 키, 내 컴퓨터의 Claude Code나 Codex, 직접 운영하는 게이트웨이,
또는 서버의 AI예요. [AI와 모델](/ko/docs/guides/ai/)을 보세요. 이들은 각각 뒤에 있는 제공자에게 텍스트를 보내요.

| 기능 | 보내는 것 | 시점 |
| ------- | ----------- | ---- |
| 정리 | 선택한 스크래치 노트와 위키 페이지 이름 | **제안받기**를 누를 때 |
| 피드 분류 | 새 이벤트마다 제목과 본문 최대 2KB, 그리고 관심사로 쓰는 위키 용어 최대 200개 | 이벤트가 도착할 때 |
| 어시스턴트 | 열린 할 일, 오늘 캘린더 일정과 비어 있는 시간, 어시스턴트의 기억과 목표 노트, 어시스턴트가 읽겠다고 요청한 노트 | 메시지를 보낼 때마다, 또는 어시스턴트가 먼저 말할 때 |
| 회의 | 녹취록, 용어집, 회의에 연결된 노트 | 녹음을 요약할 때 |
| 서버 플러그인 | 플러그인마다 모으는 것: 브리핑의 캘린더와 할 일, 저녁 정리의 데일리 노트, 답장이 필요할 수 있는 Gmail 스레드, 저장한 Slack 스레드 등 | 플러그인의 일정에 따라, 또는 반응할 때 |

어시스턴트가 Claude Code와 Codex를 쓸 때는 도구 없이 빈 임시 폴더에서 실행해요. 프롬프트가 들어가고 답이 나올
뿐이에요. 스스로 내 파일을 읽을 수 없어요.

### 보내지 않게 하는 방법

- **AI를 쓰지 않아요.** **설정 › AI**에서 <strong>규칙(AI 미사용)</strong>을 골라요. 그러면 정리는 규칙으로 노트를 분류하고(첫
  `#tag`는 `topics/<tag>`로, 할 일이 있는 노트는 오늘 데일리 노트로), 분류는 키워드로 이벤트를 나눠요. 로컬
  모드에서는 API 키를 넣지 않으면 정리가 똑같이 동작해요.
- **읽지 않을 폴더.** **설정 › 어시스턴트**의 **읽지 않을 폴더**에 폴더를 넣으세요(`private/`나 `health/` 등).
  그 아래의 것은 어시스턴트에 보내지 않아요. 그 안의 할 일은 빠지고, 어시스턴트가 그 안의 노트를 요청해도 읽지
  않아요. 레이더는 자체 `neverRead` 설정의 폴더를 절대 읽거나 쓰지 않아요.
- **읽기 승인.** 어시스턴트가 기본으로 허용되지 않은 노트를 읽으려 하면 먼저 물어봐요. <strong>어시스턴트가 읽으려는
  항목: …</strong>이라는 메시지와 함께 **허용**과 **거부**가 나와요.
- **플러그인을 꺼 두세요.** 모든 서버 플러그인은 직접 켜기 전까지 꺼져 있어요.

## 토큰과 페어링

- **기기 토큰**은 서버에 SHA-256 해시로만 저장돼요. 기기에서는 키체인(Mac과 iPhone)이나 키링(Linux)에 있고,
  잠금 해제된 키링을 찾지 못하면 비공개 파일에 있어요.
- 서버의 **페어링 코드**는 한 번만 쓸 수 있고 10분 뒤에 만료돼요. 10번 실패한 클라이언트 주소는 10분 동안
  차단돼요. **설정 › 기기**에 모든 기기가 나오고, **접근 권한 해제**를 누르면 그 기기가 로그아웃돼요.
- **데스크톱 호스트와의 페어링**에는 5분 동안 기기 한 대에만 쓸 수 있는 링크를 써요. 키 지문을 비교한 뒤
  호스트에서 기기를 승인해요.
- **플러그인 토큰**은 범위가 정해져 있어요. 서버 플러그인마다 읽거나 쓸 수 있는 노트, 보낼 수 있는 이벤트 토픽,
  AI 실행 여부로 제한된 토큰을 받아요. 기기 토큰처럼 해시로 저장돼요.
- **Claude 앱의 토큰**(**설정 › Claude 앱**)은 노트를 읽고, 허용했을 때만 노트를 써요. 연결을 끊으면 토큰이
  해제돼요.
- `aidectl`이 쓰는 내 컴퓨터의 **로컬 API**는 내 사용자로 실행되는 프로그램에만 응답해요.

## 서버의 비밀 값

AI 키, 게이트웨이 토큰, 플러그인 비밀 값(예: Slack 토큰)은 저장하기 전에 서버의 키로 AES-256-GCM 봉인을 해요.
앱은 비밀 값을 저장할 수는 있지만 다시 읽을 수는 없어요. 설정되어 있다는 사실만 알 수 있어요. 비밀 값은 그 값이
속한 플러그인만 읽을 수 있어요.

데스크톱 호스트에서는 봉인 키가 Mac의 키체인이나 Linux 키링에 있어요. 전용 서버에서는 `AIDE_SECRET_KEY`예요.

## 기기 사이의 연결

- **데스크톱 호스트**: 양방향 TLS 1.3이에요. 기기마다 호스트 키를 고정하고, 호스트는 내가 승인한 뒤 발급한
  인증서를 가진 기기만 들여보내요. 네트워크 접근은 직접 켜기 전까지 꺼져 있고, 고른 주소에서만 연결을 기다려요.
  [데스크톱에서 호스팅하기](/ko/docs/self-hosting/desktop-host/)를 보세요.
- **전용 서버**: 앞단에 둔 프록시(Tailscale, Cloudflare Tunnel, Caddy)를 통한 HTTPS예요. 앱은 같은 컴퓨터의
  서버가 아니면 HTTPS를 요구해요.

## 기기 플러그인

기기 플러그인은 iPhone, Mac, Linux에서 샌드박스 웹 뷰 안에서 돌아가요.

- **권한.** 설치할 때 플러그인이 요청하는 권한(특정 폴더 아래 노트 읽기, 할 일 쓰기, 자체 저장 공간, 지정한
  호스트로의 HTTPS…)을 하나하나 보고, 동의하는 것만 켜요. 그 밖의 호출은 실패해요.
- **기본으로 네트워크가 없어요.** 플러그인 페이지는 네트워크에서 아무것도 불러올 수 없어요. 승인한 호스트에만
  AIDE를 거쳐 닿을 수 있어요.
- **파일 고정.** 플러그인은 모든 파일의 해시로 식별돼요. 그 뒤에 기기에서 파일이 바뀌면, 다시 설치할 때까지
  플러그인이 꺼져요.

[기기 플러그인 설치하기](/ko/docs/plugins/device-plugins/)를 보세요.

## 업데이트

AIDE 릴리스는 공개 GitHub 릴리스에서 와요. `install.sh`와 앱 안의 업데이트 모두 내려받은 파일을 릴리스의
`SHA256SUMS`와 대조해요. Mac 앱은 Developer ID로 서명되고 Apple의 공증을 받았어요. 업데이트할 때는 새 앱이 같은
팀의 서명을 받았는지도 확인한 뒤 교체해요. 새 버전이 시작되지 않으면 AIDE가 이전 버전으로 돌아가요.

<Aside type="note">
Linux에서는 체크섬으로 내려받은 파일이 온전한지 확인해요. 릴리스에 따로 서명하지는 않아요.
</Aside>
