호스팅하면 Mac이나 Linux 컴퓨터의 보관소가 그 자체로 서버가 돼요. 로컬 모드에 없는 기능(서버 플러그인, 피드,
내 키로 쓰는 AI, `aidectl mcp`를 통한 Claude)을 쓸 수 있고, 노트는 같은 폴더에 Markdown 파일로 그대로 남고,
서버를 따로 운영할 필요도 없어요.

## 호스팅하면 실행되는 것

보관소를 호스팅하면 AIDE가 내 컴퓨터에서 세 가지를 시작해요. 모두 설치한 앱 안에 들어 있어요.

- **AIDE 서버**: 직접 운영하는 서버와 같은 프로그램을 호스트 모드로 실행해요. 내 사용자 계정만 열 수 있는
  Unix 소켓으로 보관소를 제공해요. 기기를 들이기 전까지는 네트워크에서 아무것도 연결을 기다리지 않아요.
- **자체 PostgreSQL**(AIDE에 포함된 PostgreSQL 18): 비공개 소켓에서만 연결을 기다리고, TCP 포트는 절대 쓰지
  않아요. 이벤트 로그, 설정, 페어링한 기기, 플러그인 데이터를 저장해요. 시스템에 설치된 PostgreSQL과는
  별개예요.
- **플러그인 러너**: 내장 서버 플러그인을 모두 실행해요. 멈추면 호스트가 30초 뒤에 다시 시작해요.

노트 자체는 원래 있던 곳, 즉 보관소 폴더의 파일로 남아요. 보관소를 호스팅하는 동안에는 호스트만 보관소에 쓸
수 있고, 앱, `aidectl`, 플러그인은 모두 호스트를 거쳐요.

## 호스팅 시작하기

이 컴퓨터에 있는 보관소(로컬 모드)를 호스팅할 수 있어요. iPhone은 호스팅할 수 없고, 대신 호스트에 연결해요.

<Steps>

1. 호스팅할 보관소를 열어요.
2. 설정을 열어요. Mac에서는 <strong>설정 › 노트 › 이 보관소 호스팅…</strong>으로, Linux에서는
   <strong>설정 › 일반 › 노트 › 이 보관소 호스팅…</strong>으로 가요.
3. **호스팅 시작**을 눌러요. 서버와 데이터베이스가 시작되는 동안 창에 <strong>호스트 시작 중…</strong>이 표시돼요. 처음
   시작할 때 가장 오래 걸려요.

</Steps>

실행되면 설정의 **노트** 자리에 **호스트** 그룹이 나타나요. 여기에는 다음이 있어요.

- **보관소**: 제공 중인 폴더예요.
- **실행 중**: 호스트가 응답하는 소켓이에요.
- **로그**: 호스트의 로그 파일이에요. 문제가 생기면 열어 보세요.
- **네트워크로 연결할 기기…**, **로그인한 동안 계속 실행**, **백업…**, **호스팅 중지…**: 이 페이지 아래에서
  다뤄요.
- **보관소**, **최근 삭제된 항목**, **노트에서 제외**: 로컬 모드와 같아요.

보관소의 정리가 끝나지 않았다면 호스팅이 시작되지 않아요. 먼저 정리를 마치세요.

### 호스트를 실행할 수 없을 때

호스트가 시작되지 않으면 창에 이유와 함께 **호스트를 실행할 수 없어요**가 표시돼요. **다시 시도**를 누르거나,
<strong>보관소를 현재 상태로 돌려주기…</strong>를 눌러 호스팅을 멈추고 폴더를 다시 일반 로컬 보관소로 여세요. 돌려줘도
노트는 그대로예요. 호스트가 끝내지 못한 일(나를 기다리는 정리 등)은 버려져요.

## 호스트가 데이터를 두는 곳

보관소의 노트는 보관소 폴더에 남아요. 호스트가 보관하는 나머지는 보관소마다 보관소 ID 이름을 딴 폴더에 있어요.

| 시스템 | 폴더                                                    |
| ------ | ------------------------------------------------------- |
| macOS  | `~/Library/Application Support/AIDE/hosts/<vault id>/`  |
| Linux  | `~/.local/share/aide/hosts/<vault id>/`(또는 `$XDG_DATA_HOME/aide/hosts/<vault id>/`) |

설정의 **로그** 행이 이 폴더의 `host.log`를 가리켜요. 폴더 안에는 데이터베이스(`pg/`), 플러그인 자체
상태(`plugins/`), 첨부 파일 상태(`files/`), 그리고 만들었다면 로컬 플러그인 설정(`plugins.json`)이 있어요.

호스트의 봉인 키는 이 폴더와 따로 보관해요. 호스트가 저장하는 AI 키와 플러그인 비밀 값을 암호화하는 키예요.
Mac에서는 키체인에 있어요. Linux에서는 키링(GNOME Keyring, KeePassXC 등)에 있고, 잠금 해제된 키링을 찾지
못하면 비공개 파일에 있어요. 예전에 호스팅한 적 있는 보관소에는 AIDE가 새 키를 만들지 않아요. 이전 키 없이는
저장된 자격 증명을 읽을 수 없기 때문이에요.

## 로그인한 동안 계속 실행

기본으로 호스트는 AIDE가 열려 있는 동안 돌아가고, 앱을 종료하면 멈춰요. 앱 없이도 계속 돌리려면 호스트
그룹에서 **로그인한 동안 계속 실행**을 켜세요.

- **macOS**: LaunchAgent(`com.marshallku.aide.host.<vault id>`)가 로그인할 때부터 호스트를 실행하고, 비정상
  종료되면 다시 시작해요.
- **Linux**: systemd 사용자 서비스(`aide-host-<vault id>.service`)가 같은 일을 해요. 출력은
  `journalctl --user -u aide-host-<vault id>.service`로 볼 수 있어요.

이 설정을 바꾸면 호스트가 한 번 다시 시작돼요. 그 뒤로는 앱을 열 때 실행 중인 호스트에 붙어요. 이 설정을
켜 두면 예약된 플러그인(아침 브리핑, 저녁 정리, 밤마다 하는 지난 작업 정리)이 AIDE를 닫아도 돌아가요. 로그인해 있고
컴퓨터가 깨어 있는 동안에만요.

## 다른 기기 들이기

휴대폰과 다른 컴퓨터에서 네트워크로 호스팅한 보관소를 쓸 수 있어요. 네트워크 접근은 직접 켜기 전까지 꺼져
있고, 호스트에서 승인한 기기만 들어올 수 있어요.

<Aside type="note">
네트워크 접근에는 키체인(Mac)이나 잠금 해제된 키링(Linux)에 호스트 키가 있어야 해요. 파일에 두면 호스트
데이터와 함께 키가 복사될 수 있어서 AIDE가 거부해요. Linux에서는 키링을 시작하고 AIDE를 다시 여세요.
</Aside>

<Steps>

1. 호스트 그룹에서 <strong>네트워크로 연결할 기기…</strong>를 열어요.
2. **주소** 아래에서 기기가 이 컴퓨터에 연결할 주소를 골라요. AIDE는 이 컴퓨터의 Tailscale 주소를 먼저,
   그다음 로컬 네트워크(LAN) 주소를 8443 포트로 보여 줘요. 어디서든 호스트에 연결하려면 Tailscale 주소를,
   집 네트워크에서만 쓰려면 LAN 주소를 고르세요.
3. **기기 접근 허용**을 눌러요. 호스트가 다시 시작되고 그 주소 하나에서만 연결을 기다려요. 그러면 **지금**에
   주소별 상태와 호스트 키 지문이 표시돼요.
4. <strong>기기 추가…</strong>를 눌러요. AIDE가 페어링 링크(`aide://pair-host?…`)를 보여 줘요. 5분 동안, 기기 한 대에만
   쓸 수 있어요.
5. 다른 기기의 **시작하기** 화면(열 보관소나 서버가 아직 없을 때 AIDE가 보여 주는 화면)에서
   **호스트에 연결**을 찾아 **페어링 링크**에 링크를 붙여 넣고 **호스트에 연결**을 눌러요. iPhone에서는 링크를
   열어도 돼요. 그러면 기기에 이름과 키 지문이 표시돼요.
6. 호스트로 돌아오면 **페어링 요청 중** 아래에 기기가 나타나요. 지문이 기기에 표시된 것과 같은지 확인하고
   **승인**을 눌러요. **거부**를 누르면 돌려보내요.

</Steps>

호스트는 고른 주소에서만 연결을 기다려요. 공유기의 포트를 열지 않고, 모든 인터페이스로 대신 연결을 기다리는
일도 없어요. 주소가 사라지면(Tailscale 연결이 끊기거나 Wi-Fi가 바뀌면) 다시 생길 때까지 기다려요. 기기를 더
받지 않으려면 <strong>네트워크로 연결할 기기…</strong>를 열고 **끄기**를 누르세요.

### 연결을 보호하는 방법

- **양방향 TLS 1.3.** 호스트에는 봉인 키에서 만든 P-256 키가 있어요. 페어링 링크에 그 키의 지문이 들어 있고,
  기기는 이 지문을 고정해요. 다른 키를 내미는 호스트는 거부돼요.
- **기기마다 자기 키가 있어요.** 기기가 페어링할 때 키를 만들고(iPhone에서는 Secure Enclave가 있으면 그
  안에서), 연결할 때마다 호스트가 발급한 인증서를 보여 줘요. 승인된 인증서가 없는 연결은 서버에 닿기 전, TLS
  핸드셰이크 중에 끊겨요.
- **페어링은 따로예요.** <strong>기기 추가…</strong>가 열려 있는 동안에는 인증서 없는 연결 몇 개가 페어링 경로에만 닿을 수
  있고, 다른 곳에는 닿지 못해요.
- **접근 권한 해제는 즉시 적용돼요.** 해제한 기기의 열린 연결은 바로 닫혀요.

네트워크로 연결한 기기는 노트와 할 일을 읽고 바꾸고, 피드를 읽고, 플러그인 탭을 쓰고, AI와 정리를 실행하고,
알림도 따로 받을 수 있어요. 기기 페어링, 설정이나 AI 키 변경, 플러그인 켜고 끄기, MCP 접근은 할 수 없어요.
이런 일은 호스트에서 직접 해요.

### 기기 제거하기

Linux에서는 호스트의 **설정 › 기기**에 페어링한 기기가 나오고, 기기마다 옆에 **접근 권한 해제**가 있어요. Mac
앱은 호스팅하는 동안 기기 목록을 보여 주지 않아요. Mac에서 모든 기기를 막으려면 **네트워크로 연결할 기기…**
아래의 **끄기**를 누르세요.

기기 자체에서 **설정 › 기기 › 로그아웃**을 누르면 그 기기에서만 호스트 정보를 지워요. 기기를 완전히 막으려면
호스트에서 제거하세요.

## 호스트의 플러그인

호스트는 모든 내장 서버 플러그인을 등록하고, 각 플러그인은 직접 켜기 전까지 꺼져 있어요. 플러그인마다 하는
일은 [플러그인의 동작 방식](/ko/docs/plugins/overview/)을 보세요.

<Steps>

1. 설정을 열어요. Mac에서는 플러그인이 **코어 플러그인** 아래에 나와요. Linux에서는 **코어 플러그인** 페이지의
   **서버 플러그인** 아래에 있어요.
2. 플러그인을 열고 **활성화됨**을 켜요(Linux에서는 행의 스위치를 켜요).
3. 설정을 채워요. 설정은 바꾸는 즉시 저장되고, 플러그인은 1분 안에 반영해요.

</Steps>

플러그인은 각자 필요한 노트와 토픽으로 제한된 토큰으로 호스트와 통신해요. 내장 플러그인은 내 컴퓨터에서 내
사용자로 돌아가기 때문에, 호스트는 나를 믿는 만큼 내장 플러그인을 믿어요. 토큰은 실수가 건드릴 수 있는 범위를
제한할 뿐, 악의적인 코드가 할 수 있는 일을 막아 주지는 않아요.

### 로컬 플러그인 설정 파일

일부 플러그인 설정은 절대 앱에서 오지 않아요. docs-sync의 git `remote`와 `clone`, Google의 `credentials`와
`tokenFile`처럼 이 컴퓨터의 자격 증명과 경로가 그래요. 이런 값은 호스트 데이터 폴더(`host.log` 옆)의
`plugins.json`에 넣으세요.

```json
{
    "timezone": "Asia/Seoul",
    "plugins": {
        "docs-sync": { "remote": "git@github.com:you/notes.git", "branch": "main" }
    }
}
```

- `timezone`은 선택 사항이에요. 없으면 플러그인이 이 컴퓨터의 시간대를 써요.
- `plugins` 아래의 각 키는 플러그인 ID이고, 그 값은 해당 플러그인의 로컬 블록이에요. 플러그인이 읽는 키는 이
  매뉴얼의 플러그인 페이지에 나와 있어요.
- 플러그인 설정에 선언된 키는 앱에서 바꾼 값이 파일보다 우선해요. 나머지는 파일 값을 써요. `token`, `remote`,
  `clone`, `credentials`, `tokenFile`, `healthDir`, `stateDir`는 항상 파일에서만 와요.
- 호스트는 시작할 때 파일을 읽어요. 파일을 바꾼 뒤에는 호스트를 다시 시작하세요. AIDE를 종료했다가 다시
  열거나(**로그인한 동안 계속 실행**이 꺼져 있을 때), 그 설정을 껐다가 다시 켜면 돼요.
  <Badge text="다음 릴리스" /> 호스트가 실행 중에도 파일을 읽어요. 파일을 만들거나, 바꾸거나, 지우면 호스트를
  다시 시작하지 않아도 1분쯤 안에 그 내용으로 플러그인이 다시 시작돼요.
- <Badge text="다음 릴리스" /> 읽을 수 없는 파일이나 플러그인 블록은 `host.log`에 경고를 남기고 빼요. 다른
  플러그인은 계속 실행돼요. 이번 릴리스까지는 둘 다 모든 플러그인을 멈췄어요.

## 호스팅 중지하기

호스트 그룹에서 <strong>호스팅 중지…</strong>를 열고 **호스팅 중지**를 눌러요. AIDE가 쓰던 내용을 저장하고, 호스트를
멈추고, 보관소를 이 컴퓨터 전용 노트로 열어요. 다시 호스팅하기 전까지 서버 플러그인, 피드, Claude는 멈춰요.
호스트는 그때를 위해 데이터와 설정을 간직해 둬요.

호스트에 보관소의 끝나지 않은 작업(나를 기다리는 정리, 아직 전달하지 않은 변경)이 남아 있으면 호스팅 중지가
거부되고 이유를 알려 줘요. **무시하고 중지**를 누르면 멈추고 그 작업을 버려요.

## 제한 사항

- **Mac과 Linux에서만 돼요.** iPhone은 호스트에 연결할 수는 있지만 호스트가 될 수는 없어요.
- **컴퓨터가 켜져 있어야 해요.** 호스트는 로그인해 있고 컴퓨터가 깨어 있는 동안에만 돌아가요. 컴퓨터가 잠자는
  동안에는 밖에 있는 기기가 노트에 닿을 수 없어요.
- **iPhone 푸시 알림이 없어요.** 호스트에는 Apple 푸시 키가 없어서, 연결된 iPhone은 푸시 알림을 받지 못해요.
  Mac과 Linux 앱은 직접 알림을 가져와요.
- **보관소 하나에 호스트 하나예요.** 다른 AIDE나 같은 폴더를 가리키는 서버는 보관소가 이미 사용 중인 걸
  알게 돼요.
- **호스팅한 보관소를 Syncthing, iCloud, git으로 컴퓨터끼리 동기화하지 마세요.** 한 번에 한 프로그램만 보관소에
  쓸 수 있어요. 위의 네트워크 접근을 쓰거나, git 사본이 필요하면 [docs-sync](/ko/docs/plugins/docs-sync/)
  플러그인을 쓰세요.
- **호스트 키가 새로 생기면 다시 페어링해야 해요.** 호스트 키를 잃어버리거나 백업에서 보관소를 복원하면 모든
  기기가 다시 페어링해요.
