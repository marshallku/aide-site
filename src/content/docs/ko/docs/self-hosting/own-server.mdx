전용 서버는 [데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)가 돌리는 것과 같은 AIDE 서버를 항상 켜져
있는 기기에서 돌리는 거예요. 데스크톱이 깨어 있든 아니든 노트, 피드, 서버 플러그인이 그대로 있고, iPhone은
데스크톱 없이도 AIDE를 쓸 수 있어요.

<Aside type="caution" title="아직 내려받을 수 없어요">
서버의 컨테이너 이미지는 아직 공개 배포되지 않아서, 지금은 공개 릴리스로 내 서버를 운영할 수 없어요. 대신
[데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)를 쓰세요. 같은 서버, 데이터베이스, 플러그인을 Mac이나
Linux 컴퓨터에서 돌려요. 이 페이지는 이미지가 나왔을 때를 위해 서버에 필요한 것을 설명해요.
</Aside>

## 데스크톱 호스트보다 나은 점

- **항상 켜져 있어요.** 컴퓨터가 꺼져 있어도 예약된 플러그인이 제시간에 돌고, 피드가 이벤트를 받아요.
- **iPhone만으로도 돼요.** 휴대폰이 데스크톱을 거치지 않고 서버와 직접 페어링해요.
- **iPhone으로 푸시를 보내요.** 서버가 Apple 푸시 서비스에 닿을 방법이 있을 때요([푸시 알림](#푸시-알림) 참고).
  데스크톱 호스트는 iPhone으로 푸시를 보낼 수 없어요.
- **Claude 앱을 위한 원격 MCP.** HTTPS로 닿을 수 있는 서버는 Claude 앱의 사용자 지정 커넥터 역할을 할 수
  있어요. [MCP와 Claude 앱](/ko/docs/developers/mcp/)을 보세요.

## 구성 요소

| 구성 요소             | 하는 일                                                                      |
| --------------------- | ---------------------------------------------------------------------------- |
| AIDE 서버(Go)         | 기기, 노트, 할 일, 피드와 분류, AI 호출, 정리, 푸시, MCP                     |
| PostgreSQL 17         | 이벤트 로그, 설정, 페어링한 기기, 플러그인 데이터                            |
| 노트 폴더             | Markdown 파일로 된 노트. 내 컴퓨터의 보관소와 같은 형식이에요               |
| 플러그인 러너         | 내장 서버 플러그인. 각자 권한이 제한된 토큰을 가져요                         |

`AIDE_NOTES_DIR`을 설정하지 않으면 서버는 노트를 `<AIDE_DATA_DIR>/notes`에 파일로 둬요. 그래서 이 폴더는
AIDE나 다른 Markdown 편집기로 열 수 있는 보관소예요. 한 번에 한 프로그램만 이 폴더에 쓸 수 있어요.

플러그인 러너는 서버 옆에서 돌면서 HTTP로 서버와 통신해요. 플러그인마다 `aide plugin-token`으로 발급한
토큰을 써요. [서버 플러그인 만들기](/ko/docs/developers/server-plugins/)를 보세요.

## HTTPS로 접속하기

서버는 일반 HTTP(8080 포트)로 연결을 기다리고, HTTPS는 앞단에 다른 무언가를 둔다고 가정해요. 앱은 같은
컴퓨터의 서버가 아니면 HTTPS를 요구해요. 다음 중 무엇이든 돼요.

- **Tailscale**(비공개, 가장 간단): `tailscale serve --bg 8080`을 실행하면
  `https://<machine>.<tailnet>.ts.net`이 생기고, tailnet 안에서만 접속할 수 있어요.
- **Cloudflare Tunnel**: `cloudflared tunnel --url http://127.0.0.1:8080` 또는 이름 있는 터널.
- 공개된 기기의 **Caddy**: `reverse_proxy 127.0.0.1:8080`.

`AIDE_PUBLIC_URL`을 HTTPS 주소로 설정하세요. 그러면 페어링할 때 앱에 값을 채워 주는 링크를 보여 줄 수 있어요.
프록시가 다른 기기에서 돌면서 클라이언트 주소를 전달한다면 그 프록시를 `AIDE_TRUSTED_PROXIES`에 넣으세요.
페어링은 클라이언트 주소마다 실패 횟수를 제한하거든요.

## 기기 페어링하기

서버에서 `aide pair`를 실행해요. 한 번만 쓸 수 있고 10분 뒤에 만료되는 페어링 코드(`XXXXX-XXXXX`)를 보여
줘요. `AIDE_PUBLIC_URL`이 설정되어 있으면 `aide://pair?server=…&code=…` 링크도 함께 보여 줘요.

앱의 **시작하기** 화면에서 **내 AIDE 서버** 아래에 **서버** 주소와 **페어링 코드**를 입력하고 **연결**을
눌러요. 링크를 열면 두 칸이 모두 채워져요. **연결**은 직접 눌러야 해요.

이미 연결된 기기에서 다음 코드를 만들 수도 있어요. **설정 › 기기 › 다른 기기 페어링**으로 가세요. 같은 화면에
모든 기기가 **접근 권한 해제**와 함께 나와요.

열린 코드는 한 번에 최대 5개이고, 10번 실패한 클라이언트 주소는 10분 동안 차단돼요. 기기를 모두 잃어버렸다면
서버에서 `aide pair`를 다시 실행하세요. 서버에 접근할 수 있다는 것 자체가 주인이라는 증거예요.

## 푸시 알림

서버는 내가 챙겨야 할 이벤트를 푸시해요. **조치 필요**로 분류된 모든 이벤트, 그리고 끄지 않는 한 **알아둘
내용**도요. Mac과 Linux 앱은 서버에서 직접 알림을 가져오니 따로 필요한 게 없어요. iPhone에는 Apple 푸시
서비스가 필요하고, 서버는 두 가지 방법 중 하나로 여기에 닿아요.

- **APNs 키**(`AIDE_APNS_KEY_FILE`, `AIDE_APNS_KEY_ID`, `AIDE_APNS_TEAM_ID`). 키는 앱에 서명하는 Apple
  개발자 팀에서만 동작해요. 그래서 내 팀으로 직접 빌드한 iPhone 앱을 위한 방법이에요.
- **푸시 릴레이**(`AIDE_PUSH_RELAY_URL`). 배포된 앱용 키를 가지고 있어요. 릴레이는 TLS로 알림마다 제목과
  본문을 보지만 어느 것도 저장하지 않아요. 아직 공개된 릴레이가 없어서, 지금은 배포된 앱으로 내 서버의 iPhone
  푸시를 받을 수 없어요.

`AIDE_PUSH_RELAY_URL=off`로 두거나 비워 두면 iPhone 푸시가 꺼져요. 데스크톱 알림을 비롯한 나머지는 모두 계속
동작해요.

## 환경 변수

직접 설정하게 될 변수들이에요. 형식이 잘못된 변수가 있으면 서버가 시작을 거부하고 어느 변수인지 알려 줘요.

| 변수                          | 기본값                      | 하는 일                                                                      |
| ----------------------------- | --------------------------- | ---------------------------------------------------------------------------- |
| `AIDE_DATABASE_URL`           | 로컬 개발용 데이터베이스    | PostgreSQL 연결 URL                                                          |
| `AIDE_DATA_DIR`               | (없음)                      | 노트(`notes/` 안)와 첨부 파일을 둘 절대 경로 폴더. 새 서버에는 꼭 필요해요  |
| `AIDE_NOTES_DIR`              | `<AIDE_DATA_DIR>/notes`     | 노트를 다른 절대 경로 폴더에 둬요. `AIDE_DATA_DIR`과 `AIDE_USER_ID`가 필요해요 |
| `AIDE_SECRET_KEY`             | (없음)                      | base64로 된 무작위 32바이트. 저장된 AI 키, 게이트웨이 토큰, 플러그인 비밀 값을 봉인해요. 없으면 서버가 이 값들을 저장할 수 없어요 |
| `AIDE_PUBLISH_TOKEN`          | (필수)                      | 외부 발행자가 `POST /events`에 보내는 토큰. [피드에 이벤트 보내기](/ko/docs/developers/events/)를 보세요 |
| `AIDE_PUBLIC_URL`             | (없음)                      | 기기가 쓰는 HTTPS 주소. 설정하면 `aide pair`가 링크를 보여 줘요             |
| `AIDE_TRUSTED_PROXIES`        | (없음)                      | `X-Forwarded-For`를 설정할 수 있는 IP나 CIDR, 쉼표로 구분                    |
| `AIDE_ADDR`                   | `:8080`                     | 서버가 연결을 기다리는 주소                                                  |
| `AIDE_TIMEZONE`               | 기기의 시간대               | `Asia/Seoul` 같은 IANA 이름의 시간대. 템플릿과 일정의 "오늘"에 써요          |
| `ANTHROPIC_API_KEY`           | (없음)                      | 서버 전체용 Anthropic 키. 설정 › AI에 내 키를 설정하지 않았을 때 써요        |
| `AIDE_AI_MODEL`               | `claude-opus-5-5`           | 서버 전체용 키에 쓰는 모델                                                   |
| `AIDE_AI_DAILY_LIMIT`         | `200`                       | 하루에 허용하는 AI 호출 수                                                   |
| `AIDE_ALLOW_PRIVATE_GATEWAYS` | `false`                     | `http://`, LAN, Tailscale 주소의 게이트웨이를 허용해요. 사용자가 나뿐이라면 안전해요 |
| `AIDE_GATEWAY_TIMEOUT`        | `150s`                      | 게이트웨이 호출에 걸릴 수 있는 최대 시간                                     |
| `AIDE_APNS_KEY_FILE`, `AIDE_APNS_KEY_ID`, `AIDE_APNS_TEAM_ID` | (없음) | iPhone 푸시용 APNs 인증 키(`.p8`)와 그 ID                     |
| `AIDE_PUSH_RELAY_URL`         | (없음)                      | APNs 키 없이 쓸 푸시 릴레이. `off`면 iPhone 푸시가 꺼져요                    |

`AIDE_SECRET_KEY`는 백업과 함께 보관하세요. 잃어버리면 저장된 AI 키, 게이트웨이 토큰, 플러그인 비밀 값(예:
Slack 토큰)을 읽을 수 없게 되고, 다시 입력해야 해요. [백업과 복원](/ko/docs/self-hosting/backups/)을 보세요.
