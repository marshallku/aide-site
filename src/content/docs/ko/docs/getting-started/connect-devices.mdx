컴퓨터 한 대가 보관소를 호스팅하거나 내 서버를 운영하고 있다면, 쓰고 있는 다른 기기들을 거기에 페어링해서
같은 노트로 작업할 수 있어요. 페어링은 기기마다 한 번만 하면 돼요. 그다음부터는 기기가 알아서 연결해요.

## 데스크톱 호스트와 페어링하기

데스크톱 호스트는 내가 고른 네트워크로만, 그리고 호스팅하는 컴퓨터에서 승인한 기기만 받아요. 기기는 페어링할
때 자기 키를 만들고, 그 뒤로는 인증서로 식별돼요. 여기저기 복사할 비밀번호나 토큰은 없어요.

### 시작하기 전에

- 보관소가 Mac이나 Linux 컴퓨터에서 호스팅되고 있어야 해요([AIDE 실행 방식](/ko/docs/getting-started/ways-to-run/#로컬-보관소-호스팅하기)).
- 호스트 키는 시스템의 보안 저장소에 보관돼요. Mac에서는 키체인, Linux에서는 잠금 해제된 키링(GNOME Keyring,
  KeePassXC…)이에요. 보안 저장소가 없으면 **네트워크로 연결할 기기**에 "키체인에 호스트 키가 있어야 해요"라고
  표시되고 꺼진 채로 남아요. 파일에 둔 키는 호스트 데이터와 함께 복사될 수 있기 때문이에요. Linux에서는 키링을
  시작하고 AIDE를 다시 여세요.
- 다른 기기가 호스팅하는 컴퓨터에 닿을 수 있어야 해요. 두 기기 모두 [Tailscale](https://tailscale.com/)을
  쓰면 어디서든 연결돼요. 같은 Wi-Fi나 LAN에 있다면 집에서는 로컬 주소로 연결돼요.

### 기기 들이기

<Steps>

1. 호스팅하는 컴퓨터에서 호스트 설정을 열어요. Mac에서는 **설정 › 호스트**, Linux에서는 **설정 › 일반**의
   **호스트** 그룹이에요. <strong>네트워크로 연결할 기기…</strong>를 골라요.
2. **기기에서 이 Mac에 연결할 주소**(Linux에서는 **기기에서 이 컴퓨터에 연결할 주소**) 아래에서 **주소**를
   골라요. 목록에는 이 컴퓨터의 Tailscale 주소가 먼저, 그다음 LAN 주소가 나와요. 호스트는 기본으로 8443
   포트에서 연결을 기다려요.
3. **기기 접근 허용**을 눌러요. 호스트가 다시 시작되고, **지금**에 **기기 연결 허용 중**과 함께 주소별 상태와
   호스트 키의 지문이 표시돼요.

</Steps>

**끄기**를 누르면 네트워크로 기기를 더 이상 받지 않아요. 컴퓨터에 Tailscale 주소도 LAN 주소도 없으면
페이지에 그렇게 표시되고 고를 주소가 없어요.

### 기기 추가하기

<Steps>

1. 호스팅하는 컴퓨터의 **네트워크로 연결할 기기**에서 <strong>기기 추가…</strong>를 눌러요. AIDE가 `aide://pair-host?`로
   시작하는 **링크**를 보여 줘요. 이 링크는 5분 동안, 기기 한 대에만 쓸 수 있어요.
2. 다른 기기에서 AIDE의 **시작하기** 화면을 열고, **호스트에 연결** 아래의 **페어링 링크**에 링크를 붙여
   넣은 다음 **호스트에 연결**을 눌러요. iPhone에서는 링크를 열면 칸이 자동으로 채워져요.
3. 기기에 이름과 키 지문이 표시되고, 호스트에도 **페어링 요청 중** 아래에 지문과 함께 기기가 나타나요. 두
   지문이 같은지 확인하세요.
4. 호스트에서 **승인**("승인됨: 연결하고 있어요") 또는 **거부**를 눌러요.

</Steps>

그 뒤로는 연결할 때마다 호스트 키를 확인해요. 그래서 기기가 내 호스트인 척하는 다른 기기와 통신할 일은
없어요. 기기 인증서는 2년 동안 유효하고, 만료 60일 전부터는 연결할 때 저절로 갱신돼요. 이미 만료된 기기는
다시 페어링해야 해요.

<Aside>
링크는 QR 코드가 아니라 텍스트로 보여 줘요. 원하는 방법(AirDrop, 다른 앱의 메모, 나에게 보내는 메시지)으로
다른 기기에 보내세요. 5분이 지나거나 기기 한 대가 쓰고 나면 쓸 수 없어요.
</Aside>

### 페어링한 기기가 할 수 있는 것

호스트에 연결된 기기는 노트, 할 일, 데일리 노트, 검색, 피드, 플러그인 탭, AI, 정리를 쓸 수 있고, 알림도
따로 받아요. 호스트 자체를 바꾸는 일은 모두 호스팅하는 컴퓨터에서만 해요. 페어링, 기기 목록, AI 키, 플러그인
설정, 피드 구독, MCP가 그래요.

기기 연결을 끊으려면 그 기기의 **설정 › 기기**에서 **로그아웃**을 누르세요. 이 기기에서 호스트 정보를
지워요. 기기 인증서는 호스트에서 제거할 때까지 유효해요.

## 내 서버와 페어링하기

서버는 한 번만 쓸 수 있는 코드로 기기를 페어링해요. 페어링하려면 서버 주소가 필요하고, 내 컴퓨터에서 도는
서버가 아니라면 반드시 HTTPS여야 해요.

<Steps>

1. 페어링 코드를 받아요.
    - 서버에서 `aide pair`를 실행하거나,
    - 이미 연결된 기기에서 **설정 › 기기**를 열고 **다른 기기 페어링**을 눌러요.
2. 새 기기의 **시작하기 › 내 AIDE 서버**(Linux에서는 **서버에 연결**)에서 `https://aide.my-tailnet.ts.net`
   같은 **서버** 주소와 **페어링 코드**를 입력해요.
3. **연결**을 눌러요.

</Steps>

코드는 `XXXXX-XXXXX` 형태이고, 한 번만 쓸 수 있으며 10분 뒤에 만료돼요. 쓰지 않은 코드는 한 번에 최대 다섯
개까지 있을 수 있어요. 한 주소에서 10분 안에 틀린 코드를 10번 입력하면, 서버가 한동안 그 주소의 시도를
거부해요.

서버가 자기 공개 주소(`AIDE_PUBLIC_URL`)를 알고 있으면 `aide pair`가 `aide://pair?server=…&code=…` 링크도
함께 보여 줘요. 기기에서 이 링크를 열면 두 칸이 모두 채워져요.

서버 앞에 Tailscale, Cloudflare Tunnel, Caddy로 HTTPS를 두는 방법은 [내 서버 운영하기](/ko/docs/self-hosting/own-server/)에서
다뤄요.

## 기기 관리하기

### 내 서버에서

서버에 연결된 기기의 **설정 › 기기**에는 페어링한 모든 기기가 마지막으로 접속한 시각과 함께 나와요. 지금
쓰는 기기에는 **이 기기**라고 표시돼요.

- 다른 기기 옆의 **접근 권한 해제**를 누르면 그 기기를 차단해요. 다음 요청이 실패하고 로그아웃돼요.
- **로그아웃**은 먼저 이 기기의 접근 권한을 해제한 뒤 서버 정보를 지워요. 초안은 다시 연결할 때를 위해
  기기에 남아요. 서버에 닿을 수 없으면 **접근 권한 해제 없이 로그아웃**이 나타나요. 이걸 누르면 기기는 서버
  정보를 지우지만, 다른 기기에서 해제하기 전까지 권한은 그대로 남아요.

### 데스크톱 호스트에서

기기는 페어링한 기기가 아니라 호스팅하는 컴퓨터에서 관리해요. 페어링한 기기의 **설정 › 기기**에서도 목록은
보이지만, 접근 권한 해제는 호스트에서 해요. <Badge text="다음 릴리스" /> 페어링한 기기의 목록에는 해제 버튼이
없고, 목록 아래(Linux에서는 각 행의 도움말)에 "기기 권한은 노트를 호스팅하는 컴퓨터에서 해제해요."라고 나와요.

- **Linux 호스트:** **설정 › 기기**에 호스트와 페어링한 기기가 나오고, 기기마다 **접근 권한 해제**가 있어요.
  해제한 기기는 바로 차단되고 열려 있던 연결도 닫혀요.
- **Mac 호스트:** 이번 릴리스에는 호스팅하는 Mac에 기기 목록이 없어요. 페어링한 기기를 모두 막으려면
  **네트워크로 연결할 기기**에서 **끄기**를 누르세요. 그러면 호스트가 네트워크로 어떤 기기도 받지 않아요.
  <Badge text="다음 릴리스" /> Linux처럼 **설정 › 호스트 › 기기**에 기기와 **접근 권한 해제**가 나와요.

백업에서 호스트를 복원하면 모든 기기의 접근 권한이 해제돼요. 기기들은 복원한 호스트와 다시 페어링해요.

### 기기를 잃어버렸다면

- **내 서버를 쓴다면:** 연결된 다른 기기의 **설정 › 기기**에서 접근 권한을 해제하세요. 기기를 모두
  잃어버렸다면 서버에서 `aide pair`를 실행하고 그 코드로 새 기기를 페어링하세요. 서버 기기에 접근할 수 있다는
  것 자체가 주인이라는 증거예요.
- **데스크톱 호스트를 쓴다면:** 위에서 설명한 대로 호스팅하는 컴퓨터에서 해제하세요.

## 휴대폰으로 알림 받기

서버는 **조치 필요**로 분류된 모든 피드 이벤트에 알림을 보내요. **알아둘 내용** 이벤트도 끄지 않는 한 알림을
보내요. 끄려면 **설정 › 알림 › “알아둘 내용”도 푸시 알림**(Linux에서는 **“알아둘 내용”도 알림**)을 끄세요.
나머지는 피드에서 기다려요. 플러그인이 이벤트 하나를 항상 알리거나 절대 알리지 않도록 지정할 수도 있어요.

- **Mac과 Linux**는 서버나 호스트에서 직접 알림을 가져와요. 따로 필요한 건 없어요.
- **iPhone** 알림은 Apple의 푸시 서비스를 거쳐요. 서버는 푸시 릴레이(앱을 직접 빌드한 경우에는 자체 APNs
  키)를 통해 이 서비스에 닿아요. 아직 공개된 푸시 릴레이가 없어서 지금은 iPhone에 푸시 알림이 오지 않아요.
  이벤트는 앱을 열면 피드에 있어요.

이벤트를 분류하는 방식은 [피드](/ko/docs/guides/feed/)를 보세요.
