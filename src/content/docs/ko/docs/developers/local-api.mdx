Mac이나 Linux의 AIDE 앱은 보관소를 열어 두는 동안 그 보관소의 노트를 Unix 소켓으로 제공해요. 같은 컴퓨터에서 실행하는 프로그램이라면 서버도 토큰도 없이 평범한 HTTP로 노트를 읽고 쓸 수 있고, 서버가 주는 것과 같은 응답을 받아요. [`aidectl`](/ko/docs/developers/aidectl/)도 이 위에서 만들어졌어요. 이 페이지는 직접 호출하고 싶을 때를 위한 거예요.

## 누가 연결할 수 있나요

- 같은 컴퓨터에서 **내 사용자 계정**으로 실행되는 프로그램만요. 앱은 연결마다 사용자를 확인하고 다른 사용자의 연결은 닫아요.
- 소켓 폴더는 `0700` 모드로 만들어지고, 링크가 아닌 실제 폴더여야 하며, 내 소유이고 다른 누구도 접근할 수 없어야 해요. 그렇지 않으면 앱은 제공을 거부하고 `aidectl`은 연결을 거부해요.
- 그 밖의 인증은 없어요. 소켓에 닿는 사람은 누구든 보관소 소유자로 동작해요.

iPhone에는 로컬 API가 없어요.

## 소켓 위치

`XDG_RUNTIME_DIR`이 설정돼 있으면(대부분의 Linux 데스크톱) 폴더는 `$XDG_RUNTIME_DIR/aide/`이고, 아니면 `/tmp/aide-<uid>/aide/`예요(macOS에는 런타임 폴더가 없어요). 열린 보관소마다 소켓이 하나씩 있고, 이름은 `<32 hex digits>.sock`이에요. 보관소 폴더의 실제 경로와 장치 번호, inode 번호로 정해져요. 다른 폴더에 있는 보관소 사본은 자기 소켓을 따로 가져요.

맞는 소켓을 찾는 가장 쉬운 방법은 소켓마다 어느 폴더를 제공하는지 물어보는 거예요.

```sh
dir="${XDG_RUNTIME_DIR:-/tmp/aide-$(id -u)}/aide"
for s in "$dir"/*.sock; do
    printf '%s  ' "$s"
    curl -s --unix-socket "$s" http://aide/me
    echo
done
```

```json
{"mode": "local", "vaultId": "8c4e…", "root": "/Users/you/Notes", "dev": 16777232, "ino": 2918843}
```

URL의 호스트 이름은 상관없어요. 이 페이지에서는 `http://aide/`를 써요. `root`가 내 보관소 폴더(링크를 따라간 경로)인 소켓을 쓰세요.

소켓은 앱이 보관소를 열어 두는 동안에만 있어요. 보관소를 닫거나 앱을 종료하면 사라져요.

## 데스크톱 호스트의 소켓

[데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)가 보관소를 제공하면, 그 소켓은 같은 폴더에 `host-<same name>.sock`이라는 이름으로 있어요. 이 소켓은 아래 경로 대신 서버 API 전체를 제공하고, 역시 토큰 없이 나로 동작하며, `GET /me`는 제공하는 폴더를 `"host"` 아래에 알려 줘요. `aidectl`은 호스트의 소켓을 먼저 시도하고, 그다음 앱의 소켓, 마지막으로 폴더를 직접 열어요.

## 경로

AIDE 서버의 노트 경로와 입력, JSON 형태, 상태 코드, 오류가 같아요.

| 경로 | 하는 일 |
| --- | --- |
| `GET /me` | 이 소켓이 제공하는 보관소: `mode`(`local`), `vaultId`, `root`, `dev`, `ino` |
| `GET /notes?kind=&prefix=` | `{"notes": [Note]}`, 최근에 바뀐 순서. `kind=scratch`는 스크래치 노트를 나열해요 |
| `GET /notes/lookup?path=` | 경로나 미러링하는 파일(`topics/x.md`)로 찾은 노트. 노트 경로가 우선해요 |
| `GET /notes/{id}` | 살아 있는 노트 하나 |
| `POST /notes` | `{path?, body?, title?, sourcePath?, template?, vars?}` → `201` Note, `409 path_taken` |
| `PUT /notes/{id}` | `{version, body}` → Note. 그사이 노트가 바뀌었으면 `409 version_conflict`. 여기서는 `path`, `title`, `sourcePath`를 바꿀 수 없어요(`422 unsupported`) |
| `DELETE /notes/{id}` | `{version}` → `204`. 노트는 삭제되지 않고 보관돼요 |
| `POST /notes/{id}/append` | `{text, heading?, createHeading?, ifAbsent?}` → Note와 `appended`, `404 heading_not_found` |
| `POST /notes/{id}/todos/{line}/toggle` | `{version}` → Note. 그 줄이 할 일이 아니면 `422` |
| `GET /todos` | `{"todos": [OpenTodo]}`: 열린 할 일 전부 |
| `GET /daily/{date}` | `YYYY-MM-DD`의 일일 노트. 없으면 템플릿으로 만들어요 |
| `GET /periodic/{period}/{key}` | `key`(`YYYY-MM-DD`, `today`, `2026-W43`, `2026-10`)를 포함하는 `daily`, `weekly`, `monthly`, `quarterly`, `yearly` 노트. 없으면 만들어요. `?create=false`면 대신 `404`로 답해요 |
| `GET /periodic/{period}/{key}/prev` | `key`의 기간보다 앞서는, 그 주기의 가장 최근 노트 |
| `GET /search?q=&limit=` | `{"notes": [{id, path, kind, title, summary?, snippet?}]}`, `limit`는 최대 50 |
| `GET /notes/{id}/sections/{name}` | 플러그인이 관리하는 이름 있는 섹션. 없으면 `404`, `409 section_ambiguous` |
| `PUT /notes/{id}/sections/{name}` | `{content, version?}` → Note |
| `GET /settings` | 실제로 적용되는 설정과 `serverTimezone` |

Note는 `{id, path, kind, title, body, version, todos, updatedAt}`이고, 다른 이름의 파일을 미러링하는 노트에는 `sourcePath`가, 저널 노트에는 `period` / `periodStart`가 붙어요. 줄 번호는 0부터 세요.

서버가 제공하는 나머지(이벤트, 플러그인, 정리, 첨부 파일, 설정 변경)는 로컬 API에 없어요. 모르는 경로는 `404`, 아는 경로에 다른 메서드를 쓰면 `405`로 답해요.

### 오류

오류는 `{"error": {"code": "…", "message": "…"}}` 형태예요. `version_conflict`에는 지금 상태의 노트인 `"current"`도 들어 있어요.

### 쓰기는 무작정 덮어쓰지 않아요

- `version`을 담은 요청(수정, 보관, 토글, `version`을 담은 섹션 교체)은 그 버전 이후 노트가 바뀌었다면 현재 노트와 함께 `409 version_conflict`를 받아요. 앱은 대신 재시도하지 않아요. 다시 읽고 판단하세요.
- 덧붙이기와 `version` 없는 섹션 교체는 읽기와 쓰기 사이에 외부 편집이 끼어들면 다시 읽고 재시도해요. 최대 3번까지요.

## 동작

<Badge text="다음 릴리스" /> 앱의 소켓은 이름 있는 동작, 즉 명령 팔레트가 실행하는 것을 id로 실행하기도 해요. id 목록은 [키보드 단축키](/ko/docs/guides/shortcuts/#동작-id)에 있어요. 데스크톱 호스트의 소켓에는 이 경로가 없어요(`404`).

| 경로 | 하는 일 |
| --- | --- |
| `GET /actions` | `{"actions": [{"id", "title", "available", "why"}]}`: 지금 창에 있는 동작이에요. `why`는 실행할 수 없는 동작에만 붙고, 무엇이 필요한지 알려 줘요 |
| `POST /actions/{id}` | 동작을 실행하고 끝나면 답해요: `200` `{"id", "ran": true}` |

`POST /actions/{id}`는 이렇게 답하기도 해요.

| 상태 | `code` | 언제 |
| --- | --- | --- |
| `404` | `unknown_action` | 그 id의 동작이 없음(예: 그사이 제거된 플러그인) |
| `409` | `unavailable` | 지금 실행할 수 없음. `message`가 이유예요 |
| `409` | `no_window` | 이 보관소를 보여 주는 창이 없음(`GET /actions`도 이렇게 답해요) |
| `409` | `superseded` | Linux: 끝나기 전에 다른 것이 열려서 가져온 것을 열지 않음 |
| `500` | `action_failed` | 동작이 실패함(`message`가 그 오류예요) |
| `500` | `window_closed` | 실행하는 동안 창이 닫힘 |

두 경로 모두 이 소켓의 보관소를 보여 주는 창 중 마지막으로 쓴 창에서 동작해요. 그 창이 앞에 있든 없든 마찬가지예요. id의 `/`는 이스케이프하세요(`/actions/plugin%2Fbookmark%2Fsave`). 이스케이프하지 않은 형태(`/actions/plugin/bookmark/save`)도 돼요. [`aidectl action`](/ko/docs/developers/aidectl/#action)이 이 경로 위에서 만들어졌어요.

`$s`가 [예시](#예시)에서처럼 소켓일 때:

```sh
curl -s --unix-socket "$s" http://aide/actions | jq -r '.actions[] | select(.available) | .id'
curl -s --unix-socket "$s" -X POST http://aide/actions/today
```

## 브라우저

<Badge text="다음 릴리스" /> Mac과 Linux에서는 **설정 › 코어 플러그인**에서 켜 둔 [브라우저](/ko/docs/guides/browser/)도 앱의 소켓으로 다룰 수 있어요. 앱마다 브라우저는 하나라서, 앱의 어느 볼트 소켓으로든 같은 탭에 닿아요. 데스크톱 호스트의 소켓과 Mac App Store 빌드에는 이 경로가 없어요(`404`). [`aidectl browser`](/ko/docs/developers/aidectl/#browser)와 [`aidectl secret`](/ko/docs/developers/aidectl/#secret)이 이 경로를 써요.

| 경로 | 하는 일 |
| --- | --- |
| `GET /browser/tabs` | `{"tabs": [{"id", "url", "title", "loading", "mode"}], "active"}`: `mode`는 `automation`이나 `protected`, `active`는 보이는 탭의 순서예요(탭이 없으면 `-1`). 보호된 탭이 있는 동안에는 주소와 제목이 비어 있어요 |
| `POST /browser/{op}` | JSON 본문을 매개변수로 op를 실행하고(빈 본문은 `{}`) 결과와 함께 `200`으로 답해요 |

본문의 `tab_id`로 탭을 고르고, 없으면 브라우저가 보여 주는 탭에서 동작해요. op는 다음과 같아요.

- 탭: `tab/new`(`url`, `background: false`가 아니면 뒤에서 열려요), `tab/select`, `tab/close`, `tab/move`(`index`), `tab/protect`(`on`, `false`가 아니면 켜요).
- 이동: `navigate`(`url`), `back`, `forward`, `reload`, `state`.
- 페이지: `execute_js`(`code`), `get_content`(`format`: `text`나 `html`), `query`, `query_all`(`selector`, `limit`), `get_styles`(`selector`, `properties`), `click`, `fill`(`selector`, `value`), `scroll`(`selector`, 또는 `x`와 `y`), `page_info`, `screenshot`(`{"image_b64", "width", "height"}`).
- 기록: `net`과 `console`(`since`, `filter`, `limit`, 콘솔은 `level`도)은 `{"records", "coverage"}`로 답해요. `clear_log`.
- `profile/list`, `profile/clear`(`kinds`: `cookies`, `storage`, `cache`).
- `grab`: 요소를 클릭할 때까지 최대 2분 기다렸다가 그 설명을 `{"prompt"}`로 답해요.
- 비밀번호: `secret/list`(`origin`), `secret/fill`(`credential_id`), `secret/save`(`username`), `secret/delete`(`credential_id`). 비밀번호는 요청에도 응답에도 담기지 않아요.

탭이 보호되는 동안 읽는 op는 `409` `tab_protected`로 답하고, 쓰는 op는 `{"status", "protected": true}`만 답해요. 오류에는 코드마다 정해진 메시지만 담기고, 페이지 텍스트는 담기지 않아요.

| 상태 | `code` | 언제 |
| --- | --- | --- |
| `400` | `invalid_params` | 매개변수가 없거나 틀렸어요 |
| `404` | `unknown_method`, `tab_closed`, `not_found` | 그런 op, 탭, 자격 증명이 없어요 |
| `409` | `plugin_off` | 브라우저가 꺼져 있어요 |
| `409` | `no_tab` | 열린 탭이 없어요 |
| `409` | `tab_protected`, `requires_protected`, `origin_mismatch` | 보호된 탭이 있어서 거부했거나, 보호되지 않은 탭이나 다른 사이트에 비밀번호 op를 요청했어요 |
| `409` | `purge_incomplete` | 사이트의 service worker나 캐시를 지우지 못해서 보호나 채우기를 거부했어요 |
| `409` | `superseded`, `timeout`, `cancelled` | 다른 가져오기로 바뀌었거나, 시간이 지났거나, 끝난 가져오기예요 |
| `500` | `js_error`, `snapshot_failed`, `fill_failed`, `secret_backend_unavailable` | 페이지 스크립트가 실패했거나, 스크린샷을 못 찍었거나(Linux에서 화면에 없는 탭), 페이지가 값을 받지 않았거나, 키체인·키링이 없어요 |

```sh
curl -s --unix-socket "$s" http://aide/browser/tabs
curl -s --unix-socket "$s" -X POST http://aide/browser/navigate -d '{"url": "http://localhost:3000"}'
```

## 트리거

<Badge text="다음 릴리스" /> Mac과 Linux에서 코어 플러그인이 켜져 있으면 보관소 소켓으로 [트리거](/ko/docs/guides/triggers/)도 다룰 수 있어요. 꺼져 있으면 모든 경로가 `409` `plugin_off`로 답해요. 데스크톱 호스트의 소켓과 Mac App Store 빌드에는 없어요. [`aidectl trigger`](/ko/docs/developers/aidectl/#trigger)와 [`aidectl event`](/ko/docs/developers/aidectl/#event)가 이 경로를 써요.

| 경로 | 하는 일 |
| --- | --- |
| `GET /triggers` | `{"file", "file_error", "paused_all", "triggers", "errors"}`: 트리거마다 소스, `enabled`, `paused`, `busy`, `next_fire`, 최근 실행 10개 |
| `POST /triggers/{name}/run` | 지금 한 번 실행해요(`202`). `409` `paused` 또는 `busy`, `403` `not_privileged`, `404` `unknown_trigger` |
| `POST /events` | `{"kind": "custom.<name>", "payload"}`: `202` `{"id"}`. `custom.*`만 받고, 8 KiB를 넘는 페이로드는 `413`이에요 |
| `GET /events?epoch=&after=&limit=` | 최근 이벤트 500개에서 `{"epoch", "events", "next", "dropped"}`. `after`가 사라졌거나, 앱이 다시 시작됐거나, `after`가 앞서 있으면 `dropped`가 true예요 |

## 상태 항목

<Badge text="다음 릴리스" /> Mac과 Linux에서 보관소 소켓은 그 보관소 사이드바 아래의 [상태 항목](/ko/docs/guides/appearance/#상태-항목mac과-linux-)을 설정해요. 소켓은 자기 항목(`ext.<id>`)만 설정하고 지울 수 있고, `GET`은 앱과 플러그인 항목까지 모두 보여 줘요. 저장하지 않으니 ttl이 지나거나 앱을 끄면 사라져요. [`aidectl status-item`](/ko/docs/developers/aidectl/#status-item)이 이 경로를 써요.

| 경로 | 하는 일 |
| --- | --- |
| `GET /status-items` | `{"items": [...], "shown": 8}`, `order` 다음 `id` 순서예요. 앞의 `shown`개가 레일에, 나머지는 … 안에 있어요 |
| `PUT /status-items/{id}` | `{"text", "icon", "progress": {"start", "end"}, "tooltip", "action", "order", "ttl"}`(모두 선택이지만 텍스트, 아이콘, 링 중 하나는 있어야 해요): `200` `{"item"}`, 16개를 넘으면 `409` `too_many` |
| `DELETE /status-items/{id}` | `200` `{"id", "cleared"}` |

## 제한

- HTTP/1.1이고, 연결 하나에 요청 하나면 충분해요(`Connection: close`).
- 요청 줄과 헤더는 최대 16KiB, 본문은 최대 2MiB, 요청을 보내는 데 10초, 동시 연결은 8개까지예요.
- 본문에는 `Content-Length`가 있어야 해요. chunked `Transfer-Encoding`은 거부돼요. `curl --data`가 알아서 넣어 줘요.

## 예시

```sh
s="${XDG_RUNTIME_DIR:-/tmp/aide-$(id -u)}/aide/3f9a….sock"   # 위의 반복문에서 찾은 소켓
```

오늘의 일일 노트(없으면 만들어요):

```sh
curl -s --unix-socket "$s" http://aide/periodic/daily/today | jq -r .body
```

노트를 찾아 제목 아래에 덧붙이기:

```sh
id=$(curl -s --unix-socket "$s" "http://aide/notes/lookup?path=topics/k8s" | jq -r .id)
curl -s --unix-socket "$s" -X POST "http://aide/notes/$id/append" \
    -H 'Content-Type: application/json' \
    -d '{"text": "- read the 1.31 changelog", "heading": "Reading", "createHeading": true}' | jq .appended
```

읽은 뒤 아무도 바꾸지 않았을 때만 본문 바꾸기:

```sh
note=$(curl -s --unix-socket "$s" "http://aide/notes/$id")
version=$(echo "$note" | jq .version)
body=$(echo "$note" | jq -r .body | sed 's/TODO/DONE/')
jq -n --argjson v "$version" --arg b "$body" '{version: $v, body: $b}' |
    curl -s --unix-socket "$s" -X PUT "http://aide/notes/$id" -H 'Content-Type: application/json' -d @-
```

노트의 첫 번째 열린 할 일 체크하기:

```sh
curl -s --unix-socket "$s" http://aide/todos |
    jq -r --arg id "$id" '[.todos[] | select(.noteId == $id)][0] | "\(.line) \(.version)"' |
    while read -r line version; do
        curl -s --unix-socket "$s" -X POST "http://aide/notes/$id/todos/$line/toggle" \
            -H 'Content-Type: application/json' -d "{\"version\": $version}"
    done
```

검색:

```sh
curl -s --unix-socket "$s" "http://aide/search?q=postgres&limit=5" | jq -r '.notes[] | "\(.path)\t\(.title)"'
```

<Aside title="열린 앱이 없나요?">
보관소를 연 앱이 없으면 소켓도 없어요. 그때 `aidectl`은 명령 하나를 위해 폴더를 직접 열고, 규칙과 응답은 똑같아요. 그래서 `aidectl`을 쓰는 스크립트는 어느 쪽이든 동작해요. 앱이 보관소를 열었는데 응답하는 소켓이 없다면 앱을 업데이트하거나 다시 시작하세요.
</Aside>

## 터미널 소켓

<Badge text="다음 릴리스" /> AIDE의 터미널은 소켓 하나로도 제공돼요. 프로그램이 이 소켓으로 페인을 읽고 입력하고, 탭을 열고 나누고 닫을 수 있어요. HTTP가 아니라 copad의 터미널 소켓과 같은 프로토콜을 쓰기 때문에, copad의 `coctl`과 comux의 알림 클릭이 AIDE에서도 동작해요. [`aidectl terminal`](/ko/docs/developers/aidectl/#terminal)은 이 소켓 위에 만들어졌어요. Mac App Store 빌드와 iPhone에는 없어요.

### 위치

셸을 실행하고 앱보다 오래 사는 터미널 서버([AIDE보다 오래 사는 셸](/ko/docs/guides/terminal/#aide보다-오래-사는-셸-))가 자기 폴더의 `terminal.sock`으로 제공해요.

- Mac: `~/Library/Application Support/AIDE/mux/terminal.sock`이에요.
- Linux: `$XDG_RUNTIME_DIR/aide-mux/terminal.sock`이에요. `XDG_RUNTIME_DIR`이 없으면 `/tmp/aide-mux-<uid>/terminal.sock`이에요.
- 폴더는 나만 쓸 수 있고(모드 `0700`), 소켓은 모드 `0600`이며, 내 사용자만 연결할 수 있어요.

페인마다 셸은 이 소켓의 경로인 `COPAD_SOCKET`과 `AIDE_TERMINAL_SOCKET`, 그 페인의 id인 `COPAD_PANEL_ID`와 `AIDE_MUX_PANE`을 받아요.

AIDE 창이 하나도 없어도 읽고 입력할 수 있어요. 창만 할 수 있는 일(`panel.focus`, `tab.switch`, `tab.new`)은 그 페인의 볼트를 보여 주는 창 가운데 마지막으로 앞에 있던 AIDE 창으로 가고, 그런 창이 없으면 `no_window`로 응답해요. 페인을 지정하지 않은 요청은 앞에 있는 창의 포커스된 페인을, 창이 없으면 탭이 있는 첫 볼트의 페인을 뜻해요.

### 요청과 응답

한 줄에 JSON 요청 하나를 보내면, 같은 연결로 한 줄에 JSON 응답 하나가 와요. 한 연결로 요청을 여러 번 보낼 수 있어요.

```json
{"id": "1", "method": "terminal.read", "params": {"id": "…"}}
{"id": "1", "ok": true, "result": {"text": "…"}}
{"id": "1", "ok": false, "error": {"code": "not_found", "message": "…"}}
```

### 메서드

`params`의 `id`(또는 `panel_id`)는 **페인** id이고, 없으면 마지막으로 앞에 있던 창의 포커스된 페인이에요. 탭 id는 `tab.*` 메서드만 받아요.

| 메서드 | 파라미터 | 하는 일 |
| --- | --- | --- |
| `system.ping` | | 소켓이 살아 있는지 확인하는 응답을 해요: `{status, app: "aide", server: "aide-mux", pid}` |
| `panel.focus` | `panel_id` | 그 페인과 탭을 고르고, 터미널 섹션을 보여 주고, 창을 앞으로 가져와요. `{focused, raised}`로 응답해요. 서버에 없는 페인이면 오류가 아니라 `focused: false`예요. Linux는 항상 `raised: false`로 응답해요 |
| `terminal.read` | `id`, `start_row`, `start_col`, `end_row`, `end_col` | 지금 화면, 또는 그 일부를 글자로 줘요. 양 끝을 포함하고, 화면을 넘는 끝은 화면 끝으로 맞춰요 |
| `terminal.state` | `id` | 크기, 커서, 폴더, 제목, 셸이 끝났는지 |
| `terminal.exec` | `id`, `command` | `command`와 줄바꿈을 입력해요. 명령을 기다리지는 않아요 |
| `terminal.feed` | `id`, `text` | `text`를 그대로 입력해요 |
| `terminal.history` | `id`, `lines` | 화면 위의 마지막 `lines`줄(최대 10 000줄), 그다음 화면 |
| `terminal.context` | `id`, `history_lines` | 상태, 화면, 그 위의 줄 |
| `tab.new` | | 탭을 열고 그 페인의 id로 응답해요 |
| `tab.close` | `id` | 탭 id를 주면 그 탭을 안의 모든 페인과 함께 닫고, 없으면 포커스된 페인을 닫아요 |
| `tab.list`, `tab.info` | | `{count, current, tabs: [{id, index, title, selected, panes: [{id, title, focused, exited, cols, rows}]}]}`: 앞에서 뒤 순서의 창들의 탭이에요. 창이 없으면 모든 볼트의 탭이고 `current`는 null이에요 |
| `tab.rename` | `id`, `title` | 탭에 이름을 붙여요 |
| `tab.switch` <Badge text="다음 릴리스" /> | `index` | `tab.list`의 그 순서(0부터)에 있는 탭을 선택하고 `{tab}`을 돌려줘요. 그 자리에 탭이 없으면 `not_found`, 정수가 아니면 `invalid_params`예요 |
| `split.horizontal` | `id` | 페인을 오른쪽으로 나누고 새 페인의 `{panel_id}`로 응답해요 |
| `split.vertical` | `id` | 페인을 아래로 나누고 `{panel_id}`로 응답해요 |
| `pane.focus_next`, `pane.focus_prev` | | 다음 또는 이전 페인으로 포커스를 옮겨요 |

읽어도 페인의 스크롤 위치는 바뀌지 않아요.

### 오류

| `code` | 언제 |
| --- | --- |
| `parse_error` | 줄이 JSON이 아님 |
| `invalid_request` | JSON 객체가 아니거나, 문자열 `id`나 `method`가 없거나, `params`가 객체가 아님 |
| `invalid_params` | 파라미터가 없거나 잘못됨(예: 말이 안 되는 읽기 범위) |
| `unknown_method` | 그 이름의 메서드가 없음 |
| `not_found` | 그 id의 페인이나 탭이 없음(그사이 닫혔을 때 등) |
| `no_terminal` | 열린 터미널이 없음(창이나 탭이 없음) |
| `exited` | 셸이 끝난 페인에 `terminal.exec`나 `terminal.feed`를 보냄. 읽기는 여전히 돼요 |
| `too_small` | 페인이 나누기엔 너무 작음 |
| `busy` | 이미 클라이언트 16개가 연결돼 있음, 또는 보낸 것을 읽지 않는 프로그램의 페인에 `terminal.exec`이나 `terminal.feed` |
| `no_window` | 그 페인의 볼트를 보여 주는 AIDE 창이 없을 때 `panel.focus`, `tab.switch`, `tab.new` |
| `frame_too_large` | 요청 줄이 64 KiB를 넘음 |

### 터미널 소켓의 제한

- 요청 한 줄은 64 KiB까지, 동시에 클라이언트 16개까지예요.
- 한 줄을 보내는 데 10초, 응답을 받아 가는 데 10초가 주어지고, 멈춘 클라이언트는 연결이 끊겨요.

`$t`가 그 소켓일 때(페인 안에서는 `$COPAD_SOCKET`, 아니면 위의 폴더):

```sh
printf '%s\n' '{"id": "1", "method": "tab.list"}' | nc -U "$t"
```
