`aidectl`은 터미널, 스크립트, 에디터, 상태 표시줄에서 AIDE 노트를 읽고 써요. AIDE의 노트 규칙을 그대로 따르기 때문에, 보지 못한 편집을 덮어쓰는 일은 없어요. 특정 작업 방식은 정해 두지 않았어요. `get`, `put`, `append`, `toggle`을 직접 조합해서 쓰면 돼요.

## 설치

`aidectl`은 macOS와 Linux 데스크톱 앱에 함께 들어 있어요. 따로 설치하지 않아도 돼요.

- 설치 스크립트가 macOS에서는 `AIDE.app` 안의 사본을 `~/.local/bin/aidectl`로 연결하고, Linux에서는 `~/.local/bin`(`--prefix`를 주면 `<prefix>/bin`)에 넣어요.
- Homebrew cask(`brew install --cask marshallku/tap/aide`)도 `PATH`에 연결해 줘요.
- 앱과 함께 업데이트돼요.

`aidectl help`를 실행하면 명령 목록이 나오고, 직접 추가한 확장 명령은 맨 끝에 보여요.

## 연결할 대상 고르기

`aidectl`은 두 대상 중 하나와 일해요.

- **볼트**: 이 컴퓨터에 있는 노트 폴더예요. AIDE 앱이 그 폴더를 열고 있으면 `aidectl`은 앱의 [로컬 소켓](/ko/docs/developers/local-api/)으로 앱과 통신해요. [데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)가 그 폴더를 서비스하고 있으면 호스트와 통신하고, 그 뒤의 서버 기능을 모두 쓸 수 있어요. 아무것도 열고 있지 않으면 `aidectl`이 명령 하나를 실행하는 동안만 같은 노트 규칙으로 폴더를 직접 열고, 끝나기 전에 놓아줘요.
- **서버**: AIDE 서버 URL과 토큰이에요.

대상을 지정한 첫 번째 출처를 사용해요.

| 출처 | 볼트 | 서버 |
| --- | --- | --- |
| 명령 앞의 플래그 | `--vault DIR` | `--server URL` |
| 환경 변수 | `AIDE_VAULT` | `AIDE_URL` |
| 설정 파일 | `vault=` | `url=` |

한 출처는 볼트나 서버 중 하나만 지정해요. 둘 다 지정하면 사용법 오류로 멈춰요. 서버 토큰은 `AIDE_TOKEN`에서, 없으면 설정 파일의 `token=`에서 가져와요.

```sh
aidectl --vault ~/Notes daily
AIDE_URL=https://aide.example.ts.net AIDE_TOKEN=aide_p_… aidectl todos
```

<Aside type="caution" title="응답하지 않는 열린 볼트">
앱이 볼트를 열고 있는데 소켓이 응답하지 않으면, `aidectl`은 기다리지 않고 멈춰요: `… is open in AIDE, but … doesn't answer for it: update or restart the app (or close the vault there)`. 서버가 노트를 보관하는 폴더도 거부해요. 그럴 때는 그 서버와 통신하세요.
</Aside>

### 설정 파일

`~/.config/aidectl/config`, 또는 `AIDECTL_CONFIG`가 가리키는 파일이에요. 한 줄에 `key=value` 하나씩 쓰고, `#`으로 시작하는 줄은 건너뛰어요. 기본 파일이 없어도 괜찮지만, `AIDECTL_CONFIG`로 지정한 파일이 없으면 오류예요.

```ini
# 이 컴퓨터의 노트 폴더 (절대 경로, 또는 ~/로 시작)
vault=~/Notes

# 또는 서버
# url=https://aide.example.ts.net
# token=aide_p_…

# 확장 aidectl-<name>만 받는 토큰
# token.sync=aide_p_…
```

파일의 `vault=`는 절대 경로(또는 `~/`로 시작)여야 해요. `--vault`와 `AIDE_VAULT`는 현재 폴더 기준의 상대 경로여도 돼요.

### 서버용 토큰

직접 운영하는 서버에서는 호출하는 쪽이 건드려도 되는 범위로 제한한 플러그인 토큰을 쓰세요. 서버의 `aide plugin-token` 명령으로 발급해요. 토큰과 범위는 [서버 플러그인 만들기](/ko/docs/developers/server-plugins/)에서 설명해요.

## 노트와 경로

`<path>`는 노트 경로(`topics/k8s`)나 그 노트가 대응하는 파일(`topics/k8s.md`)이에요. 둘 다 있으면 노트 경로가 우선해요. id를 받는 명령(`toggle`)은 `--json` 출력과 `todos`가 보여 주는 노트 id를 써요.

## 명령

### get

```sh
aidectl get <path> [--json]
```

노트의 Markdown 본문을 출력해요. `--json`을 주면 노트 전체를 출력해요: `id`, `path`, `kind`, `title`, `body`, `version`, `todos`, `updatedAt`, 그리고 저널 노트라면 `period` / `periodStart`도요.

### put

```sh
aidectl put <path> --create-only [--file f]
aidectl put <path> --base-version N [--file f]
```

본문 전체를 `--file`이나 표준 입력에서 받아 써요(`--file -`도 표준 입력을 읽어요). 다음 중 정확히 하나를 줘야 해요.

- `--create-only`: 노트를 만들어요. 이미 있는 경로라면 종료 코드 3이에요. `.md`로 끝나는 경로는 쓴 그대로 파일 이름을 유지해요.
- `--base-version N`: 노트가 아직 버전 `N`일 때만 본문을 바꿔요. 그사이 바뀌었으면 아무것도 쓰지 않고, 보내려던 본문을 임시 파일에 저장한 뒤 그 경로를 출력하고, 종료 코드 4로 끝나요.

성공하면 노트를 JSON으로 출력해요.

```sh
v=$(aidectl get topics/k8s --json | jq .version)
aidectl get topics/k8s | sed 's/old/new/' | aidectl put topics/k8s --base-version "$v"
```

### append

```sh
aidectl append <path> [--heading H] [--create-heading] [--if-absent] [--text T] [--json]
```

텍스트(`--text`, 없으면 표준 입력)를 제목 섹션의 끝에, `--heading`이 없으면 노트 끝에 덧붙여요. 버전은 필요 없어요. 같은 순간에 누가 노트를 편집하면 AIDE가 다시 읽고 재시도해요.

| 플래그 | 효과 |
| --- | --- |
| `--heading H` | 텍스트가 `H`인 제목 아래에 덧붙여요. `--create-heading`이 없으면 제목이 없을 때 "찾을 수 없음"(종료 코드 5)이에요. |
| `--create-heading` | 제목이 없으면 노트 끝에 `## H`를 추가해요. |
| `--if-absent` | 그 섹션에 같은 줄들이 이미 붙어 있으면 덧붙이지 않고 `already there`를 출력해요. |
| `--json` | `id`, `path`, `version`, `appended`(true 또는 false)를 출력해요. |

```sh
aidectl append daily/2026-10-22 --heading Log --create-heading --text "- 14:10 deployed v2"
```

### edit

```sh
aidectl edit <path>
```

노트를 `$VISUAL`, 없으면 `$EDITOR`, 그것도 없으면 `vi`로 열고, 읽었던 버전 기준으로 다시 저장해요. 에디터가 열려 있는 동안 `aidectl`은 볼트를 놓아주기 때문에 앱이 볼트를 열 수 있어요. 그사이 노트가 바뀌었으면 아무것도 쓰지 않고, 작성한 텍스트는 안내한 임시 파일에 남겨 두고, 종료 코드 4로 끝나요. 바꾸지 않고 닫으면 아무것도 쓰지 않아요.

### daily와 periodic

```sh
aidectl daily [YYYY-MM-DD] [--json | --edit]
aidectl periodic <period> <date> [--json | --edit]
```

`daily`는 오늘(또는 지정한 날)의 데일리 노트를 출력하고, 없으면 데일리 템플릿으로 만들어요. `periodic`은 `<date>`를 포함하는 `daily`, `weekly`, `monthly`, `quarterly`, `yearly` 노트에 대해 같은 일을 해요. 날짜는 `YYYY-MM-DD` 또는 `today`예요. `weekly`는 ISO 주(`2026-W43`)도, `monthly`는 월(`2026-10`)도 받아요. 새 노트는 저널 설정에서 그 주기에 정한 위치에 만들어져요. `--edit`을 주면 출력하는 대신 에디터로 열어요.

### todos

```sh
aidectl todos [--json]
```

모든 노트의 열린 할 일을 한 줄에 하나씩, 탭으로 구분해 출력해요: 노트 id, 줄(0부터), 노트 버전, 노트 경로, 텍스트. `--json`은 `noteTitle`, `indent`, `due`, `scheduled`, `noteDate`(할 일이 들어 있는 데일리 노트의 날짜)를 더해요.

### toggle

```sh
aidectl toggle <noteId> --line L --version V --text T
```

버전 `V`에서 읽은 `L`번째 줄의 할 일이 아직 `T`라면 체크(또는 체크 해제)해요. 세 플래그 모두 필수예요. 그 뒤로 노트가 바뀌었으면, 같은 줄에 같은 열린 할 일이 그대로 있을 때만 다시 시도해요. 다른 줄에 있는 같은 텍스트의 할 일은 다른 작업이라서 찾아다니지 않아요. 그 밖의 경우는 종료 코드 4예요. 할 일 목록을 다시 받아 오세요.

```sh
aidectl todos | grep "call Mina" | head -1 | while IFS=$'\t' read -r id line version path text; do
    aidectl toggle "$id" --line "$line" --version "$version" --text "$text"
done
```

### search

```sh
aidectl search <query…> [--limit N] [--json]
```

전문 검색이에요. 일치하는 노트마다 경로와 제목을 탭으로 구분해 출력해요. `--limit`의 기본값은 20이고, 서버는 최대 50개까지 돌려줘요.

### capture

```sh
aidectl capture [text… | -]
```

앱의 빠른 기록처럼 스크래치 노트를 추가해요. 텍스트는 인자에서, 또는 `-`를 주거나 인자가 없으면 표준 입력에서 받아요. 앞뒤 공백을 지우고, 빈 텍스트면 사용법 오류예요. 새 노트의 경로를 출력해요(`--json`: 노트).

```sh
pbpaste | aidectl capture
```

### status

```sh
aidectl status [--json | --waybar] [--format T]
```

하루를 한눈에 보여 줘요: 열린 할 일, 기한이 지난 할 일, 오늘 마감인 할 일, 스크래치 노트, 오늘의 데일리 노트, 다음 캘린더 일정이에요. 데일리 노트를 만들지는 않아요.

- 기한이 지났다는 건 마감일(없으면 예정일)이 오늘보다 앞이라는 뜻이에요. 오늘 마감에는 할 일 탭이 세는 것처럼 오늘 데일리 노트에 있는 날짜 없는 할 일도 들어가요. "오늘"은 설정의 시간대를 기준으로 해요.
- 다음 일정은 표시하도록 설정한 캘린더에서 Google Calendar 플러그인이 가져온 첫 번째 시간 지정 일정이에요. `aidectl`이 소유자로서 서버와 통신할 때만 나타나요. 볼트를 통하거나 플러그인 토큰을 쓰면 빠져요.

플래그 없이 실행하면 짧은 요약을 출력해요.

```text
12 open todos · 2 overdue · 3 due today
4 scratch notes
Today: daily/2026-10-22
Next: 15:00 Design review
```

`--format`으로 아래 자리 표시자를 써서 원하는 줄을 만들 수 있어요. 모르는 자리 표시자는 사용법 오류예요.

| 자리 표시자 | 값 |
| --- | --- |
| `{open}` | 열린 할 일 |
| `{overdue}` | 기한이 지난 할 일 |
| `{today}` | 오늘 마감인 할 일 |
| `{scratch}` | 스크래치 노트 |
| `{date}` | 오늘, `YYYY-MM-DD` |
| `{daily}` | 오늘 데일리 노트의 제목, 없으면 빈 값 |
| `{next}` | 오늘이면 `15:04 Title`, 이후 날짜면 `Mon 15:04 Title`, 없으면 빈 값 |

`--json`은 `date`, `open`, `overdue`, `today`, `scratch`, `daily`(`id`, `path`, `title`, 또는 `null`), `next`(있을 때 `title`, `start`, `end`)를 출력해요. `--json`은 `--waybar`나 `--format`과 함께 쓸 수 없어요.

`--waybar`는 [Waybar](https://github.com/Alexays/Waybar) 사용자 모듈용 JSON 한 줄을 출력해요: `text`(`--format` 값, 기본은 `{open}`), `tooltip`(위의 요약), 그리고 기한이 지난 할 일이 있으면 `overdue`, 없으면 `ok`인 `class` / `alt`예요. 실패해도 `text`는 `!`, `tooltip`에는 오류, class는 `error`인 줄을 출력하고 0으로 끝나요. Waybar는 명령이 실패한 모듈을 숨기기 때문이에요.

### watch

```sh
aidectl watch (--waybar | --json | --format T) [--interval 30s]
```

상태가 바뀔 때마다 한 줄씩 다시 출력해요. `--interval`마다(기본 `30s`, 최소 `1s`) 확인해요. 세 출력 플래그 중 하나가 필요해요. 확인할 때마다 볼트나 서버를 열었다가 놓아주기 때문에, 확인 사이에 볼트를 붙잡고 있지 않아요. 확인에 실패하면 `--waybar`에서는 오류 줄을 출력하고, 그 밖에는 표준 오류에 한 번 알린 뒤 계속 지켜봐요.

스스로 갱신되는 Waybar 모듈이에요.

```json
"custom/aide": {
    "exec": "aidectl watch --waybar --format '{today} today · {overdue} late'",
    "return-type": "json",
    "on-click": "aidectl open todos"
}
```

### open

```sh
aidectl open [today | scratch | wiki | todos | <period> | YYYY-MM-DD | <path> | aide://…] [--print]
```

macOS에서는 `open`, Linux에서는 `xdg-open`으로 AIDE 앱의 해당 위치를 열어요. 인자가 없으면 오늘의 데일리 노트를 열어요. 주기(`weekly` 등)는 그 주기의 현재 노트를, 날짜는 그날의 데일리 노트를, 노트 경로는 그 노트를 열어요(노트 id를 찾아야 해서 이 경우에만 볼트나 서버가 필요해요). `aide://` 링크는 앱이 받는 링크인지 확인해요: `aide://note/<id>`, `aide://today`, `aide://periodic/<period>[/YYYY-MM-DD]`, `aide://scratch`, `aide://wiki`, `aide://todos`.

`--print`를 주면 열지 않고 링크를 출력해요.

### mcp

```sh
aidectl mcp
```

Claude Code와 다른 MCP 클라이언트를 위한, 표준 입출력으로 동작하는 MCP 서버예요. [MCP와 Claude 앱](/ko/docs/developers/mcp/)을 참고하세요. 볼트를 쓰려면 데스크톱 호스트가 실행 중이어야 해요.

### plugins list

```sh
aidectl plugins list [--json]
```

찾은 확장 명령(아래 참고)을 이름, 설명, 경로 순으로 탭으로 구분해 보여 주고, 실행할 수 없는 확장은 그 이유를 보여 줘요.

## 종료 코드

| 코드 | 의미 |
| --- | --- |
| 0 | 완료 |
| 1 | 오류 |
| 2 | 사용법: 잘못된 플래그나 인자, 또는 볼트나 서버가 설정되지 않음 |
| 3 | 이미 있는 경로(`put --create-only`) |
| 4 | 충돌: 노트가 그사이 바뀌어서 아무것도 쓰지 않음 |
| 5 | 찾을 수 없음: 노트, 또는 `append`의 제목 |

확장 명령은 자기 종료 코드로 끝나요(시그널로 끝났으면 128에 시그널 번호를 더한 값).

## 확장

`git`이나 `kubectl`처럼, 다른 명령 `foo`를 실행하면 `aidectl-foo`라는 실행 파일을 실행해요. 내장 명령이 항상 우선하고, `help`와 `plugins`는 예약돼 있어요.

- **위치**: 먼저 `~/.config/aidectl/plugins/`(또는 `AIDECTL_PLUGINS_DIR`), 그다음 `PATH`의 각 폴더를 찾아요. 그 이름으로 처음 찾은 파일을 써요. 이름은 영문 소문자, 숫자, `-`, `_`로 최대 64자예요.
- **신뢰**: 파일과 그 경로의 모든 폴더(링크를 따라간 결과 포함)가 내 소유이거나 root 소유이고 다른 사용자가 쓸 수 없을 때만 확장을 실행해요(`/tmp`처럼 sticky 비트가 있는 폴더는 예외). 처음 찾은 파일이 안전하지 않으면 거부하고, 다음 파일로 넘어가지 않아요. 볼트 안의 파일은 절대 실행하지 않아요.
- **환경 변수**: 확장은 `AIDE_URL`, `AIDE_TOKEN`, `AIDE_VAULT`, `AIDECTL_*`를 뺀 환경 변수에 아래 값을 더해 받아요.

| 변수 | 값 |
| --- | --- |
| `AIDECTL_BIN` | 확장을 실행한 `aidectl`. 다시 호출할 때 써요 |
| `AIDECTL_PLUGIN_NAME` | 확장의 이름(`foo`) |
| `AIDECTL_VERSION` | `aidectl`의 버전 |
| `AIDECTL_CONFIG` | 설정 파일을 지정했을 때만 |
| `AIDE_VAULT` | 대상이 볼트일 때, 결정된 볼트 |
| `AIDE_URL`, `AIDE_TOKEN` | 결정된 서버. 토큰은 `AIDE_TOKEN`이나 설정 파일의 `token.foo=`에서 왔을 때만 주고, 일반 `token=`에서 온 토큰은 주지 않아요 |

아무것도 설정하지 않아도 확장은 대상 없이 실행돼요. 설정이 잘못됐으면(한 출처에 볼트와 서버를 함께 지정, 잘못된 경로, 지정한 설정 파일이 없음) 멈추기 때문에, 요청하지 않은 대상에 대해 실행되는 일은 없어요. 터미널에서 Ctrl-C를 누르면 확장에만 전달돼요.

- **메타데이터**: `aidectl help`와 `plugins list`는 `aidectl-foo --aidectl-metadata`를 실행하고, 2초 안에 64 KiB 이내로 `{"schemaVersion": 1, "name": "…", "description": "…", "version": "…"}`가 오기를 기대해요.

오늘의 열린 할 일 개수를 출력하는 가장 작은 확장이에요.

```sh
#!/bin/sh
# ~/.config/aidectl/plugins/aidectl-count  (chmod 755)
if [ "$1" = "--aidectl-metadata" ]; then
    echo '{"schemaVersion": 1, "name": "count", "description": "Count open todos", "version": "1.0.0"}'
    exit 0
fi
exec "$AIDECTL_BIN" status --format '{open} open, {today} today'
```

```sh
aidectl count
```

## 예시

git 훅에서 오늘 데일리 노트에 한 줄 덧붙이기:

```sh
aidectl append "$(aidectl daily --json | jq -r .path)" --heading Log --create-heading \
    --text "- $(date +%H:%M) committed $(git log -1 --format=%s)"
```
