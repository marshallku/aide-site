HTTP 요청을 보낼 수 있다면 무엇이든 [피드](/ko/docs/guides/feed/)에 글을 올릴 수 있어요. 가격을 지켜보는 cron 작업,
CI 파이프라인, 홈 오토메이션 허브, 놓치기 쉬운 공지를 긁어 오는 스크레이퍼 같은 것들이요. 이벤트는 각각 하나의 주제에
들어가고, AIDE가 **조치 필요**, **알아둘 내용**, **관심 있을 만한 내용**, **나머지** 중 하나로 분류한 뒤 확인이 필요한
것을 푸시해요.

<Aside type="caution" title="직접 운영하는 서버에서만">
외부에서 게시하려면 서버가 발급한 토큰이 있어야 해요. 서버를 배포할 때 정한 게시 토큰이나, 서버 호스트에서
`aide plugin-token`으로 만든 플러그인 토큰이에요. 둘 다 [직접 운영하는 서버](/ko/docs/self-hosting/own-server/)에서만
나와요. 이번 릴리스의 [데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)에는 둘 다 없어서, 호스트가 실행하는
플러그인만 피드에 게시할 수 있어요.
</Aside>

## 이벤트 게시하기

```sh
curl -X POST https://aide.example.com/events \
    -H "Authorization: Bearer $AIDE_PUBLISH_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
        "topic": "finance.rates",
        "key": "rates:2026-10-22",
        "title": "Base rate held at 2.50%",
        "body": "The central bank kept the base rate unchanged.",
        "url": "https://example.com/rates/2026-10-22"
    }'
```

응답은 저장된 이벤트예요. `201 Created`는 새 이벤트라는 뜻이고, `200 OK`는 같은 `topic`과 `key`의 이벤트가 이미
있었다는 뜻이에요. 이때는 원래 이벤트가 바뀌지 않은 채 돌아와요.

### 토큰

| 토큰                                     | 받는 곳                                                     | 게시할 수 있는 주제                             |
| ---------------------------------------- | ----------------------------------------------------------- | ----------------------------------------------- |
| 게시 토큰(`AIDE_PUBLISH_TOKEN`)          | 배포할 때 정하는 서버의 환경 변수                           | 예약된 `aide.*`를 뺀 모든 주제                  |
| 플러그인 토큰(`aide_p_…`)                | `aide plugin-token <id> --scope events:publish:<prefix>`    | `events:publish` 스코프가 허용하는 주제         |

게시 토큰은 이벤트 게시만 할 수 있는 공유 비밀 값 하나예요. 새로 만드는 것이라면 플러그인 토큰이 더 좋아요. 게시하는
쪽마다 자기 토큰을 받고, 자기 주제로만 제한되고, `aide plugin-token <id> --revoke`로 따로 폐기할 수 있고, 이벤트마다
어느 플러그인이 게시했는지 기록돼요. 소유자는 앱에서 플러그인을 끄는 것으로 그 플러그인의 게시를 막을 수도 있어요(이때
`403 plugin_disabled`를 받아요). 토큰을 만드는 방법은 [서버 플러그인 만들기](/ko/docs/developers/server-plugins/)를
보세요.

```sh
aide plugin-token rates --scope events:publish:finance
```

스코프 접두사는 점으로 나뉜 구간 단위로 맞춰 봐요. `events:publish:finance`는 `finance`와 `finance.rates`에는 맞지만
`financial`에는 맞지 않아요.

## 필드

| 필드      | 필수   | 값                                                                                                                         |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------- |
| `topic`   | 예     | 소문자나 숫자 하나로 시작하고, 이어서 `a-z 0-9 . _ -` 최대 63자. `aide.`로 시작하는 주제는 예약돼 있어요(`403 reserved`)   |
| `title`   | 예     | 최대 500바이트. 피드와 알림에 보이는 내용이에요                                                                            |
| `body`    | 아니요 | 최대 64KiB의 텍스트                                                                                                        |
| `url`     | 아니요 | 링크. 이벤트 상세에서 **링크 열기**로 보여요                                                                               |
| `key`     | 아니요 | 1–200바이트. 같은 주제 안에서 게시를 멱등하게 만들어요(아래 참고)                                                          |
| `payload` | 아니요 | 구조화된 데이터와 아래 힌트를 담는 JSON 객체(기본값 `{}`)                                                                  |

다른 필드가 있으면 `400 bad_request`, 규칙에 맞지 않는 값이 있으면 이유와 함께 `422 invalid`를 받아요.

주제는 첫 이벤트가 올 때 만들어지고, 서버의 모든 사람이 그 첫 이벤트부터 구독돼요. 그래서 맨 처음 게시한 이벤트도 바로
보이고 푸시될 수 있어요. 소유자는 피드의 **주제**에서 구독을 해제할 수 있어요.

### 키: 한 번만 게시하고, 안심하고 재시도하기

`key`는 주제 안에서 영원히 고유해요. 그 주제가 이미 본 키로 다시 게시하면 아무것도 저장하지 않고, 원래 이벤트를 `200`과
함께 돌려주고, 다시 보여 주거나 푸시하지 않아요. 같은 이벤트임을 나타내는 값으로 키를 만들고, 실패한 요청은 마음껏
재시도하세요.

- 항목마다 공지 하나: `notice:<the source's id>`
- 하루에 요약 하나: `daily-summary:2026-10-22`
- 임계값을 넘을 때마다 알림 하나: `disk-90:<host>:2026-10-22`

키가 없으면 게시할 때마다 새 이벤트가 돼요.

## 피드가 분류하는 방식

모든 이벤트는 사람마다, 그 사람에게 처음 전달될 때 한 번 분류돼요. 분류는 아무것도 숨기지 않아요. **나머지**에 들어간
이벤트도 접혀 있을 뿐 그대로 있어요.

소유자가 AI 모델을 설정해 두었다면(**설정 › AI**), 모델이 이벤트의 주제, 제목, 본문 앞 2KB를 보고 분류해요. 소유자의
위키 페이지 제목을 관심사로 삼아요.

| 분류                     | 대상                                                                       |
| ------------------------ | -------------------------------------------------------------------------- |
| **조치 필요**            | 소유자가 해야 할 일: 마감, 신청, 납부, 필요한 절차                         |
| **알아둘 내용**          | 할 일은 없지만 중요한 것: 관심 있는 일에 영향을 주는 소식, 규정 변경       |
| **관심 있을 만한 내용**  | 관심사와 맞는 것                                                           |
| **나머지**               | 그 밖의 것                                                                 |

모델은 이벤트의 언어로 한 문장짜리 이유를 쓰고, 이 이유는 이벤트 상세에 보여요. 이벤트의 텍스트는 모델에 데이터로만
전달되고, 지시로 쓰이지 않아요.

AI 모델이 없거나 모델이 실패하면 아래 규칙을 순서대로 적용해요.

1. 제목이나 본문에 `deadline`, `due`, `action required`, `expires`, `apply by`, `register by`, `마감`, `신청`, `납부`,
   `시행`, `만료`, `기한` 중 하나가 있으면 **조치 필요**.
2. `payload.severity`가 `"high"`면 **알아둘 내용**.
3. 제목이나 본문에 소유자의 위키 페이지 제목이나 경로에 있는 단어가 있으면(영어는 단어 전체가 맞아야 해요) **관심 있을
   만한 내용**.
4. 그 밖에는 **나머지**.

그래서 이벤트가 중요하다는 걸 아는 게시자는 `"payload": {"severity": "high"}`로 알려 줄 수 있고, 제목에 마감이 있으면
모델이 있든 없든 **조치 필요**에 들어가요.

## 푸시

AIDE는 몇 초마다 새 이벤트를 확인하고 이벤트마다 푸시 여부를 정해요.

| `payload.push` | 푸시                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------- |
| `"force"`      | 항상                                                                                     |
| `"never"`      | 하지 않아요. 피드에서 기다려요                                                           |
| 생략           | **조치 필요**는 항상, **알아둘 내용**은 소유자가 끄지 않았다면, 나머지는 하지 않아요     |

이벤트는 새것일 때만 푸시돼요. 차례가 왔을 때 한 시간보다 오래된 이벤트(예를 들어 서버가 멈춰 있다가 밀린 것)는 피드에는
보이지만 푸시되지 않아요. 같은 알림이 다시 오면 기기에 쌓이지 않고 이전 알림을 대신해요. Mac과 Linux 앱은 서버에서 직접
알림을 가져와요. iPhone은 서버에 Apple 푸시가 설정돼 있어야 해요([직접 서버 운영하기](/ko/docs/self-hosting/own-server/)
참고).

```sh
curl -X POST https://aide.example.com/events \
    -H "Authorization: Bearer $AIDE_PLUGIN_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
        "topic": "home.alerts",
        "key": "door-open:2026-10-22T23:10",
        "title": "The front door has been open for 10 minutes",
        "payload": {"push": "force", "sensor": "front-door"}
    }'
```

`force`는 아껴 쓰세요. 소유자가 휴대폰을 조용히 두려고 기대는 분류를 건너뛰니까요.

## 예시

하루 한 번 디스크 사용량을 푸시 없이 게시하는 cron 줄:

```sh
0 8 * * * curl -fsS -X POST https://aide.example.com/events \
    -H "Authorization: Bearer $AIDE_PLUGIN_TOKEN" -H "Content-Type: application/json" \
    -d "{\"topic\": \"server.disk\", \"key\": \"disk:$(date +\%F)\", \"title\": \"Disk $(df --output=pcent / | tail -1 | tr -d ' ') full\", \"payload\": {\"push\": \"never\"}}"
```

배포가 실패하면 게시하는 GitHub Actions 단계:

```yaml
- name: Tell AIDE
  if: failure()
  run: |
      curl -fsS -X POST "$AIDE_URL/events" \
        -H "Authorization: Bearer $AIDE_TOKEN" -H "Content-Type: application/json" \
        -d "{\"topic\": \"ci.deploy\", \"key\": \"deploy:${GITHUB_RUN_ID}\", \"title\": \"Deploy of ${GITHUB_REPOSITORY} failed\", \"url\": \"${GITHUB_SERVER_URL}/${GITHUB_REPOSITORY}/actions/runs/${GITHUB_RUN_ID}\", \"payload\": {\"severity\": \"high\"}}"
  env:
      AIDE_URL: ${{ secrets.AIDE_URL }}
      AIDE_TOKEN: ${{ secrets.AIDE_PLUGIN_TOKEN }}
```

시간 초과 뒤에 재시도해도 두 번 게시되지 않도록 키를 쓰는 Python:

```python
import json, urllib.request

def publish(topic, title, key, body="", url="", payload=None):
    request = urllib.request.Request(
        "https://aide.example.com/events",
        data=json.dumps({"topic": topic, "key": key, "title": title, "body": body,
                         "url": url, "payload": payload or {}}).encode(),
        headers={"Authorization": "Bearer aide_p_…", "Content-Type": "application/json"},
        method="POST")
    with urllib.request.urlopen(request, timeout=10) as response:
        return response.status == 201  # False: 이 키는 이미 게시됐어요

publish("finance.rates", "Base rate held at 2.50%", key="rates:2026-10-22")
```

## 오류

| 상태 | 코드              | 언제                                                                 |
| ---- | ----------------- | -------------------------------------------------------------------- |
| 400  | `bad_request`     | JSON이 아니거나, `/events`가 받지 않는 필드가 있을 때                |
| 401  | `unauthorized`    | 토큰이 없거나, 알 수 없거나 폐기된 토큰일 때                         |
| 403  | `scope`           | 플러그인 토큰에 이 주제를 위한 `events:publish` 스코프가 없을 때     |
| 403  | `plugin_disabled` | 소유자가 그 플러그인을 껐을 때                                       |
| 403  | `reserved`        | 주제가 `aide.`로 시작할 때                                           |
| 422  | `invalid`         | 잘못된 주제, 없거나 긴 제목, 긴 본문이나 키, 객체가 아닌 payload     |
