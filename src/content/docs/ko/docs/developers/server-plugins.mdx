서버 플러그인은 플러그인 토큰을 가지고 AIDE 서버의 HTTP API로 통신하는 프로그램이에요. 언어는 무엇이든 괜찮아요.
소유자가 앱에서 채우는 설정을 등록하고, 노트 변경에 반응하고, 노트에 블록을 쓰고, 피드에 글을 올리고, 소유자의
AI 모델에 물어볼 수 있어요. AIDE의 기본 서버 플러그인(아침 브리핑, Slack, 레이더 등, [플러그인의 동작 방식](/ko/docs/plugins/overview/)
참고)도 바로 이 API로 만들어졌어요.

앱이 열려 있든 아니든 일정에 맞춰 또는 백그라운드에서 해야 하는 일에는 서버 플러그인을 쓰세요. 화면에 무언가를
그리는 기능이라면 [기기 플러그인](/ko/docs/developers/device-plugins/)을 만드세요.

<Aside type="caution" title="직접 운영하는 서버 전용">
플러그인 토큰은 서버를 실행하는 컴퓨터에서 서버의 명령줄 `aide plugin-token`으로 발급해요. 그래서 이 페이지는
[직접 운영하는 서버](/ko/docs/self-hosting/own-server/)에 해당해요. [데스크톱 호스트](/ko/docs/self-hosting/desktop-host/)는
함께 들어 있는 플러그인에만 토큰을 주고, 이번 릴리스에는 직접 만든 플러그인용 토큰을 발급하는 명령이 없어요.
</Aside>

## 플러그인의 동작 방식

1. 플러그인 id로, 필요한 범위를 담은 토큰을 발급해요.
2. 플러그인이 시작할 때 매니페스트를 등록해요: 이름, 게시하는 토픽, 설정이에요.
3. 소유자가 플러그인을 켰는지 확인하고, 설정을 읽고, 할 일을 해요: 노트 읽고 쓰기, 노트 변경 기다리기,
   이벤트 게시하기예요.
4. 소유자는 앱 설정에서 플러그인을 보고, 켜거나 끄고, 설정을 채워요.

모든 요청에는 토큰이 들어가요: `Authorization: Bearer aide_p_…`. 요청 본문은 엄격한 JSON이에요. 모르는 필드가
있으면 `400 bad_request`라서 오타를 바로 알 수 있어요.

## 토큰과 범위

서버가 돌아가는 컴퓨터에서 실행하세요.

```sh
aide plugin-token leftovers --off \
    --scope notes:write:daily \
    --scope events:read:aide.notes \
    --scope events:publish:leftovers
```

이 명령은 `aide_p_`로 시작하는 토큰을 출력해요. 서버는 해시만 보관하니까, 플러그인이 읽을 수 있는 곳에 저장해
두세요.

| 플래그        | 효과                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------ |
| `--scope <s>` | 토큰이 가질 범위예요. 여러 개라면 반복하세요. 하나 이상 필요해요                            |
| `--off`       | 소유자에게 처음인 플러그인은 소유자가 켤 때까지 꺼진 채로 시작해요. 기존 선택은 유지돼요    |
| `--revoke`    | 그 플러그인의 모든 토큰을 폐기해요(`revoked N token(s) of <id>`)                           |

다시 발급하면 새 토큰이 나오고 이전 토큰도 계속 유효해요. 토큰을 교체할 때는 이전 토큰을 폐기하세요.

플러그인 id는 영문 소문자 하나로 시작하고, 이어서 영문 소문자, 숫자, `-`가 1–39자 와요. 앱의 내장 id(`feed`,
`calendar`, `organizer`, `callouts`, `tasks`)는 쓸 수 없고, 같은 서버에서 AIDE의 기본 서버 플러그인(`briefing`,
`gcal`, `slack` 등)이 돌아간다면 그 id도 쓰지 않는 게 좋아요.

| 범위                               | 허용하는 것                                                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `notes:read:<path-prefix\|*>`      | 그 경로와 그 아래의 노트 읽기                                                                            |
| `notes:write:<path-prefix\|*>`     | 노트 만들기, 바꾸기, 옮기기, 보관하기, 그리고 플러그인 자신의 섹션 쓰기. 읽기도 포함해요                 |
| `events:publish:<topic-prefix\|*>` | 그 토픽에 이벤트 게시하기. `*`는 예약된 `aide.*` 토픽을 뺀 모든 토픽이에요                               |
| `events:read:<topic-prefix\|*>`    | `GET /plugins/self/events`로 그 토픽 읽기. 시스템 토픽은 이름을 지정해야 해요: `events:read:aide.notes`  |
| `ai:run`                           | `POST /ai/run`: 소유자의 AI 모델에 묻기                                                                  |

접두사는 구간 단위로 일치해요. 경로 접두사는 `/` 기준(`daily`는 `daily/2026-10-22`를 포함하지만 `daily-log`는
포함하지 않아요), 토픽 접두사는 `.` 기준(`leftovers`는 `leftovers.daily`를 포함해요)이에요. 플러그인의 읽기 범위
밖에 있는 노트는 없는 것처럼 `404`로 답해요. 쓰기 범위 밖에서 쓰거나 옮기면 `403 scope`예요. 소유자의 기기만
쓸 수 있는 엔드포인트(피드, AI 설정, 기기 등)는 플러그인 토큰에 `403 forbidden`으로 답해요.

## 매니페스트 등록하기

플러그인 자신의 id로 `PUT /plugins/<id>/manifest`를 보내요(다른 id면 `403 forbidden`). 시작할 때마다 등록하세요.
가장 최근 것이 적용돼요.

```json
{
    "name": "Yesterday's leftovers",
    "description": "Lists yesterday's unchecked todos in today's daily note.",
    "version": "0.1.0",
    "publishes": ["leftovers"],
    "slots": ["leftovers.today"],
    "schedules": [],
    "settings": [
        {
            "key": "post",
            "title": "Tell me in the Feed",
            "type": "bool",
            "help": "Posts a Feed event when there are leftovers."
        }
    ],
    "locales": {
        "ko": {
            "name": "어제 남은 일",
            "description": "어제 체크하지 않은 할 일을 오늘 데일리 노트에 적어요.",
            "settings.post.title": "피드로 알려 주기"
        }
    }
}
```

| 필드          | 값                                                          |
| ------------- | ----------------------------------------------------------- |
| `name`        | 필수                                                        |
| `description` | 앱에서 이름 아래에 보여요                                   |
| `version`     | 플러그인 상세 화면에 보여요                                 |
| `publishes`   | 게시하는 토픽(참고용)                                       |
| `slots`       | 쓰는 섹션(참고용)                                           |
| `schedules`   | 실행되는 때를 적은 텍스트(참고용)                           |
| `settings`    | 소유자가 앱에서 편집하는 필드, 최대 64개(아래 참고)         |
| `locales`     | 위 항목의 번역, 최대 8개 언어(아래 참고)                    |
| `syntax`      | 에디터의 사용자 하이라이트, 최대 32개(아래 참고)            |

본문은 최대 16 KiB이고 엄격하게 해석해요. 규칙을 어긴 매니페스트는 이유와 함께 `422 invalid`예요. 플러그인이
꺼져 있어도 등록할 수 있어요.

### 설정

| 필드      | 값                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------- |
| `key`     | 영문자 하나로 시작하고, 이어서 영문자, 숫자, `_`, `-`. 최대 40자. `token`은 안 돼요                          |
| `title`   | 최대 80바이트                                                                                               |
| `type`    | `string`, `text`(여러 줄), `number`, `bool`, `enum`, `time`(`HH:MM`), `list`(문자열 목록), `secret`          |
| `options` | `enum`용: 선택지 1–32개                                                                                     |
| `help`    | 최대 300바이트                                                                                              |
| `link`    | `{title, url}`: 필드 옆에 `https` 페이지를 여는 버튼(제목 최대 60자, URL 최대 2,000자)                       |

앱은 이 값으로 플러그인 상세 화면에 양식을 그려요. Slack 설정이 **Slack 앱 만들기**를 보여 주는 것도 `link`예요.
소유자가 값을 얻을 수 있는 페이지를 가리키세요.

`secret` 필드는 토큰과 비밀번호용이에요. 소유자가 앱에서 입력하면 서버가 비밀 키(`AIDE_SECRET_KEY`)로 봉인해서
다른 설정과 따로 저장하고, 다시 보여 주지 않아요. 앱에는 값이 저장됐다는 것만 **바꾸기**, **제거**와 함께
보여요. 그 값은 플러그인만 읽어요. 한 번이라도 secret으로 선언한 키는 계속 secret이라서, 나중에 일반 설정으로
바꿀 수 없어요. `AIDE_SECRET_KEY`가 없는 서버는 secret 저장을 거부해요(`422 secrets_unavailable`).

### 번역

`locales`는 언어 코드(`ko`, `en`, `pt-BR`)를 앱에 보이는 텍스트의 번역에 대응시켜요: `name`, `description`,
그리고 `settings.<key>.title`, `settings.<key>.help`, `settings.<key>.link`(링크 제목),
`settings.<key>.options`(`enum`의 선택지마다 순서대로 하나씩인 라벨. 저장되는 값은 여전히 선택지 자체예요)예요.
매니페스트에 없는 경로는 거부해요. 어떤 언어에 빠진 항목은 매니페스트 원래 텍스트로 보여요.

플러그인이 노트와 피드에 쓰는 내용은 플러그인에 달려 있어요. AIDE의 기본 플러그인처럼
`GET /plugins/self/owner`에서 소유자의 언어를 읽고 그 언어로 쓰세요.

### 문법 하이라이트

문법 규칙은 플러그인이 켜져 있는 동안 에디터에서 정해진 트리거 문자열을 하이라이트해요. 정규 표현식이나 코드는
필요 없어요.

```json
"syntax": [{ "trigger": "@@", "value": "word", "style": "purple", "link": "note", "title": "Person" }]
```

`trigger`는 공백, `<`, `>`, `&`, 따옴표, 백틱이 없는 1–8자예요. `value`는 `date`(뒤따르는 `YYYY-MM-DD`), `word`(다음
공백까지), `none` 중 하나예요. `style`은 `accent`, `green`, `orange`, `red`, `purple`, `muted`, `strong` 중 하나예요.
`link: "note"`(`word`에서만)를 주면 값이 그 노트로 가는 링크가 돼요. `title`(최대 40자)은 툴팁이에요.

## 플러그인용 엔드포인트

| 메서드 | 경로                                              | 응답                                                                                                |
| ------ | ------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| GET    | `/plugins/self`                                   | `{id, registered, enabled, scopes}`                                                                 |
| PUT    | `/plugins/<id>/manifest`                          | 저장된 매니페스트                                                                                   |
| GET    | `/plugins/self/settings`                          | 소유자의 설정 객체(설정하기 전에는 `{}`)                                                            |
| GET    | `/plugins/self/secrets`                           | 이 플러그인에 저장된 secret의 `{key: value}`(없으면 `{}`)                                            |
| GET    | `/plugins/self/owner`                             | `{language, timezone}`: 글을 쓸 언어(정하기 전에는 `""`: 영어로 쓰세요)와 시간대                    |
| PUT    | `/plugins/self/state`                             | `204`. 최대 512 KB의 JSON 객체를 그대로 저장해요                                                    |
| GET    | `/plugins/self/events?topic=&after=&limit=&wait=` | 오프셋 `after` 이후의 `{events: [...]}`                                                             |
| POST   | `/events`                                         | 이벤트를 게시해요([피드에 이벤트 게시하기](/ko/docs/developers/events/) 참고)                       |
| POST   | `/ai/run`                                         | `{text, provider, notes}`                                                                           |

그리고 토큰의 범위 안에서 쓸 수 있는 노트 경로예요.

| 메서드 | 경로                          | 본문 / 응답                                                                                                    |
| ------ | ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| GET    | `/notes?prefix=`              | `{notes: [...]}`, 최근 변경 순, 보관된 노트는 빠져요                                                           |
| GET    | `/notes/lookup?path=`         | 그 경로의 노트                                                                                                 |
| GET    | `/notes/<id>`                 | 노트: `{id, path, kind, title, body, version, todos, …}`                                                       |
| POST   | `/notes`                      | `{path, body?}` 또는 `{path, template, vars?}` → `201`과 노트                                                  |
| PUT    | `/notes/<id>`                 | `{version, body?, path?, title?}`. `version`이 오래됐으면 현재 노트와 함께 `409 version_conflict`              |
| POST   | `/notes/<id>/append`          | `{text, heading?, createHeading?, ifAbsent?}`. 버전은 필요 없어요                                              |
| GET    | `/notes/<id>/sections/<name>` | `{name, content, todos, version}`                                                                              |
| PUT    | `/notes/<id>/sections/<name>` | `{content, version?}` → 노트                                                                                   |
| GET    | `/periodic/<period>/<date>`   | 데일리, 주간, 월간, 분기, 연간 노트. 없으면 템플릿으로 만들어요. `?create=false`면 찾기만 해요(없으면 `404`). `<date>`는 `today`도 돼요 |
| GET    | `/search?q=&limit=`           | `{notes: [{id, path, kind, title, summary?, snippet?}]}`                                                       |

주기 노트를 만들려면 그 경로에 쓰기 권한이 있어야 해요. 노트 본문은 최대 1 MiB예요.

### 켜기와 끄기

소유자는 플러그인 상세 화면(**활성화됨**)에서 플러그인을 켜고 꺼요. 꺼져 있는 동안 플러그인의 설정, secret,
상태, 이벤트, AI, 노트 요청은 `403 plugin_disabled`로 답해요. `GET /plugins/self`와 매니페스트 등록만 계속
돼요. 그러니 플러그인은 가끔 `GET /plugins/self`를 확인하고(AIDE의 기본 실행기는 1분마다 확인해요), `enabled`가
false인 동안은 아무것도 하지 않다가 true가 되면 다시 시작하세요. 아직 매니페스트를 등록하지 않은 플러그인은 켜진
것으로 쳐요.

설정은 소유자가 앱에서 저장할 때 바뀌어요. 시작할 때 한 번만 읽지 말고, 일을 할 때마다 다시 읽으세요.

### 상태와 상태 메시지

`PUT /plugins/self/state`는 소유자의 앱이 읽을 최대 512 KB의 JSON 객체를 저장해요. 특별한 키가 하나 있어요.

```json
{ "status": { "ok": true, "text": "Connected as Marshall in Acme" } }
```

앱은 `status.text`를 플러그인 설정 아래에 보여 주고, 화면이 열려 있는 동안 5초마다 새로 고쳐요. `ok: false`면
문제로 표시해요. 플러그인이 연결됐는지, 토큰을 기다리는지, 실패하고 있는지 알려 줄 때 쓰세요.

상태는 앱이 보여 주기 위한 거예요. 플러그인은 토큰으로 상태를 다시 읽을 수 없으니, 플러그인 자신에게 필요한
것(커서, 마지막 실행 시각)은 자체 저장소에 두세요.

## 노트 변경에 반응하기

노트가 바뀔 때마다 그 변경과 같은 트랜잭션에서 시스템 토픽 `aide.notes`에 이벤트가 남아요. 그래서 순서대로 읽으면
변경을 하나도 놓치지 않아요. `events:read:aide.notes` 범위로 읽어요.

```sh
curl -s -H "Authorization: Bearer $TOKEN" \
    "$AIDE_URL/plugins/self/events?topic=aide.notes&after=$CURSOR&wait=25"
```

응답은 오프셋 `after`(기본값 `0`, 처음부터) 이후의 `{events: [...]}`이고, 최대 `limit`개(1–500, 기본 100)예요.
아직 아무것도 없으면 요청은 최대 `wait`초(최대 25) 동안 이벤트를 기다려요. 마지막으로 처리한 `offset`을
기억해 두었다가 다음에 `after`로 보내세요. 서버는 커서를 대신 보관하지 않아요. 각 이벤트의 `payload`는 다음과
같아요.

| 필드                    | 값                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------- |
| `id`, `path`, `version` | 노트                                                                                  |
| `sourcePath`            | `path`와 다를 때, 정확한 파일 경로                                                    |
| `kind`                  | `scratch`, `wiki`, `daily`                                                            |
| `op`                    | `created`, `updated`, `archived`, `restored`, 또는 `deleted`(AIDE 밖에서 파일이 삭제됨) |
| `period`, `periodStart` | 주기 노트일 때: 예를 들어 `daily`와 그 날짜                                           |
| `slots`                 | 노트 본문에 있는 올바른 형식의 섹션                                                   |

게시한 토픽도 `events:read:<topic>`으로 같은 방식으로 읽을 수 있어요. 스트림에는 플러그인이 읽을 수 없는 노트의
변경까지 모두 들어 있어요. `path`가 원하는 노트인지 확인하세요.

## 노트에 쓰기: 슬롯

슬롯은 플러그인이 소유하고, 주변을 건드리지 않고 다시 쓰는 노트의 블록이에요. 소유자가 템플릿에 한 줄을 넣어요.

```md
{{slot leftovers.today}}
```

그 템플릿으로 만든 노트에는 두 표시 사이에 빈 블록이 생겨요.

```md
<!-- aide:slot leftovers.today -->
<!-- /aide:slot leftovers.today -->
```

`{content}`로 `PUT /notes/<id>/sections/leftovers.today`를 보내면 노트를 잠근 채 두 표시 사이만 바꾸고, 블록이
없으면 노트 끝에 추가해요. `version`을 주면 그사이 바뀐 노트는 `409 version_conflict`예요. 플러그인은
`<자기 id>.<name>` 이름의 섹션만 쓸 수 있어요(다른 섹션은 `403`). 표시가 중복되거나 중첩되거나 닫히지 않았으면
`409 section_ambiguous`이고, 내용에 표시가 들어 있으면 `422`예요. 펜스 코드 블록 안의 표시는 그냥 텍스트예요.

각 `aide.notes` 이벤트의 `slots` 필드를 보면 내 슬롯이 있는 노트가 방금 만들어졌는지 알 수 있어요. 그때가 슬롯을
채울 때예요. 소유자가 템플릿을 설정하는 방법은 [데일리 노트와 템플릿](/ko/docs/guides/periodic-notes/)을 참고하세요.

## AI에 묻기

`ai:run` 범위로 보내요.

```json
{ "prompt": "Summarize what changed this week.", "context": { "notePaths": ["daily/2026-10-21"], "search": "launch" }, "maxTokens": 1000 }
```

`POST /ai/run`은 소유자의 AI 백엔드(**설정 › AI**)와 일일 한도를 써요. `prompt`는 필수(최대 32 KiB)이고,
`context.notePaths`에는 노트를 최대 10개까지 넣을 수 있고, `context.search`(최대 200바이트)는 제목과 본문이 가장 잘
맞는 노트 5개를 더해요. `maxTokens`는 최대 8,000이에요. 노트는 지시가 아니라 데이터 블록으로 모델에 전달되고,
플러그인의 읽기 범위 밖에 있는 노트는 오류 없이 빠져요. 응답은 일반 텍스트인 `{text, provider, notes}`이고,
서버는 어디에도 적용하지 않아요. AI가 설정되지 않았으면 `409 ai_unavailable`, 일일 한도를 넘으면
`429 ai_quota`예요.

## 오류

모든 오류는 `{"error": {"code": "…", "message": "…"}}`이고, 버전 충돌일 때는 지금 상태의 노트인 `current`가 더
붙어요.

| 상태 | 코드                  | 언제                                                           |
| ---- | --------------------- | -------------------------------------------------------------- |
| 400  | `bad_request`         | 본문이 올바른 JSON이 아니거나, 경로가 받지 않는 필드가 있을 때 |
| 401  | `unauthorized`        | 토큰이 없거나, 모르는 토큰이거나, 폐기된 토큰일 때             |
| 403  | `plugin_disabled`     | 소유자가 플러그인을 껐을 때                                    |
| 403  | `scope`               | 토큰에 이 노트나 토픽의 범위가 없을 때                         |
| 403  | `forbidden`           | 소유자 전용 엔드포인트, 또는 다른 플러그인의 매니페스트        |
| 403  | `reserved`            | `aide.*` 토픽에 게시할 때                                      |
| 404  | `not_found`           | 그런 노트가 없거나, 읽기 범위 밖일 때                          |
| 409  | `version_conflict`    | 보낸 `version`이 오래됐을 때                                   |
| 409  | `path_taken`          | 그 경로에 다른 노트가 있을 때                                  |
| 409  | `section_ambiguous`   | 섹션 표시가 중복되거나 중첩되거나 닫히지 않았을 때             |
| 409  | `ai_unavailable`      | 소유자에게 AI 백엔드가 없을 때                                 |
| 413  | `too_large`           | 본문이 1 MiB를 넘을 때                                         |
| 422  | `invalid`             | 매니페스트, 경로, 설정, 값이 규칙을 어겼을 때. 메시지에 어떤 규칙인지 나와요 |
| 422  | `secrets_unavailable` | 서버에 비밀 키가 없을 때                                       |
| 429  | `ai_quota`            | 소유자의 일일 AI 한도를 다 썼을 때                             |
| 502  | `ai_backend`          | AI 백엔드가 실패했을 때                                        |

## Python 예시

이 플러그인은 오늘의 데일리 노트가 슬롯과 함께 만들어지기를 기다렸다가, 어제 데일리 노트에서 체크하지 않은 할 일로
슬롯을 채워요. **피드로 알려 주기**가 켜져 있으면 이벤트도 하나 게시해요. Python 표준 라이브러리만 써요.

소유자는 데일리 템플릿에 `{{slot leftovers.today}}`를 추가해요. 위의 범위로 토큰을 발급하고(데일리 노트 폴더를
바꿨다면 `daily` 대신 그 폴더를 쓰세요) 실행하세요.

```sh
AIDE_URL=https://aide.example.com AIDE_PLUGIN_TOKEN=aide_p_… python3 leftovers.py
```

```python
#!/usr/bin/env python3
"""Yesterday's leftovers: an AIDE server plugin."""
import datetime, json, os, time, urllib.error, urllib.request
from pathlib import Path

URL = os.environ["AIDE_URL"].rstrip("/")
TOKEN = os.environ["AIDE_PLUGIN_TOKEN"]
CURSOR = Path(os.environ.get("LEFTOVERS_CURSOR", "leftovers.cursor"))

MANIFEST = {
    "name": "Yesterday's leftovers",
    "description": "Lists yesterday's unchecked todos in today's daily note.",
    "version": "0.1.0",
    "publishes": ["leftovers"],
    "slots": ["leftovers.today"],
    "settings": [{"key": "post", "title": "Tell me in the Feed", "type": "bool",
                  "help": "Posts a Feed event when there are leftovers."}],
    "locales": {"ko": {"name": "어제 남은 일", "settings.post.title": "피드로 알려 주기"}},
}


class AideError(Exception):
    def __init__(self, status, code, message):
        super().__init__(f"{status} {code}: {message}")
        self.status, self.code = status, code


def call(method, path, body=None, timeout=40):
    data = json.dumps(body).encode() if body is not None else None
    request = urllib.request.Request(URL + path, data=data, method=method, headers={
        "Authorization": f"Bearer {TOKEN}", "Content-Type": "application/json"})
    try:
        with urllib.request.urlopen(request, timeout=timeout) as response:
            raw = response.read()
            return json.loads(raw) if raw else None
    except urllib.error.HTTPError as error:
        detail = json.loads(error.read() or b"{}").get("error", {})
        raise AideError(error.code, detail.get("code", ""), detail.get("message", "")) from None


def fill(note_id, day):
    yesterday = (datetime.date.fromisoformat(day) - datetime.timedelta(days=1)).isoformat()
    try:
        previous = call("GET", f"/periodic/daily/{yesterday}?create=false")
    except AideError as error:
        if error.status != 404:
            raise
        previous = None
    lines = previous["body"].split("\n") if previous else []
    open_todos = [lines[t["line"]].strip() for t in (previous or {}).get("todos", [])
                  if not t["done"] and t["indent"] == 0 and t["line"] < len(lines)]
    content = "\n".join(open_todos) if open_todos else "Nothing left from yesterday."
    call("PUT", f"/notes/{note_id}/sections/leftovers.today", {"content": content})
    if open_todos and call("GET", "/plugins/self/settings").get("post"):
        call("POST", "/events", {
            "topic": "leftovers", "key": f"leftovers:{day}",
            "title": f"{len(open_todos)} todos left from yesterday",
            "body": content, "payload": {"push": "never"}})


def main():
    call("PUT", "/plugins/leftovers/manifest", MANIFEST)
    after = int(CURSOR.read_text()) if CURSOR.exists() else 0
    while True:
        try:
            if not call("GET", "/plugins/self")["enabled"]:
                time.sleep(60)
                continue
            events = call("GET", f"/plugins/self/events?topic=aide.notes&after={after}&wait=25")["events"]
            for event in events:
                change = event["payload"]
                if (change.get("op") == "created" and change.get("period") == "daily"
                        and "leftovers.today" in change.get("slots", [])):
                    fill(change["id"], change["periodStart"])
                after = event["offset"]
                CURSOR.write_text(str(after))
        except AideError as error:
            if error.code != "plugin_disabled":
                print(error)
            time.sleep(10)
        except OSError as error:  # 서버가 재시작 중이거나 연결할 수 없어요
            print(error)
            time.sleep(10)


if __name__ == "__main__":
    main()
```

커서를 파일에 보관하기 때문에, 다시 시작해도 멈춘 곳부터 이어서 해요. 처음 실행하면 스트림을 처음부터 읽고, 이미
빈 슬롯이 있는 데일리 노트도 채워요. 서버에서 프로세스를 계속 살려 두는 도구(systemd, 컨테이너, launchd)로
실행하세요.

<Aside>
등록이 끝나면 플러그인은 앱의 **설정 › 코어 플러그인**(Linux에서는 설정의 **코어 플러그인** 페이지)에 나타나요. 토큰을 `--off`로
발급했으니 꺼진 상태예요. 거기서 **활성화됨**을 켜면 플러그인이 1분 안에 알아차려요.
</Aside>
